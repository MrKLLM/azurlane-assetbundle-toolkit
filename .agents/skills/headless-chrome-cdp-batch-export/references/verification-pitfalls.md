## 验证类任务的额外坑（做"批量断言"而非"批量导出"时）

1. **断言要读运行时状态，别用画面代理指标**。判"动画/交互是否生效"要读引擎内部状态（如 Live2D 的 `motionManager.state.currentGroup`、Spine 的 `anim.getCurrent`）。帧哈希/`drawImage` 比对两头都骗人：无头环境 rAF 被节流 → **假阴性**；而 physics/眨眼等常驻动画让帧一直变化 → **假阳性**（曾据此误判"动画正常"）。
2. **异步生效要等一拍再断言**。触发函数内部常含 `fetch`（如 Live2D 加载 motion JSON），调用后立刻读状态会拿到空值 → 误判失败。加 ~1.5s 等待再采样。另注意某些状态会**自动回落**（idle 播完 `currentGroup` 归 null），所以"值变了"才是被触发的证据。
   - ⚠️ **"没等到"不会报错，它会伪装成一次成功的对照**（2026-10-08 实测）：给材质挂 lightmap 时用
     不 `await` 的 `TextureLoader.load()`，返回的是**尚未解码的占位 Texture**——挂是挂上了、
     `needsUpdate` 也设了，但截图与"根本没挂"的那一版**五个机位读数逐位相同**（0.546/0.367/…）。
     ⇒ 凡是"应用 X 之后量画面/量像素"的判据，必须**同时**跑一版"不应用 X"并断言**两者必须不同**；
     只断言"应用版的数达到阈值"抓不到这种失效。异步资源一律 `await`（`load(url, onLoad, _, onError)`
     包成 Promise，`onError` 要 **reject**，不许静默降级）。
3. **冷启动要先轮询等待页面全局变量**。删过 profile 后页面加载变慢，`/json` 有 tab、甚至 `evaluate` 能跑，都不代表数据脚本已执行；直接访问 `window.<DATA>` 会 `ReferenceError`。探针开头写 `for(let i=0;i<80 && !window.GALLERY;i++) await t(300)`。
   - ⚠️ **等全局变量还不够：第一处「数 DOM 结构」的断言前，要轮询页面自己渲染出来的选择器**（2026-10-07 实测）。页面常见形态是「`window.META` 早已赋值，但卡片是 `boot()` 里 `fetch(索引.json)` 回来才建的」⇒ 探针一连上就 `querySelectorAll('.card')` 得到 0，**一次假红能连带打红四五条**（默认视图张数、chip 数、常驻条文案、截图体积）。轮询谓词要落在**被断言的那个节点**上：`for(let i=0;i<150 && !document.querySelector('#gChar .chip');i++) await t(200)`。
     ⇒ 反向纪律：**假红没消净之前不许改判据**，先原样重跑一遍确认稳定（同一台机器同时压着多个后台代理时尤其容易复现）。
   - ⚠️ **就绪谓词本身会造成"门在生效"的假象**：`Runtime.evaluate` 里写
     `typeof G!=='undefined' && Array.isArray(G.ships) && G.ships.length`，返回的是**最后一个操作数的值**
     （一个数字），Python 侧 `is True` 恒假 → 门退化成白等满超时，症状是"工具很慢"而不是"门没生效"，
     且后续步骤可能照样成功，于是永远发现不了。→ **谓词一律显式降为布尔**：`String(<expr>)==='true'`
     或在 JS 侧 `=== true` / `Boolean(...)`；写完先故意在页面加载前跑一次，确认它真的会等待。
4. **两个 chrome 实例并发跑 CDP 会互相抢**，表现为 `Execution context was destroyed`。批量验证串行执行，或确保端口/profile 完全隔离且不重叠运行。
   4b. **同一类报错还有第二种成因**：探针刚连上 tab 就 `Runtime.evaluate`，而页面仍在导航 → 执行上下文被销毁。这种**不是并发问题**，串行也照犯。判据：先轮询 `document.readyState === 'complete'`，再对首次求值配"最多 6 次、每次 sleep 4s"的重试（同一张 tab 的默认上下文导航后会重建，重连即可）。⚠️ 别据此判产品坏了——本轮两个验收脚本就是这么假红过。另：脚本崩在半路会把 Chrome 整棵树漏在机器上（`proc.terminate()` 写在最后一行 = 异常时永不执行），注册 atexit 的整树 `taskkill /T /F` 才是兜底。
   4c. **第三种形态最阴：不报错，只是静默附着到别人的浏览器**（2026-09-27 实测）。探针的 `PORT` 与 `--user-data-dir` 写死时，第二个会话起不来新实例（端口被占），`/json` 列出的却是**别人那个正在跑的浏览器**里的同一 URL → 两边驱动交替点同一个页面。症状不是异常而是**数据整齐地错位**：每条断言读到的"当前值"恰好等于**上一次操作**的结果（实测：逐部位点击，`played` 整体滞后一位 ⇒ 62 个部位报出 38 条 WIRING 假红 + 一个模型"加载失败"）。
      ⇒ 判据：结果出现**统一偏移一位 / 整序列平移**这种"太整齐"的形状，先怀疑探针侧污染，不要去改产品；
      跑任何 CDP 探针前先查那条端口上有没有别的 python 在跑
      （`Get-CimInstance Win32_Process -Filter "Name like 'python%'"` 看命令行 + 按 `--user-data-dir` 归属性），
      是别人的长批量任务就等或换端口——**别去改他正在用的脚本**。
      **根治（已落成一份实现，别再各自写）**：把"取端口 + 取 profile"收进**一个共用出口**，规则三条——
      ① 端口默认让 OS 绑 0 挑一个**真空闲**的；② 允许用 env 钉死端口（复现某次运行用），
      但**钉的端口被占就直接退出并说明原因**——宁可不跑，也不许静默附着到别人的浏览器；
      ③ profile 一律带**进程号**（`chrome_<tag>_<pid>`），每进程一份，名字仍保留公共前缀好让清理脚本按前缀扫。
      迁完要配三条验收：两个探针**并发**跑各自 exit 0、把 env 指向被占的端口确认 exit 1、原有回归全绿。
      ⚠️ 这类"拒绝启动"的说明文字走的是 **stderr**：脚本只把 stdout 转 UTF-8 时，中文会被编成 GBK，
      **抓输出的调用方解码就崩了**——等于闸门把结论弄丢；共用出口里要把 stdout 与 stderr 一起转。
5. **清理残留 chrome 必须按 `--user-data-dir` 精确匹配命令行再 kill**：`Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | ? { $_.CommandLine -like '*<你的profile目录>*' }`。**绝不能按进程名全杀**——会误杀用户自己的浏览器。
6. **跨坐标空间的自动化探针，断言要落在产品语义上**。若探针要自己算目标坐标（模型单位 → 屏幕 → 再被页面反解回单位），往返误差在极端坐标处会被放大，导致"我猜它不该命中"类断言恒失败。改断言成产品契约（如"有判定区的模型任何点击都不该播出兜底动作组"）。
7. **上面第 1 条"读运行时状态"对视觉产物只够证「没死」，不够证「对」**（2026-09-26 实测）：
   Live2D 贴图整体错绑时，加载成功、drawable 计数正常、参数跨帧 min/max 全在动——代理指标**全部为真**，
   而画面是几十个部件碎片叠一堆。→ 渲染类产物的批量验证必须**同时**有：
   ① 状态断言（快、可全量、能进 CI）＋ ② 按 canvas `clip` 只截模型区的截图，**逐张看内容**
   （慢、只能抽样，但唯一能证"对"）。只有 ① 的验收报告不要写成"全绿"。
   看图要有**可比对象**（同皮肤静态图 > 同批未改动对照组 > 外部权威实现），否则会把
   正常的前缩透视/夸张构图判成"姿势反常"。
8. **探针脚本不要在启动时清空整个输出目录**——同一轮里第二次运行会把上一轮的证据删掉。
   只删本次要重产出的那些 key；跨轮对比依赖旧产物。
9. **验"图/内容真的出现了"必须量解码结果，并且先量视口尺寸**（2026-10-07 实测，两种形态都遇过）：
   - 连着的应用内浏览器页在侧边栏未展开时 `innerWidth/innerHeight = 0`。此时
     **IntersectionObserver 永不判相交、原生 `loading="lazy"` 也不触发** ⇒
     "内容要靠观察器/事件才出现"的实现会**整页空白而 DOM 看起来完全正常**（实测 1897 个卡片全在、
     `img` 全空、`broken=0`）。无头 Chrome 必须带 `--window-size=1440,1000`。
   - 判据写成 `img.complete && img.naturalWidth>0`（真的解出像素），**不是**"卡片/节点数量对不对"。
     探针开头先断言 `innerHeight>400`，否则后面所有懒加载类判据都没有含义。
   - **必配反向对照**：故意把某张图的 src 换成不存在的文件，看"缺失标记"会不会亮。
     不亮 ⇒ 上面那条 ✅ 是空集给的绿，不是产品正确。
   - 推论（产品侧）：懒加载优先用 `loading="lazy"` + `content-visibility:auto` 这类**浏览器原生**机制，
     不要自己挂 IO 当唯一出图路径——那等于给页面加一条"环境不配合就整页白"的失效模式。
10. **一致性判据要先确认单位**：`fetch(...).then(r=>r.text()).length` 是 **UTF-16 单元数**，
    含中文的页面会把正本 17758 字节读成 15569，造出一条"served 与磁盘不一致"的**假红灯**。
    量字节一律 `arrayBuffer().byteLength`。同类：数路径层级用 `/` 还是 `\` 要先看数据里存的是哪种
    （Windows 侧常是反斜杠，判据写错会整表恒为 0 命中）。
11. **截图判据要"先复位再拍"**：浮层/详情层没关就拍网格，拍出来的是被挡住的一半；
    用元素包围盒做 `clip` 时要把高度**夹到视口**（长列表页的元素整高可达几十万像素，
    不夹就得到一张几乎全空的长图，等于没拍）。

### 视觉 / 交互态专用（2026-09-28~30 几轮前端改版攒下的，每条都对应一次假灯）

9. **CSS 伪类只能被"真实输入"点亮**。`el.dispatchEvent(new MouseEvent('mousemove'))`
   不会让 `:hover` / `:focus-visible` 命中——伪类由浏览器**命中测试**决定，不由事件决定。
   用合成事件测交互反馈，得到的永远是假绿。必须走 `Input.dispatchMouseEvent`。
   ⚠️ 而且**发一次 mouseMoved 不一定刷新命中测试**：要边小幅挪边轮询，直到
   `el.matches(':hover')` 为真再往下读。
10. **按压态的事件类型是 `mousePressed` / `mouseReleased`**。写成 `mouseDown`/`mouseUp`
    会被**静默忽略**——不报错、不警告，只是元素停在 hover 态，于是你读到"按压没反馈"，
    然后去改本来正确的产品代码。
11. **读计算样式必须轮询到过渡落位**。状态刚切换的同一轮求值里读 `getComputedStyle`，
    拿到的是 transition 的**第 0 帧**：`border-color` 还是旧值、`box-shadow` 会显示成
    `旧值, transparent 0 0 0 0`（多层过渡里缺的层按"透明 + 零长度"补齐），
    而**没参与过渡的自定义属性**（`--lift` 之类）已经跳到位 —— 三者不一致就是这一帧的特征。
    固定 `sleep(0.3)` 也不保险：挂了 `backdrop-filter` 的页面在无头里只有十几帧每秒，
    一条 .18s 的过渡要等好几帧才起步。一律**轮询到值落位或超时**，判"最终有没有到位"。
12. **想用"逐像素相同"证明"界面自己在动/没在动"，先排除两类污染**：
    ① `loading=lazy` 的图会在页面放着放着时继续到货 → 整图哈希必然变化；
    ② 任何**跟指针走的持久样式**（例：把镜面高光坐标写进卡片的 `--mx/--my`）会让
    划过的元素永久改变，"回到初始态"这条就永远红——而这恰恰暴露了真实缺陷（页面留下"我动过"的痕迹），
    正确解法是"指针离开即复位"，不是放宽判据。
    ⚠️ **复位要覆盖"每一个"跟指针走的量，不只主属性**：2026-09-30 实测把 `scaleY()` 收回了
    0.34、却漏收 `transform-origin`（内联 `--oy` 停在指针进入的高度），一条 2px 的边条就永久
    偏在那里——肉眼看不出，逐像素量到 104 个差异点**全部落在同一列**上。
    ⇒ 几何量要**成对读回来**（`scale` 和 `transform-origin`），别只判起眼的那个。
    ⇒ 比对区要选**永远没有内容元素的条带**（容器 padding 留白那种），并先轮询到图片停止到货。
13. **给父元素的直接子元素统一设 `z-index` 会切碎层叠上下文**：子树里 `z-index:40` 的弹层
    压不过 DOM 中排在其后的兄弟，症状是"下拉面板和下一行文字混在一起"。
    判"弹层是否真的盖住"不要比 z-index 数值，要用 `document.elementFromPoint()`
    取一个**低于父容器底边**的点，断言命中目标在面板内部。
14. **判"看不见 / 没效果"必须按满偏算**。曾实测某 3D 倾斜只有 1.4°/1.8°，据此判定
    "肉眼约等于零"并删掉整条动效——但取样点在元素 68%/32% 处，**满偏本来有 4.5°**。
    要么按最大偏移设计断言，要么取多个点判 `max`。把"取样点偏小"当成"设计幅度小"
    会导致删掉用户其实要的东西（用户原话：要的是看得见，不是不要）。
15. **Chrome 会把 `color-mix()` 的计算值序列化成 `color(srgb R G B / A)` / `oklab(... / A)`**。
    取 alpha 只写 `rgba(...)` 正则的话，13% 的半透明会被读成**不透明**，
    "整块填色回来了"这类判据立刻假红。alpha 解析要同时认 `rgba()`、斜杠语法、以及 `oklab/color()`。
16. **把主观反馈翻译成能红的量化判据**，否则"还是不够高级"这种话没法验收。本轮的三条翻译：
    "还是毛玻璃" → 背景模糊 >10px **或** 面板底色 alpha >0.30 就红；
    "不要发光" → 非 `inset` 的 box-shadow 层里出现第 4 个长度值（spread）就红；
    "不要整块填色" → 选中项的 `background-image` 含 gradient、或底色 alpha >0.30 就红。
    每条都要配**阳性对照**（旧版本确实会被判红），否则判据可能是空的。
    ⭐ **更好的做法是别自己翻译**：用户说「还是太丑了，借鉴一下大厂的优秀 UI」时，
    去取**公开设计系统的成文 token** 当判据来源，而不是我凭审美再猜一版。
    `VoltAgent/awesome-design-md` 按 `design-md/<slug>/DESIGN.md` 收了 70+ 家品牌的成文值
    （`linear.app` / `raycast` / `sentry` / `cursor` 等；raw 域名不通就走 WebFetch，
    先取目录列表拿准 slug）。**要问的是具体数值和禁止清单**，不是「给我点灵感」。
    这类需求最值钱的是禁止项——它们能逐字翻译成会红的判据，例如
    「别拿薰衣草色当卡片填充」→ 面板底色 RGB **通道极差 ≤8**；
    「几乎不用 drop shadow」→ 非 `inset` 的 box-shadow **层数必须为 0**；
    「别加氛围渐变」→ chrome 元素 `backgroundImage` 不得含 gradient；
    「小标签别全大写」→ `textTransform !== 'uppercase'`。
    好处是判据**不依赖我的口味**，下一轮换配色也不会把这些病带回来。
17. **"整屏逐像素相同"在密集仪表盘上必然假红，要先把屏幕分区**。第 12 条那招（挑一条
    永远没有内容元素的条带来比）在画廊能用，因为画廊底部天然有一条空带；仪表盘没有。
    实测连红三次，三次都不是产品问题：
    ① 半透明面板在 WebGL 活动后重新合成，**渐变 dither 变了** → 最大差 2、4727 个点，
       全落在半透明层覆盖处（肉眼完全看不出来）；
    ② CDP 可信鼠标**停在谁身上谁就点亮 `:hover`** → 卡片被抬 1px，文字逐通道差 **209**，
       于是"起浪那张"量的其实是 hover 不是水；
    ③ 被裁一半的元素 `getBoundingClientRect` **仍越过滚动容器底边** → 取样框量到了容器外
       故意露背景的区域，"渗进内容 133"是取样框写错。
    ⇒ 三条通用手法：**按"画了背景的元素的矩形"把屏幕分区**（背景可见区 / 不透明内容区 /
    故意留的半透明装饰区各自判，掩码里要排除 `html`/`body` 和背景层自己，否则背景可见区
    = 0 像素，判据退化成空）；**每次拍照前把指针停回同一个无 hover 角落**；
    **取样框与滚动容器及视口求交**。掩码算出的背景像素数要当断言查（<5000 直接判红），
    不然"没有可比的像素"会被当成通过。
18. **半透明面板 + 会动的装饰背景 = 背景渗进文字区**。alpha 0.90 听起来很实，量出来
    一颗星能在某个字下面造成 **36 级**差异。⇒ 承载数据/图片的面板**必须完全不透明**，
    装饰只留给没有数据的带（标题带、页脚带）。
    ⚠️ 反向陷阱同样致命：面板全不透明之后，装饰区若没有一块**真的能看见**的地方，
    主题会被挤到只剩栏缝——实测浪在背景可见区只剩 68 个像素，等于没有主题，
    而"不渗进内容"这条**照样全绿**。⇒ "不遮挡"与"存在感"是两条独立判据，
    后者要配正向对照（关掉装饰后背景可见区必须明显变化）。
18b. **而"卡片内部逐像素比对"这条通道，在背景会重绘的页面上是不可用的**（同一天换背景引擎后撞到）。
    两种噪声都能压过真实泄漏：① 切"装饰开/关"会改变合成层，Chrome **重新光栅化整页**，
    全站文字边缘都能差 ±209（实测 20 万个差异点，散布在明明不透明的面板内部）；
    ② 画布每重绘一次也有同样效应，于是"背景在动那张 vs 静止那张"在卡片内部量到 154。
    ⇒ 别再拿像素比"渗不渗进来"，换成两条**结构性**判据：
    ① 数据面 `getComputedStyle().backgroundColor` 的 alpha 必须 = 1；
    ② 每个数据元素的 `getBoundingClientRect()` 必须整张落在某个不透明面板的矩形内。

    反过来"测得太松"就是假绿，是同一条纪律的两个方向。

    而列是 flex 容器 ⇒ 面板被压扁、卡片下沿被切 45px、日志格塌成 28px。
    **裁切类缺陷通常要靠"几何包含"才看得见；截图上它只是"少了半行字"。**

18c. **"只在指针经过处出现"这类显影效果，必须配一条 locality 判据**。
    只断言"划过之后亮了多少颗 / 背景区变了多少像素"，**整片一起亮的错误实现也能通过**。
    正确形式：把指针轨迹限制在屏幕一侧（如只划左半边），再断言另一侧的发光元素数为 0
    （`list.filter(t=>t.lit>0.05 && t.hx>innerWidth*0.62).length === 0`）。
    配套两条：静止时该数必须为 0（否则"显影"根本没生效）、动画收摊后必须回到 0
    且与初始帧逐像素相同（挡住"残留一片亮斑"这种假成功）。
    ⚠️ 动手前先把参照物的机制量清楚：同一个"划过有反应"，
    "把已有物体推开"与"把已有物体点亮"是两套实现，猜错方向要整层重写。

24. **覆盖层的"状态落定"必须有一条与动画无关的路径**。用弹簧/过渡做抽屉关闭时，
    如果 `classList.remove('on')` 写在动画回调里（`if(v>=1.015) 摘掉`），
    那么只要那一帧没跑完（rAF 被节流、回调抛异常、驱动端只 `sleep(0.5)` 就往下量），
    `position:fixed;inset:0` 的遮罩就永远盖着整屏 —— 而症状出现在**离根因很远**的判据上：
    背景可见区被算成 0 像素、`backdrop-filter` 拖垮帧率使划动全被"瞬移阈值"丢掉、
    抽屉里的元素矩形跑到视口外导致 hover 量不到。

25. **JS 里一个 `apply` 回调抛异常，会打死整条 rAF 循环**（本轮实测：弹簧条目只有
    `{x,v,t,k,d,apply}`，把 y 轴位移写成 `y.y` —— 读一个不存在的字段 →
    `undefined.toFixed()` 抛错 → 之后**所有**弹簧停摆，包括抽屉进出）。
    排查难点在于探针的「全程无 JS 异常」以前只收 `Runtime.exceptionThrown` **事件**，
    而 `Runtime.evaluate` 的错误是在**响应里**回来的、不发事件 ⇒ 假绿灯。
    ⇒ `ev()` 见到 `exceptionDetails` 也要计入，并且**带上栈顶三帧**
    （`stackTrace.callFrames`）：只报 `undefined.toFixed` 这种消息定位不到是谁。
    顺带两条同类：① 给新组件起类名前先 grep 同名（`.act` 既是顶栏按钮组容器又成了主按钮，
    整条顶栏被涂成实心紫）；② block 元素默认拉满父宽，用它算"避让/命中"矩形会得到
    一块横盖半屏的板砖，要 `width:fit-content`。
23. **canvas 精灵图集：`createRadialGradient` 超出 r1 之后会一直沿用最后一个色标**，
    而高斯 `exp(-t²/σ²)` 在 t=1 处还剩 5~19% ⇒ **预渲染的星体/光斑四边不透明，
    画出来每颗都套着一个看得见的正方形**（再经 `rotate()` 变成菱形，比「画得糙」更难看）。
    ⇒ 每个外层渐变一律乘一个到边归零的窗口 `*(1-t*t)`；
    判据不要靠看图，直接读位图：`getImageData` 取**四角 + 四边中点**，alpha 必须 ≤8。
    顺带两条同类：① 静态的大面幅精灵（星云 / 背景晕）**单独一张永不重绘的 canvas**，
    跟着会动的画布每帧 `drawImage` 等于每帧白拷几 MB，在无头 SwiftShader 上能把一次截图
    拖到 2s+，还每帧重合成带 dither；② 想画「衍射芒」别用 `moveTo/lineTo` 画十字
    （那是个「+」字形），要用从核向外锥形衰减的三角形渐变，并给每颗一个随机旋向。
19. **界面"看起来坏了"常常是首屏在算贵东西**。控制台的 `/api/state` 要算输入指纹

    而不是留一个 `—`；探针则必须**轮询到就绪再断言**（与第 3 条同一条规矩）。
20. **★ 验收脚本自带的"绕道开关"是最危险的一类假绿灯**（比测量噪声更隐蔽，因为它不改判据、
    只改判据跑之前按下的按钮）。真实事故：页面每 8 秒整屏淡入一次（轮询 `render()` 重建节点 +
    入场动画挂在元素基础类上），而探针里写着 `__probe.stop()`，注释明说"逐像素比对期间必须停掉
    轮询，否则卡片入场动画会把比对带歪（实测假红 75）"——**当时的处置是让验收绕开缺陷**，
    于是"32 条判据全绿"和"用户屏幕上天天闪"并存了三天。
    ⇒ 通用形式：任何"为了比图先把 X 停掉"的钩子，都必须回答一句**"X 在真实运行里会不会触发？"**
    会 ⇒ 那条判据验的是你的开关，不是产品。修法不是删钩子（比对背景层时仍需要它），
    而是**另加一条带着 X 跑的判据并排在旧判据之前**，让钩子不再决定结论。
21. **判"某个动效真的在动"，要先掐掉同屏其它动画源，并且别只靠像素**。两条都踩过：
    ① 断言"悬停中两帧之间有差 ⇒ 边框光在走"，第一版 `最大差 233` 通过——**假绿**：
    真鼠标划过会把背景星点亮起来并持续衰减，即使被测动画一动不动也必然有差。
    ⇒ 该段**先把背景关掉**再量（关掉后所有像素差只能来自动画本身），
    并补一条"跑完已把背景交还给下一节"的断言，防止这个开关状态漏到后面的判据里。
    ② 判"数据刷新没有重播入场动画"，最省事的通道不是像素而是**节点身份**：
    断言前把 `[...document.querySelectorAll('.step,.stage')]` pin 住，刷新后比
    `pinned()`（同一批对象 + 长度不变）；再配一条 `document.getAnimations()===0`。
    像素比会被子像素重排干扰，节点身份与动画计数不会说谎。
    ⚠️ **判「动画进行中的两帧不同」绝不能靠 `sleep`**：这台机器上一次
    `Page.captureScreenshot` 要 **2.16s**，而被测动画全长只有 0.78s ⇒ 两张都落在动画结束之后，
    量到 0 差（实测假红灯，差点去改本来正确的产品代码）。
    ⇒ 用 WAAPI 把动画**钉在确定时刻**再各拍一张：
    `const a=el.getAnimations()[0]; a.pause(); a.currentTime=120;` → shot → `=520` → shot。
    与截图耗时、帧率、后台节流全部无关。
22. **计算样式断言不要写死字面串**：`transform-origin:50% 50%` 会被序列化成
    `1px 67.3203px`（百分比按盒子尺寸解析），`matrix()` 里的 scaleY 是第 4 个数。
    拿 `'50% 50%'` 去比会得到**假红灯**，然后你会去改本来正确的产品代码。
    ⇒ 一律跟"进入前的基线值"比（同一条表达式在动作前后各取一次），而不是跟字面量比。
    ⚠️ 与第 11 条是两回事：那条讲**时机**（要轮询到过渡落位），这条讲**取值形态**。
    同一类坑的另外两个形态（同一天各踩一次）：
    ① **`box-shadow` 的 `inset` 关键字被序列化在末尾**
    （`rgba(...) 0px 1px 0px 0px inset`），`startswith('inset')` 会把内阴影误判成外投影；
    判「有没有外投影」要用 `'inset' in layer.split()`，且先把 `rgba(...)` 里的逗号屏蔽掉再分层。
    ② **别拿自己造的哨兵串去比**：JS 侧写 `className||'(none)'`、Python 侧比
    `cls in ('','none')` ⇒ 永远红。判「状态回位」要落在**语义**上
    （`classList.contains('legacy')===false`），不是字面串。
9. **`/json` 必须按 URL 过滤 target**：`--headless=new` 启动后 `/json` 里可能有多个带
   `webSocketDebuggerUrl` 的条目（新标签页、扩展页、iframe），抓第一个会连到**错的调试目标**，
   症状是 `Runtime.evaluate` 直接超时或拿到空结果，看起来像"页面没加载完"。
   写 `if '<你的路径段>' in tab.get('url','') and tab.get('webSocketDebuggerUrl')`。
10. **`subprocess.Popen(chrome)` + `proc.terminate()` 不回收浏览器进程**：被杀的是启动器，
    真正的浏览器进程随 `--user-data-dir` 常驻。下一次用**同一个 profile** 启动 Chrome 时，
    它会直接复用那个还活着的旧实例（并忽略你新传的 URL）——于是探针拿到的是**上一轮的页面**，
    出现"我明明改了也部署了，截图却还是旧的"这种假矛盾，足以让人误判修复无效、甚至去改本来正确的代码。
    ⇒ 探针要么每次用唯一 profile（`chrome_x_<timestamp>`），要么收尾按 profile 精确清进程；
    判"修复无效"之前先确认自己没连到旧实例。
    **同一坑的两种更狠的形态（2026-09-27 各踩一次，把用户机器压到只剩 1.1GB 空闲）**：
    ① `proc.terminate()` 只杀启动器、**不杀进程树** —— crashpad / gpu(SwiftShader) / network /
       若干 renderer 会整棵留着继续吃 CPU 与内存（一次验收漏两棵树 = 16 个 chrome 进程）。
       正确收尾是整树杀：`subprocess.call(['taskkill','/T','/F','/PID',str(proc.pid)])`。
    ② 清理语句写在脚本**最后一行** ⇒ 中途抛异常（典型 `RuntimeError: Execution context was destroyed`）
       就压根执行不到，比"忘了写 terminate"更隐蔽，因为正常路径看着是对的。
       正确姿势：注册 `atexit`（本项目已抽成 `scripts/diag/chrome_tree.py:install(proc)`），
       新增探针一律走它，别再各自在末尾写 `terminate()`。
    ③ 自查残留时 `Get-CimInstance Win32_Process | ? { $_.CommandLine -match "chrome_x_1"` 这类写法
       会**匹配到执行查询的 powershell/bash 自己**（查询串就在它的 CommandLine 里），
       误报"还有 N 个残留"、甚至差点去 kill 自己的 shell —— 先按 `$_.Name -eq "chrome.exe"` 过滤再匹配。
11. **观测通道的编码问题会被当成被测对象的缺陷**：Python 在中文 Windows 上 stdout 默认 GBK，
    把 UTF-8 内容（如带中文的资源名）打成 mojibake 后打印出来，看起来像**被测数据编码坏了**。
    本项目据此写过一条"`.skel` 与 `.atlas` 区域名编码不一致"的错误结论，
    hexdump 才证明两边逐字节相同、都是合法 UTF-8。
    ⇒ 子进程输出一律 `env=dict(os.environ, PYTHONIOENCODING='utf-8')` +
    `sys.stdout.reconfigure(encoding='utf-8')`；**下"字节层/编码层"结论前必须直接 hexdump 原始字节**，
    不能引用任何经过终端编码的字符串。
26. **改完页面源文件，先重启本地 dev server 再跑探针**（2026-10-01 实测）。若 dev server 在
    **import 那一刻就把 HTML 烘进内存**（本项目的 `scripts/pipeline_panel.py` 就是这样：请求处理器
    用的是模块加载时生成的页面串），改文件**不影响已经在跑的那个进程** ⇒ 探针连上的是上一版页面。
    症状极具误导性：探针报 `KeyError: 'k'`（读一个新加的 `__probe.fx()` 字段），而磁盘上那个字段
    明明存在 —— 看起来像"探针写错了"，实际是**被测对象过期**。
    ⇒ 判据：探针一报"页面缺某个钩子/字段"，**先别改探针**，直接看服务出来的 HTML：
    `(Invoke-WebRequest http://127.0.0.1:<port>/).Content | Select-String <新钩子名>`；没有就重启服务再跑。
    ⚠️ 重启前确认端口真的空了：`allow_reuse_address` 在 Windows 上**允许两个进程绑同一端口**，

    （与上面第 10 条 ① 是**两个不同成因**：那条是 Chrome 复用了旧实例，这条是 **HTTP 服务端**复用了
    旧内容。症状一样 ⇒ 任何"我明明改了却还是旧行为"的假矛盾，**第一步都是先证明被测的那份是新的**。）
27. **设计意图变了，旧判据必然红 —— 要重写契约，不是放宽阈值**（2026-10-01 实测）。某轮明确要背景
    "常驻漂移"，于是旧契约里"静止时零动画（`raf==0`）、两帧逐像素相同、淡净后回到同一静止态"三条

    ⇒ 逐条替换，并在注释里写明"替代了旧的哪一条、为什么旧的那条现在必红"，同时给新判据配
    **阴性对照**（例：判"避让生效"必须同时断言"避让矩形外的星一颗都没被误杀"，否则"把整片天关掉"

    · 「切回来像素只允许 dither 地板级差异」实测最大差 4、**>8 级的像素 0 个** ⇒ 兜底的 `bmax`

    ⇒ 原则：**能靠改产品解决的一律改产品；只有能证明是测量通道抖动的才动阈值，且必须保留那条最
    咬人的子断言。**
28. **探针脚本里别在 f-string 内嵌带反斜杠的表达式**（3.12 才允许）。本项目 `AGENTS.md` 写
    Python 3.13，但机器上 `py -3` 实际解析到 **3.11.9**（`py -0p` 只有 3.11 / 3.12.14）⇒

    ⇒ 写完先 `py -3 -m py_compile <探针>` 一次；嵌套求值先落成局部变量再拼进 f-string。

29. **片段被包成不 `return` 的箭头函数 ⇒ 一批判据静默全 `None`，而"无 JS 异常"照样绿**（2026-10-01 实测）。
    本项目的 `ev()` 把片段包成 `(()=>{ …片段… })()`；片段里写 async IIFE 时**必须以 `return` 开头**
    把 Promise 交出去，否则 `awaitPromise` 拿到 `undefined`。症状：进度台一节 10 条判据回读值**齐刷刷 `None`**，
    而同一节末尾的「全程无 JS 异常」还是绿的 —— **空判据不会报错，只会静默地什么都验不到**。
    ⇒ 新增一段判据后，先看它的**回读值**是不是真的非空（`None`/`''`/`[]` 一律当红），别只看 PASS/FAIL 计数；
    每条判据的 detail 里带实读值，就是让这种"静默空判据"当场现形的手段。
    ⚠️ 同源的第二形态：把"每拍都在变的数字"（进度台）挂进主 `render()`，会让
    「轮询没有重建 `.stage` 节点」这条**当场红** —— 正确修法是给它**单开一条渲染通道**
    （本项目是 `gaugeSet()`），与重建节点的 `render()` 完全分离（呼应第 20、21 条）。
    同一条纪律也管**展示层**：按历史均值预估的"剩余"必须在**收数据时记下到达时刻**再按本地时钟递减，
    否则两次轮询之间减数恒为 0（`(G.at||now)` 恒等于 `now`，一个永真表达式）——数字看着在、其实死着。

30. **自绘控件要成对检查"对比度"，别只看图**（2026-10-01 实测，两条各一次）。
    ① 主按钮 hover 只改了底色，`color` 仍从基础 `button:hover` 继承近白 ⇒ **白底白字**；
    修法是在 hover 规则里**显式写死深色**（继承来的 `color` 不会因为你换了背景而自动适配）。
    ② 自绘光标（内联 SVG data-URI）若只画亮线，落在近白底的主按钮上**整根看不见**；
    修法是**先用深色描一道底**再叠亮线。另：光标 hotspot 一律写死成十字交点，写 `0 0` 会让指针与判定点错位一格。
    ⇒ 判据用 `getComputedStyle` 读 hover 前后的 `color`/`backgroundColor` 算对比度，不要靠看图。

32. **一个 `continue` 写进 `forEach` 回调 = 整页脚本不执行**（2026-10-01 实测）。
    浏览器对语法错误是**整段不跑**：HTML 照常渲染、控件照常显示，但 `render()`/`panelState()`

    `AttributeError: 'str' object has no attribute 'get'`（`ev()` 把 JS 错误当字符串返回了）。
    ⇒ 语法检查要**在探针之前**跑：把内嵌 JS 抽出来 `node --check`（本项目是

    重建之后必须重打一次，否则标记被冲掉、界面看着"永远不动"（而数据是对的）。
31. **探针注入的合成数据，取值域不得与真实数据重叠**（2026-10-01 实测，白查一轮）。

    ③ 反过来，凡是"界面显示的数字"被断言，也要有一条**真跑**的采样（本项目：起测试面板、
    POST 一次真任务、20 秒后读 `/api/state` 断言 `stage/done/total/eta/eta_src` 非空且合理），

33. **验本地 dev server 的页面改动之前，先断言"served 页面 == 磁盘正本"**（2026-10-02 实测，同一坑第三次）。
    单文件面板（Python 里 `PAGE = r'''…'''`）是在 **import 时**把 HTML 烘成常量的，
    所以改完文件**不重启进程**，CDP 连上去验到的就是旧页面——而"全程无 JS 异常""DOM 结构符合预期"
    照样全绿。本轮的真实损失：星野参数（半径/密度/常驻占比）改完没重启，量到的还是旧分布，
    我差点据此判定"改动无效"。⇒ 预检固定两条：① 抽出内嵌 JS 过一遍 `node --check`；
    ② 取 `/` 的响应字节与 `import` 当前文件拿到的 `PAGE` 比对，不一致直接 `return 2` 并打出重启命令。
    端口也要自己确认（面板默认口与探针默认口不是同一个，连错口只会得到"拒绝连接"，看着像服务挂了）。
34. **视觉参数改动要用"落在屏幕上的像素数"当判据，DOM 里有没有这个逻辑不算**（2026-10-02 实测）。
    "常驻微光"这条开关代码里一直有（`amb` 字段非 0、常量 `AMB=0.10` 也在），但静止帧实测
    整屏只有 **67 个像素**亮着（占视口 0.01%、峰值 alpha 10/255）——因为它等概率抽星位，抽到的多半是最暗那档，
    再乘上该星自身的 alpha 就落进绘制循环的丢弃线以下。⇒ 量法固定三步：
    `canvas.getContext('2d').getImageData()` 数 `a>阈值` 的像素与峰值、按"占视口百分比"报，
    动效类再补两帧自比（`maxdiff`）证明"淡净后回到同一帧"。
    这样"看不见"会被量成一个数字，而不是被"代码里有这个逻辑"糊过去；反向还得配一条
    （关掉背景后可见像素必须显著减少），否则计数本身可能是空跑。

35. **小尺寸 UI 元素必须 `clip` + `scale` 裁开放大再看，否则渲染缺陷会被读成"我看错了"**
    （2026-10-06 实测，一条重复渲染的 bug 靠整页截图查了三步才找到）。
    整页 1280×900 里一行标签只有 ~11px 高：我看到"同一个词出现两次"，第一反应是自己看糊了，
    于是去查数据（数据干净）、再查渲染代码，最后才发现是**编辑时只替换了函数的一半**——
    旧的两行 `a.push(...)` 留在上面，新的 `all.push(...)` 又在下面推了一遍。
    ⇒ 探针里给截图函数加一个 `sel` 参数：先 `getBoundingClientRect()`，再
    `Page.captureScreenshot({clip:{x,y,width,height,scale:2.2}})`，把 chip / 进度条 / 角标
    这类**判据落在像素细节上**的东西单独拍一张。拍不出来就不要对视觉下结论。
    ⚠️ 顺带：DOM 求值偶发 `('ERR', {'code': -32000, 'message': 'Execution context was destroyed'})`
    （见第 4b 条）时，**源码 grep 往往比再试一次 CDP 更快给出定论** —— 别把"探针没读到"当成"产品没问题"。

36. **动效判据要量"会动的那个对象"，别量包含它的复合图形；首帧媒体要轮询到变化再采样**
    （2026-10-06 两条连撞）。
    - 潮水进度条：量"暂停后有没有退平"时去读**填充**路径 `M0 H L0 y … L x H Z` 的 y 范围，
      结果恒等于满高（末尾那句 `L x 46Z` 把池底算进去了），于是"振幅 26px 不变"被误判成产品坏。
      真正该量的是纯水面线（`<path>` 不带闭合），它才只含波峰波谷。
      同理"波有没有在动"要连拍两次路径比字符串，而不是看 `display`/`opacity`。
    - 波长：`sin(x/W*3.1)` 在 1000 宽的 viewBox 上**不到半个周期**，画出来就是平的矩形 ——
      做"波"要用 `x/W*2π*N`（N = 期望波长数，3~7 才在一条进度条上读得出潮）。
    - 点了没响：`await 600ms` 后读 `#t0` 仍是 `0:00`，因为首曲要现取现解码 1.8 MB。
      ⇒ 一律改成**轮询到值变了再采样**（`for(i<40 && text==='0:00') await 250`），
      这是第 2 条在媒体场景下的具体形态；固定等待造成的假红已经在项目里出现过三次。


37. **验"默认视图把一部分内容藏起来了"这类筛选，四条判据缺一不可**（2026-10-07 背景库 P2）。
    这类功能的失效模式很特殊：**藏错了不报错、卡片数照样自洽**，所以只数卡片等于没验。
    - **正向计数**：默认视图张数 == 索引里按**独立字段**算出来的（显示集 = 全集 − 明确判过"排除"的），
      不要拿页面自己的 chip 文案当口径（同源自洽）。
    - **逐档反向对照**：每个档位各点一次、逐档数得对，还要断言**不该出现的目录/类目一个都不出现**
      （例：「未标注」档里混进了已标注的目录 ⇒ 索引把没判过的当判过了，这是数据层错、页面看不出来）。
    - **归因判据**：搜一个"被筛掉"的名字 ⇒ 0 张时，空态文案与常驻条都必须写明**是被哪颗筛选挡的**，
      不许说"库里没有"（后者会把数据缺失伪装成用户搜错）。
    - **常驻"已隐藏 N 张"条要会自己收起**：切到「全部」时必须 `hidden`，
      否则"藏了 0 张还写着藏了 770 张"就是条假提示。
    ⇒ 后续旧判据若要沿用原口径，在这一组里把筛选解回「全部」再往下量，别让新增组把老判据带红。


38. **交互类判据必须先自证「我点到了」，再谈「画面变没变」；取样值不许把失败降级成可比较值**
    （2026-10-10 3D 宿舍页，一次撞出两个 bug，都在探针不在产品）。
    - **认形状**：`画面改变` 类判据全红 + `关回去逐字节相同 / 回到原画面` 类判据全绿
      ⇒ 唯一可能是**画面从头到尾一动没动** ⇒ 先查交互通路，再查产品。
      这个形状比单条红更值得警惕，因为它把"没反应"伪装成了"可逆性通过"。
    - **根因 A：选择器插进 JS 时丢了引号。** `document.querySelector(%s)` 用 `%` 插
      `.sw[data-k="sky"]` ⇒ 变成 `querySelector(.sw[data-k="sky"])` ⇒ **JS 语法错**，
      `Runtime.evaluate` 返回 `{'__err': …}`，而**返回值被丢弃** ⇒ 六次点击一次都没落地。
      ⇒ 用 `%r`（Python repr 自带引号），并让点击 helper **返回点击后果**：
      读一个**由该操作直接改变的可观测状态**（`S.on[k]` 翻了、按钮类名变了、槽位数归零了），
      为它单开一条判据；这条判据红了要 `continue`，不许顺势报"开关无效"——
      "产品没反应"与"探针没打到产品"这两种红的修法完全相反，混报一次就多花一轮。
    - **根因 B：失败值参与了比较。** 取样函数在抖动/失败时返回 `None`，调用方写
      `json.dumps(stable_hash()[0])` ⇒ `None` 变成字符串 `"null"` ⇒
      "两次都失败"被读成"画面没变"（假红），"一次失败一次成功"被读成"变了"（假绿），**同时在线**。
      ⇒ 重试到"连续两次逐字节相同"才算一次有效取样；取不到就**显式判红并停止后续判据**，
      绝不让哨兵值进入比较。
    - **半绿半红是定位器**：同一轮里滑杆（走 `dispatchEvent(new Event('input'))`）绿、
      按钮（走 `element.click()`）红 ⇒ 差异在**触发方式**，不在被测产品。别去改产品。
    - **等重画要按路径给时间**：`toggle()` 里凡是 `await` 了贴图/取数的，260ms 不够（给 700ms+）。
      当场取样拍到的是**改之前**那一帧。
    - **ES module 页"整块不初始化"的症状是钩子根本不存在**（取到 `undefined`/`{missing:1}`），
      不是"钩子返回失败值" ⇒ 优先怀疑加载链（第三方库 import 闭包缺件会让整个 module
      一行都不执行，而 vendor 台账 18/18 sha256 全绿照样看不见），
      别一上来怀疑自己的判据写错。


39. **交互/渲染类判据的三条配套纪律**（2026-10-10 行走漫游 + 角色接入，两条判据当场救回来）
    - **按某个字段去重之前，先证明那个字段存在且互不相同。** 实测 `Map.set(pa.uuid, pa.count)`
      把 10 个顶点属性全塞进同一个 `undefined` 键（`THREE.BufferAttribute` **没有 `uuid`**，
      带 uuid 的只有 Object3D / Material / Texture / BufferGeometry），于是"唯一顶点数"
      报成 224 = 最后一个网格的顶点数。语法没错、不抛异常，数还"看着像"，
      会把人引向"模型少加载了"而不是"我的聚合器塌了"。⇒ 一行断言就够：
      `ids = attrs.map(a=>a.uuid); assert ids.every(x=>x!==undefined) && new Set(ids).size===ids.length`。
    - **时间型交互判据必须先证明"时钟真的走了"**：无头浏览器 rAF 稀疏，"按住 W 0.8 秒"
      实测只推进**一个 tick**（位移恰好等于一帧的量）。⇒ 页面导出帧计数，
      探针先断言按住期间帧数 ≥3，再谈位移；否则"没动"到底是产品坏了还是根本没跑帧，两者同形。
      同理产品侧的 `dt` 上限别夹太狠（0.05 → 0.1），否则移动速度会随帧率下降而变慢——
      那是产品 bug，不是测试该迁就的行为。
    - **"必须改变画面"这类判据要配可测的前置条件，不许无条件要求。** 切换角色站位时
      "画面必须改变"在某个站位判红——她坐标逐字对上了，只是**站在当前机位画面外**。
      ⇒ 把前置条件量出来（投影到 NDC 导出 `onScreen`），只在条件成立时要求画面改变，
      条件不成立就打印一句"她在画面外 ⇒ 不要求改变"。判据的红/绿必须能区分
      "产品坏了"与"这次本来就不该有反应"；直接放宽阈值等于把这条判据作废。
    - 顺带：**同一份数据常有多个合法口径，报一个就会报假红。** Unity 子网格共用同一份顶点缓冲，
      按 primitive 求和 45,058、唯一 accessor 求和 22,606 —— 页面与探针**同时报两个**并各自比对。

40. **宿主侧逐条发 CDP 输入事件驱动动画 ⇒ 测出来的帧时是"你发事件的速度"，不是渲染成本**（2026-10-10 前端性能，整条结论被推翻一次）。
    - 失效形态：`Input.dispatchMouseEvent` 是**阻塞等 CDP 回复**的，Python 侧循环实测只能跑到
      ~30–40 次/秒。若被测动画由指针事件驱动（本项目"划过才起浪"），这个速率就成了帧率上限，
      rAF 中位帧时就会稳定在 26–33ms。诊断签名一句话：**输入速率 ≈ 测得帧率 ≈ 你据此定罪的那个东西**
      —— 三条一起出现，量的是自己。当时据此判"水面自己值 20ms"，改成页面内驱动后是 **6.6ms**，
      连"卡"的锅都换了一个对象。
    - 修法：在页面自己的 rAF 里 `window.dispatchEvent(new PointerEvent('pointermove',{clientX,clientY}))`。
      这仍然走页面挂在 `window` 上的那个监听器，**没有绕过被测入口**（对照第 1 条的纪律），
      只是把节奏交还给渲染器。
    - 同轮另一条与性能无关但同样伪装成功的：**无头探针复用 `--user-data-dir` 会吃磁盘缓存**。
      改了 CSS 变量正本，无头里仍读到旧值 ⇒ `blur(var(--x))` 变量为空 ⇒ **整条声明作废**（不是只丢一项）
      ⇒ 现象只是"改前改后两张截图逐字节相同"，控制台零报错。⇒ ① 每轮 `shutil.rmtree` 换全新 profile；
      ② 把"每个 token 读到非空 + 计算后样式串含预期函数"当**跑测量之前的闸门**打印，不许靠事后看图发现。
    - **声称"这项删减无视觉代价"之前，必须把被删的东西原样注回去比一次像素**（2026-10-11 自己抓自己）。
      删掉一层 `blur(2.5px)` 后写下"这是免费的 10ms，肉眼看不出"；探针里加一条把它注回去、
      对同一块取景算哈希 ⇒ 立刻判红（哈希不同）。⇒ 只许说"省了 X ms，代价是像素变了，交人眼判"。
      与第 1 条同源：**恒真（或根本没做）的对照等于没有对照**，而"我觉得很轻看不出来"是推断不是证据。
    - 顺带一条性能定位规律：**`backdrop-filter` 的成本单位是「挂它的盒子个数」，不是像素量**。
      同一批卡：改模糊半径、去掉 mask、把面积砍到 1/26、把滤镜链缩成只剩 blur —— 帧时全都一动不动；
      只有"少挂一层""少挂 30 个"才降。⇒ 排查这类卡顿先数元素个数，别去调半径。
      极限做法是**并成一个盒子**：一层覆盖整个网格的元素挂 `backdrop-filter`，N 个形状用一张
      `fill-rule:evenodd` 的 SVG 当 `mask-image` 一次画出。本项目实测 16.7ms → 3.3ms。
      两个前提：① 该层必须放在**滚动容器内部**随内容滚动，否则每帧要重建遮罩；
      ② ⚠️ **带 3D 旋转的元素不能"例外拆回去"**（原文是这样写的，2026-10-11 已证伪）：一旦为它们
      单独挂回 `mask + backdrop-filter`，那些元素只要转角非 0 就整盒糊（见下一条），
      并层省下的钱会连带把 bug 一起放回去。要么这些元素就没有厚边，要么它们不许被旋转。
    - **改架构之后，注入式条件会静默空转，而空转的噪声比没有数据更坏**（2026-10-11 实测）。
      边墙从"每卡一个伪元素"并成"一层遮罩"之后，七条往 `.card.g::before` 注入声明的条件全部失效
      （那个伪元素只剩 :hover 才存在），但它们照样打印出与基线相差 3ms 的数字 —— 那是纯噪声，
      读起来却像"改 X 会让它变慢 3ms"。⇒ 每轮跑完加一条通用探测：
      **任何一条条件的取景若与基线逐字节相同，就点名"这条空转，帧时不要读"**；
      架构变了就撤下旧条件，别留着当"以后可能用"。
    - **"无头复现不了"要先怀疑仪器没覆盖触发条件，而不是怀疑报障的人**（2026-10-11 三次栽在同一处）。
      仪器确实"悬停"了（`el.matches(':hover')` 为真），但那个状态里真正起作用的量是 0：
      跟手倾斜由页面自己的 mousemove 写 `--rx/--ry`，取样点落在元素**中心** ⇒ 两个角都是 0deg ⇒
      测的是"悬停但没转"。⇒ 复现类判据必须把**那个动作的实际数值**断言出来（打印 `--rx` 计算值、
      `transform` 的 matrix3d），只断言"事件发了/伪类命中"等于没测。
    - **`mask` + `backdrop-filter` 与祖先的 3D 旋转不可共存**（Chromium 行为，跨项目适用）：
      祖先 `rotateX/rotateY` 一旦非 0，子元素那层"只留一圈"的遮罩会被**整个丢掉**，模糊铺满整盒
      —— 静态 8° 即触发，与遮罩算法、图元是否重叠、是否并层都无关；2D 的 `translate/scale` 不触发。
      便宜的"后景根"代理（父级再挂一层 `backdrop-filter`、空挂 `filter:saturate(1)`、`contain:paint`）
      实测救不回原样。⇒ 要么去掉旋转，要么改成**不依赖遮罩**的画法。
      定位手法：冻住动画与取景，用 `!important` 覆盖 CSS 自定义属性造出
      `恒等 / 只 2D / 只 3D / 每帧在变` 四档，量"画面中心区域平均梯度能量"的比值。
    - **判"内容画出来没有"之前，先把部件灌上内容**（2026-10-11 一条恒红的假判据）。进度条在
      `prog=0` 时波形路径本来就是空串——那不是 bug，是"空管子当然没水"。⇒ 这类判据必须先触发真实状态
      （点播放 / 轮询到路径非空）再断言，并且把取样点推到**中间**拍一张给人眼判：空与满都看不出立体感。
      同一条也适用于开关类验收：先证明"它能让画面变"，再判"它有没有让画面变"。
    - **对照序列里不许出现"同一状态比同一状态"**（2026-10-11 两次相反的错误结论都出自这里）。
      典型写法：`开 → 关 → 再开`，然后判 `第一张 vs 第三张` —— 两张都是"开"，永远相同，
      于是把有效实现判成"没生效"。⇒ 判"变没变"必须显式取**开态那一张**和**关态那一张**比，
      并且**把三张的原始哈希全打印出来**：只印 ✅/❌ 的表，在判定式写错时完全看不出问题。
      同一条也适用于"关"态需要显式构造的场合（例如挂在 `html` 类之外的内联样式 —— 去掉类
      并不会让它变回去，于是"关"其实还是"开"）。
    - **UI 功能的验收要拍到"生效"，不是拍到"状态位变了"**（2026-10-11 一整轮被这个骗）。
      `classList.contains('x')` 为真、CSS 变量里 `url(...)` 也在、判据全绿 —— 屏幕上可以一点变化都没有
      （被上层不透明背景盖住：body 自己的渐变、`alpha:false` 的 WebGL canvas、常驻光晕）。
      状态位只证明"开关按了"，像素才证明"东西在场"。⇒ 功能判据里必须有一组
      **「做了 vs 没做」两版整屏截图逐字节比**，相同就是没生效。
      ⚠️ 对照别写成"藏掉某层再拍"：修好之后那层本来就该留着 ⇒ 对照恒不同，读不出任何东西。
    - **A/B 之前必须先跑 A/A**（同状态连拍两张）：`off vs on 不同` 这种判据，只要画面里还有
      **任何**别的东西在动就是假的——背景 CSS 动画、每秒跳一次的时间文本、还在到货的懒加载图、
      被 stub 掉一半的渲染循环（只冻 `step` 不冻 `draw` 等于没冻）。本项目两次把这种假绿灯写进过结论。
      实现上让判据函数返回三态：`True/False/None`，`None` = A/A 不稳 ⇒ **判据作废**，既不报绿
      也不许把红读成缺陷。
    - **CDP `Page.captureScreenshot` 的 `clip` 是文档坐标、且按"未滚动的整页"重绘**：页面滚了之后
      自己往 `clip.y` 加 `scrollY` 会拍到页顶那块平背景，于是"两版相同"是仪器假象。
      要看**实时合成结果**就别带 `clip`（直接拍整视口）。另外找"某元素压在滚动条下方"这类位置时
      **不能用 `elementFromPoint`**——那个点常被 sticky 头自己盖着，只会得到"找不到位置"的假结论，
      得按矩形在文档坐标系里算重叠。
    - **真双击要发两对 press/release**（第二对 `clickCount:2`）：只发一条 `mouseClicked{clickCount:2}`
      在部分 Chrome 上不合成 `dblclick`，量到的"没反应"是你的事件不像人，不是页面没接住。
      读缩放倍率要读 `getComputedStyle().transform` 里的 `matrix` 第一项，不要读自己写进去的那串。
    - **阳性对照必须随架构一起换，否则它会静默变成恒不塌**：上面那套的对照原本是"摘掉 mask 必须整盒糊"，
      而架构改成"根本没有 mask"之后，这条永远不塌 ⇒ 换成"直接给内容挂 `filter:blur(17px)`"。
      对照不塌的那一轮，所有"未复现"结论一律作废（尺子瞎的时候，量不到东西不算证据）。
    - **量"某块装饰到底改没改画面"要在最暗的那块背景前量**：`brightness()/saturate()` 这类叠层在纯色
      页面上只差几/255 级，量出来是"无罪"；同一处落在照片暗部会放大到几十级。真实踩法：托管浏览器里那张
      2.5 MB 的背景图**还没解码上屏**就拍了 A/B，于是判成"带子不影响画面"，而用户屏幕上有一条明显的杠。
      ⇒ 拍之前先确认身后那张图真的在画面里（在同一区域亮部、暗部各取一点，暗部必须真的是暗的）。
    - **注入式 CSS（JS 拼字符串塞进 `<style>`）的验收要量到"每条规则都在"**：拼接串中间误写一个 `;`
      就让赋值就地结束，后半段规则**一条都不进 DOM，而且不报任何错**——`node --check` 与"页面看起来正常"
      都查不出来。⇒ 断言 `style.textContent` 的长度**并且**逐条 `indexOf(规则签名)`，缺一即红。
    - **可读性判据要在"文字实际会遇到的每种底"上各量一次**：只量纯色页面得到的对比度，外推到照片背景
      无效——裸字压照片时**任何单一颜色都只在一半场景可读**，换颜色不算修好，要么给底要么加描边/阴影。
    - **判据失去对象时要"退役它"，不要把断言取反**：一条"切一个类画面必须变"的像素对照，在被测材质
      整个删掉之后没有对象。取反成"两版必须相同"看着对称，实际是**假判据**——页面里只要有常驻动画
      （水面、粒子、懒加载图到货），两版必然不同，取反版就会天天报假警。⇒ 正确做法：删掉这条像素对照，
      把不变式换成**结构断言**（读 computed style / 数滤镜个数 / 断言伪元素 `content:none`），
      并在代码里写清"为什么这里不再做像素对照"，否则下一个人会把它当漏写的判据补回来。
    - **同一套视觉装置搬到第二个元素上之前要重测，不要按"形状相同"外推**：一条挂在 A 上判死的带子，
      换成"因为 B 的底更透所以应该读得出来"的说法在 B 上保留，仍会被用户实机判死。⇒ 要么在 B 上
      拿到独立证据（含最暗背景那一档），要么一起撤。
    - **组件选中态要量 computed style，且要扛得住全局 reset**（2026-11-13 控制台背景标注）。
      纸本控制台有全局 `button{background:transparent!important;…}`，组件 `.on{background:…}`
      不带 `!important` 就被压掉 ⇒ class 挂上了、委托 handler 全对、屏幕却一点不亮，用户问
      "怎么知道选没选中"。⇒ 修法两层：组件 `.on` 带 `!important` + 独立色 token（亮/暗各一组）；
      判据从 `classList.contains('on')` 改成读 `getComputedStyle` 的 border/background 与 token
      **数值比对**，并顺手量第二主题。⚠️ 暗色选择器别凭想象写：本项目夜读是 `body.night`，
      写成 `html[data-theme=dark]` 永不匹配，而"bd==sel"这种自比判据会恒绿假通过——必须断言
      **token 真的换了一组**（暗 sel ≠ 亮 sel）且主题类真的在身上。
    - **"JS .click() 判据全绿 + 可信鼠标判据全红/None"是全屏遮罩的签名**（2026-11-13 六连红）。
      复核台在有 pending 时**自动弹出**，veil 盖住全屏 ⇒ `Input.dispatchMouseEvent` 全被 intercept：
      `:hover` 不成立（querySelector(':hover') 返回 null ⇒ getComputedStyle(null) 抛错读成 None）、
      擦除 handler 不跑（alpha 恒 240、lastMs=0）。JS .click() 不受遮罩影响，于是骨架/弹窗判据全绿，
      极易误读成"hover 效果回归"。⇒ 鼠标类 section 之前探针必须先**接住**自动弹层（等首查落地信号，
      把"自动弹出"本身变成判据），再用真实关闭按钮关掉；诊断这类红先量 `anyModalOpen()`，
      别急着改产品 CSS。自动弹层一般只弹一次（sessionStorage sig），后续 reload 不再弹。

### 帧时归因（2026-10-14 攒下的，答"动一下鼠标就卡"这类问题必读）

要把帧时钉到具体某一层（背景动效 / 元素悬停 / 输入通路），**顺序不能反**：

1. **合成事件不命中 `:hover` —— 这是最容易答错问题的地方。**
   页面内 `dispatchEvent(new PointerEvent('pointermove'))` **不会**让 CSS `:hover` 生效。
   所以任何"滑鼠标"类的问题，只能用 CDP `Input.dispatchMouseEvent`（可信事件）。
   用合成事件驱动的探针（如 `glass_perf_probe.py` 的划水）去答这类问题，
   它的数字**不是错的，是在答另一个问题**——量到的场景里少了元素悬停那一整块工作。
2. **事件要"发而不等"**（`conn.send()` 后不 `recv`，末尾一次性 drain 到目标 id）。
   逐条等回复会把事件速率压到 30/s，帧时于是变成"发事件的速度"（§133 坑三）。
   但**别用事件速率阈值当闸门**——反方向同样会翻车：发太快页面消费不过来，帧时又会等于事件间隔。
   正确做法是**正面对照**：跑一格"把被测的那层整个摘掉"的条件，它必须跑回地板速度；
   跑不回去就说明瓶颈是输入通路本身，前面所有差值都是仪器造出来的。
3. **必须跑满 2×2，四格都要。** 只跑"开/关"两格会撞上致命陷阱：两格都卡在同一个帧率平台时
   （无头常见 30fps 平台）**差值恒为 0，看起来像"这层免费"**。补上第三、四个变量，
   其中**"被测层开 + 干扰层关"**那一格是关键：让被测层真跑（断言它自己的帧计数在涨）却跑回地板速度
   ⇒ 它的总代价被这一格**夹住**，不用靠差值猜。
4. **单变量才归因；"全摘"只能当上界。** 一次摘四件事得到的差值不能说成"某属性是元凶"。
   本轮逐条单摘都不动、四条一起摘才掉 ⇒ 正确结论是"**归不到单条属性**"，这个"归不到"本身就是结论。
5. **不可复现的差值不写进结论。** 同一条件多跑几次，只有第一次出现的差值按"不可复现"处理。
6. **量"某层可见多少"用逐像素差，不要几何推断**：冻结该层 → 填成全透明拍 A1/A2（同态两张量噪声）
   → 填满拍 B → `|B−A2|` 是信号、`|A2−A1|` 是噪声；噪声必须远小于信号。
   几何采样（`elementFromPoint` + 沿祖先链算遮光率）要自己推断"这层算不算被挡住"，多一层假设——
   而且遮光率要**累乘 `(1-α)`**，写成累乘 `α` 会输出"全被挡住"（本轮撞过，输出 0%）。
7. **`Performance.enable` / `Page.enable` 是 CDP 域方法，不能塞进 `Runtime.evaluate`**：
   会被当 JS 表达式求值，域从未开启，`Performance.getMetrics` 六个指标**全读成 0**，
   而打印出来的表格看起来完全正常 —— 这是最容易带病收工的假绿灯。
8. **本机 `HTTP_PROXY` / `HTTPS_PROXY` 会劫持 `127.0.0.1`** ⇒ CDP 的 `/json` 与页面请求全变
   `502 Bad Gateway`，报错长得像"服务没起"。跑本地 CDP 探针前先清：
   `HTTP_PROXY= HTTPS_PROXY= NO_PROXY=127.0.0.1,localhost`。
   另：后台起静态服务别用 `(cmd &)`，工具调用一返回就被收掉。
9. **`--window-size` 与实际视口不等**：`--window-size=2560,1600` 量出 `innerWidth×innerHeight = 2538×1502`。
   画布尺寸、覆盖率都按 `innerWidth/innerHeight` 算，别按 `--win` 算。
10. **托管 Python 环境与 `py -3` 分工不同**：`websocket-client` 在
    `~/.workbuddy-ai/binaries/python/envs/default`（3.13），`PIL` 在 `py -3`（3.11.9）。
    两者都要就 `pip install pillow` 进托管环境（隔离目录），别污染系统环境。
11. **「X 比 Y 省多少」这类断言，默认它不可信 —— 必须交替配对量。**
    同机同码、隔几十秒的两轮，帧率实测能差 **40%**（31.8 vs 22.5ms/帧）。顺序 `A → B` 的差里
    混着机器的热状态，量出来的是"哪一轮跑得更早"。做法：`A B A B A B` 各 ≥3 轮，只读**配对差值**取中位。
    实例：本项目曾据此写下"上传段 0.13→0.05ms/帧（−34%）"，配对后中位 **+0.000ms/帧、三轮不同号**
    ⇒ 整条结论作废，差全是漂移。
12. **必须留一段"本轮没改动的东西"当对照段。** 上面那条正是靠**没碰过的「模拟」段也差 2 倍**
    （0.30 vs 0.15）识破的：差在整份上，不在被改的那一段上。只看目标段，假收益完美得像真的。
    **对照段是"这份数字整体可不可信"的哨兵，比目标段更重要。**
13. **配对之后还要查同号。** 三轮里有一轮反号 ⇒ 差值在噪声里，**不许写成收益**（做成硬闸最省事）。
14. **"保留改动"和"量出收益"是两件事。** 判据不支持收益时可以因为 **API 语义**保留
    （如"不再每帧重新分配纹理存储"），但文档必须写"量不出差、保留理由是语义"，
    **不许把语义理由包装成量出来的收益**。
15. **闸门要能拦"空转"。** 量某个容器时先断言**这个容器真的在滚**：把滚动容器写死成
    `'#grid'.parentElement` 量到一个不滚的元素（`scrollHeight == clientHeight`）⇒ 判据恒绿。
    改成"扫所有元素取 `scrollHeight - clientHeight` 最大的那个"。
16. **别用 shell heredoc 往 Python 里嵌 `\n`**：会被吃掉转义、写进文件的是真换行，
    直接 `SyntaxError: unterminated string literal`（连撞两次）。要么用编辑工具写文件，
    要么在目标代码里用 `chr(10)`。
17. **无头默认 dpr=1**：验"画布分辨率随 dpr 变化"这类改动必须加 `--force-device-scale-factor=<n>`
    （本项目 `hover_frame_cost_probe.py --dpr`），否则那条分支永远量不到、改动无从验证。
18. **要用户配合"手动操作"的对照，必须先把人手这个变量消灭掉。**
    反面实例：本项目曾让用户"连续试 5 个条件、每格划鼠标 3 秒"，结果同一个条件（`.card{transform:none}`）
    两次跑出 **23.3ms 和 206.6ms，差 9 倍** —— 每格里划动快慢/范围/是否扫到卡片都不一样。
    ⇒ **整轮作废。** 正确做法：**把被测机制用 JS 程序化驱动**（例：在 rAF 里直接写 `--rx/--ry`
    模拟跟手倾斜），**全程不动鼠标** —— 输入确定、跨轮可比。
    ⚠️ 这条与自己写的"顺序 A/B 不可比"是同一件事，写进规矩之后仍然会违，**要当硬约束执行**。
19. **"改 X 很贵"要先问清"是谁在贵"：拿一个干净壳做对照，再逐项藏掉页面的层。**
    本项目实测：改一个**临时造的纯色 div** 的 transform 也要 23ms（排除材质）；
    再逐项 `display:none` 掉 `#bgfx` / `main` / body 背景 ⇒ **只有藏掉 `main` 才回落地板**
    ⇒ 真根因是"这个滚动区里有 1021 个元素"，与"改 transform"本身无关。
    ⚠️ 不做这一步就会把结论钉在错误的层上（本项目先后错怪过水面、过渡、材质三层）。
20. **改 transform 的代价 ∝ 合成器 property tree 上的节点数，不 ∝ transform 本身。**
    机制：改 transform 会改动 property tree ⇒ 触发一次**完整提交**，提交要遍历滚动区里的子元素。
    1021 个带非恒等 3D transform 的卡片 ⇒ 单次提交 +13~27ms；**0 个 ⇒ +0.00ms**。
    ⇒ 修法：**让静止态的元素不带 transform**（挪到 `:hover/:active/:focus-visible`）。
    实测用户场景 23.3ms → 6.8ms（fps 43 → 147），**且零观感损失**。
    ⚠️ 两个必须一起做的配套：
    ① 用 `isolation:isolate` 顶回原来由 transform 提供的**层叠上下文**（否则带 `z-index` 的伪元素会盖到邻居上）；
    ② 别用 `will-change:transform` 去"提升合成层"——那只会让节点更多，实测更糟。
    ⚠️ 判据要断言**计算值**（静止 `transform:none`、悬停 `matrix3d(…)`、`isolation:isolate`、
    移开回 `none`），只截图或只看类名都会漏。
21. **别在无头里让用户代劳**：先判断问题是不是**结构问题**（跨机器可复现）还是**环境问题**
    （依赖用户的显卡/缩放/浏览器设置）。结构问题一律自己跑 —— 本项目曾把该自己做的
    "transform 节点数 vs 元素数量" 推给用户，而两台机 GPU 相同、帧时形状一致，本来自己就能测。
22. **探针必须自带服务器，不许绑固定端口。** 写死 `http://127.0.0.1:8777/...` 的探针，
    在那台服务器没起时会**打开浏览器的错误页**，于是页面全局全是 `undefined`，
    报出来是「GALLERY is not defined」「页面脚本未就绪」——**长得完全像产品坏了**。
    本项目因此有两条套件项长期"永久红"而没人发现（2026-10-16 查出来）。
    ⇒ 探针自己在空闲端口起正本服务器（`make_server(port=free_port(), root=…)` + 后台线程 `serve_forever`），
    收尾 `shutdown()`；这同时保证"量的是当前正本"，不依赖那台上跑的是不是旧代码。
    ⚠️ **不要用 `nohup … &` 起长期服务**：在"跑完即退"的非交互会话里，子进程会随该轮结束被杀掉，
    下次调用时端口已经没了（症状同上）。要么用宿主提供的后台任务机制，要么让探针自己起。
23. **本机代理会劫持 127.0.0.1，且要清**四个**变量**（`HTTP_PROXY`/`HTTPS_PROXY`/`http_proxy`/`https_proxy`）。
    只清大写、漏掉小写时，请求照样被代理拦下，**症状与"服务器没起"一模一样**（页面函数全 undefined），
    一次能白查一轮。另：本机沙箱里 `curl -o /dev/null` 会以**退出码 23** 掐断 `&&` 链，
    拿它当"服务器在跑吗"的链式前置会让后面的探针**根本没执行**（输出里只剩 curl 那行）。

### 写判据本身的两条纪律（2026-10-14 攒下的，各对应一次真坑）

1. **"只断言不许怎样"会把判据悄悄放宽成恒真。** 设计改了之后，旧判据整条作废，
   很容易顺手改成"断言旧特征不存在"就算完 —— 那样**功能整块丢了也会绿**。
   实例：页头材质从"整条栏是玻璃"改成"只让控件承载玻璃"后，若判据只断言
   "整条栏没有 backdrop-filter / 底色透明"，那么**玻璃被整块删掉也照样通过**。
   ⇒ 必须补上**正面那半条**（"玻璃在控件上，且不透明度落在某个区间内"）——
   `a≈0` 是"控件丢了"、`a≈1` 是"又变成实色贴纸"，两头都要能红。
2. **判据全绿、探针却崩在收尾 —— 这类"绿着崩"最难查，因为你会以为已经通过。**
   实例：在主函数里用单字母 `a` 当局部变量，而 `a` 其实是 argparse 命名空间，
   末尾要用 `a.out` 存截图 ⇒ `AttributeError: 'float' object has no attribute 'out'`。
   ⇒ 收尾用的名字（`a` / `args` / `out`）**不要当局部变量复用**；
   改完判据必须**跑到底看最后那行"通过/未通过"**，不能只看中途的判据行。

### 画布类效果的像素级验收（擦除 / 淡净 / 静止帧）

适用：页面里有"遮罩画布 + 指针擦出洞 + 时间衰减淡回"这类效果（背景图悬停擦除、显影、水波），
要证明它**真的擦了、真的淡回、静止时真的不动**。四条判据全部落在像素上：

1. **读画布自身的 alpha，不靠截图肉眼**。遮罩法：纸色 `rgba(paper, .94)` 铺满 ⇒ 静止帧 alpha≈240；
   擦开处 alpha 应 <90；没划过的角落必须仍 ≥232（**局域性**——防"整张淡掉"冒充擦除）。
   在页面里暴露 `__probe.bgAlpha(x,y)`（`ctx.getImageData` 单像素），CDP `Runtime.evaluate` 直接取值。
2. **采样点选笔迹末端**。淡出是按时间衰减的：同一实现早读会得 3、晚 200ms 读会得 111——
   取笔画中段会把"已经淡了一半"误判成"没擦开"。先划一小段、50ms 内读末端点。
3. **静止帧要三零 + 两帧相等**：`raf=false`、`stamps=0`、`getAnimations()==0`，
   且相隔 1s 两次读同一像素 alpha **完全相等**。canvas 的 rAF **不进** `getAnimations()`，
   所以"画布没在重画"必须单独用 `raf/stamps` 证明；而切换背景的 CSS `transition` 会进
   `getAnimations()` —— 切完等 ≥500ms 再判"静止零动画"。
4. **暂停集合每条都要反向证据**：`body.calm`、`prefers-reduced-motion:reduce`
   （`Emulation.setEmulatedMedia`）、任意弹层打开 —— 鼠标划过去 alpha 必须不变。
   只写"代码里 respect 了"不算，探针要各自造一次真实划过。

机制侧的确定性要求（否则判据会偶发红）：每帧从"整张底色"重画 + 按`笔迹×时间`画回，
收尾清空笔迹再整张重铺一次；**不要只往洞上补色**（会一路漂到完全不透明）。
跟指针的位移量（视差 transform）在 `pointerleave/blur/visibilitychange` 必须复位，
否则"动过鼠标后的静止帧"和"刚加载的帧"不是同一张。

### 页面加载遮罩/骨架：探针要等“遮罩自己消失”，页面也要能自己收

`document.readyState==='complete'` 和“卡片已经在 DOM 里”都不代表用户能看到页面：
首屏遮罩可能还在，或者 JS 在 `apply()` 抛错后再也没人收它。判据与实现都要独立：

- **页面侧**：启动渲染放 `try/finally`，成功/抛错都收遮罩；兜底不依赖加载模块本身
  （`loading.js` 404 时静态遮罩仍要能被内联定时器收起）；给用户一个“仍然进入”出口，
  并在 12s 自动收起。遮罩只负责等待，不能掩盖错误。
- **探针侧**：断言 `#bootveil` **不存在/已 off**，而不是只断言卡片数量；分别在图片启用/禁用
  两档各跑一次。若页面有顶层加载模块（`window.InkLoad`），先等它和遮罩都消失再取数。
- **CDP 连接**：先筛 `type==='page'` 且 URL 命中目标路径。本机扩展的 background 页也会给出
  `webSocketDebuggerUrl`；连上它时 `Page.navigate` 看似成功、页面函数却全是 `undefined`，
  是一条很贵的假红（2026-10-21 实测）。
- **错误日志**：给新页面注入 `window.__errs` 收集 `error`/`unhandledrejection`；但要把已知的
  第三方噪音（如 `spine-all.js` 的 `THREE is not defined`）与“首屏初始化失败”分开判。

### 首屏长列表分批渲染：首屏上限与“全量可达”成对判（2026-10-22）

- **判据成对**：首屏 DOM 卡数 ≤ 一页（桌面 120 / 窄屏 60）+ 滚到底或点“加载更多”后总数
  == 索引三档之和。只判前者会把内容弄丢；只判后者挡不住首屏铺满。
- **分页会推翻“全量都在 DOM”的前提**：老探针里直接 `querySelectorAll('.card')` 数全量的断言
  必须改成“按名字搜出来读”或“先点页脚按钮拉全”；这是探针假设过期，不是产品回归。
- **窗口尺寸传参**：`Page(..., win)` 若内部用 `win[0],win[1]` 拼 `--window-size`，传字符串
  `'1440,900'` 会变成 1×4，媒体查询/分页档位全错（本次 3e 假红的真因）。传 tuple，并打印
  `innerWidth` 或断言首屏卡数符合预期档位。
- **长任务先归因再算成绩**：首屏 1s+ 的 `longtask` 不一定是建卡。用 `Profiler.start/stop` 采 3s，
  按 callFrame 聚合自耗时；本次 1,522ms 落在 `water_bg.js` 的 `bgInit`（SwiftShader 下 WebGL
  初始化），`makeCard` 只有 3ms。判据按 `startTime <= bootOff` 与 `> bootOff` 分开：前者判本次
  渲染，后者只打印并标注（GPU/水面噪声），否则会把长任务总量算成建卡收益。
- **确定性命中别赌 IO 时机**：`scrollTop=scrollHeight` + 固定 250ms 轮询在 874 张档只到 720
  （布局/图片还在变，滚动位置被改掉后哨兵没进视野）；确定性的“拉全”用页脚按钮逐批点，
  无限滚动另配一条探针。
- **实现侧的四个点**：分区头不占页名额；`.grid` 跨批复用（批次边界常落在分区中间）；
  筛选/分档/搜索重置游标并断开 observer；页脚同时给哨兵和“加载更多”按钮（IO 不可用时仍能加载）。

### 截图与测量上下文：virtual-time 假半透明 + 展开时机（2026-11-13）

- **`--virtual-time-budget` 会把进场动画拍成半透明假缺陷**：列表行若用 IntersectionObserver +
  `setTimeout(k*28)` 交错加 `.in`（opacity 0→1），virtual-time 快进会把整列拍成灰蒙蒙的中间态，
  看着像「对比度坏了」。**对照截图一律走真实墙钟等待**（CDP navigate 后 sleep 到 `.row.in` 真挂上），
  判据落在「`.in` 计数 >0」而非「页面没报错」。本项目 `gallery_page_shots.py` 即此原则。
- **改测量上下文的那一步，必须放在不依赖该上下文的判据之后**：控件收进默认折叠区后，量它的
  悬停/按压要先展开次区；但「展开」本身会改变布局上下文。若探针开头就展开，水面「起浪白沫像素」
  判据从 264 掉到 58 连红（纯上下文扰动，渲染 diff 为 0）。把展开挪到水面判据之后、控件判据之前，
  水面段恢复默认首视图上下文即回绿。**先排判据对上下文的依赖，再决定改状态的动作插在哪。**
- **折叠/隐藏控件量几何全是 0**：`display:none` 的按钮 `getBoundingClientRect` 全 0、`:active/:hover`
  不命中 ⇒ 按压/悬停判据假红。这不是产品坏了（展开后实测可用），是探针没走到真实入口。
- **探针裸读全局可能早已过期**：页面脚本包进 IIFE 后，`BG`/`BG_FS` 这类词法绑定**不是全局**，
  探针 `BG.raf` 会 ReferenceError。修法：页面调试钩子暴露 `stats()/params()/shader()`，探针
  document-start 注入惰性 getter 把 `window.BG` 接上去（访问发生在加载后，`typeof` 守卫仍成立）。
- **「点筛选后 DOM 卡片数必须变」在分批渲染下恒假**：首屏恒一页（120），全部/子类都是 120。
  改读「共 N 项」计数文本的总数（1031→881 真变）才是兼容分批的筛选判据。
- **原生 `<select>` 弹窗截不到图，可读性判据落 option 计算色**：弹窗是 OS 渲染，
  `Page.captureScreenshot` 拍不到展开的选项列表；且弹窗底色**不一定跟 `color-scheme` 走**
  （夜里可能仍浅底），选项文字继承中间调会看不清。修法给 `option{color;background}` 显式配色；
  验证读 option 的**计算 color/background** 按 WCAG 算对比度 ≥4.5:1，别赌截图。
  本项目 `bgm_option_contrast.py` 即此（昼 10.43 / 夜 11.71）。
