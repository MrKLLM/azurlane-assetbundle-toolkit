# 项目文档治理与状态文档瘦身

一套「先治本、再搬家、零丢失」的文档治理管线。核心洞察：状态文档膨胀的根因几乎总是**规范未覆盖全部文档类型**，导致每次会话只能往主文档里追加流水。只瘦身不改规范 = 下次还会膨胀。

## 适用症状

- 跨会话对接用的状态文档（PROJECT_STATUS.md / STATUS.md 等）膨胀到数百上千行，每次加载吃大量 token
- 文档里混着三种职责：当前进度快照 + 逐日会话流水 + 已解决 bug 的长篇排查
- 出现「自我作废」内容：新章节宣告取代旧章节，但旧章节整段还留着
- docs/ 目录文件数超过规则文档定义的分工，存在命名误导（如 DRAFT 实为审计报告）、拼写错误、内容重叠
- 用户明确要求「先更新规范文档，不然以后还会往同一个文件夹里加」

## 核心原则

1. **治本先于治标**：先改规则文档（路由表+红线），再动内容。顺序不可颠倒。
2. **归档不删除**：被取代的内容逐字外迁到 archive，主文档只留精炼版。任何精简动作必须保证信息零丢失。
3. **git mv 保历史**：文件迁移/改名一律 `git mv`，禁止普通 `mv`（会丢 rename 追踪）。
4. **先确认后执行**：改动文档、挪动大量内容前，先输出「现状诊断表 + 分步方案」待用户确认（本技能源自对此类约定项目的实践）。
5. **不动全局 git 配置**：提交用 `git -c user.name=... -c user.email=...` 单命令内联身份。

## 工作流

### Step 0 — 只读诊断（不写任何文件）

```bash
git ls-files docs/            # 确认哪些文档在跟踪中（决定能否 git mv）
wc -l docs/*.md *.md          # 行数/体量盘点
```

1. 读规则文档（AGENTS.md / CONTRIBUTING.md）中现有的文档分工约定。
2. 逐一对照实际 docs/ 文件，输出诊断表：`| 文件 | 实际定位 | 问题 |`（重叠、误导命名、过期、未覆盖）。
3. 明确指出根因：「规范只规定了 N 个文件的分工，实际有 M 个」——缺路由表才会持续乱加。
4. 给出后续三步方案（规范→目录→瘦身）+ 提交步骤，**等用户确认后再执行**。

### Step 1 — 治本：更新规则文档

在规则文档写入两节（模板如下，按项目替换文件名/阈值）：

```markdown
## 文档写入路由（什么内容写进哪个文件）
**每类内容有且只有一个归属文件**，避免重复与膨胀：

| 内容类型 | 归属文件 | 写入方式 |
|---|---|---|
| 当前进度快照、各部分状态、接手须知、待办 | `PROJECT_STATUS.md` | 就地精简更新，**不追加**会话流水 |
| 可复用的操作流程 / 技术选型 / 步骤 | `docs/WORKFLOWS.md` | 按主题追加 |
| 具体问题 → 原因 → 解决方案（踩坑） | `docs/TROUBLESHOOTING.md` | 追加条目 |
| 运行错误流水 | `docs/ERRORS.log` | 追加 |
| 某个工具的使用说明 | `docs/tools/<工具>使用说明.md` | 就地更新 |
| 一次性审计报告、被取代的旧交接文档 | `docs/archive/` | 移入，文件名带日期 |

## 体量红线
- 状态文档超过约 **400 行**即触发归档：当次会话内把溢出内容移入 `docs/archive/`。
- 逐日会话记录、已解决 bug 的长篇分析、调参流水 → 必须外迁，禁止留在状态文档。
- 新会话对接只需读状态文档即可上手；任何"必须翻历史才知道"的内容都属于放错了地方。
```

### Step 2 — docs/ 分层（git mv 保历史）

目标布局：

```
docs/
  README.md              # 纯导航索引（路由说明，不复述工具细节）
  tools/                 # 各工具使用说明
  archive/               # 过期一次性内容，文件名带日期前缀
    2026-06-21_目录审计报告.md
  WORKFLOWS.md / TROUBLESHOOTING.md / ...   # 路由表指定的常青文件留顶层
```

1. 只迁移 `git ls-files` 里出现的文件；未跟踪文件（如被 gitignore 的 log）按路由表原位保留。
2. `mkdir -p docs/tools docs/archive` 后逐个 `git mv docs/旧名 docs/新路径/新名`；改名时**修正拼写错误、误导名称，并加日期前缀**。
3. 原 README 若与 tools/ 内容重复，重写为纯导航索引（工具细节交给 tools/）。

### Step 3 — 主文档瘦身（按行逐字抽取，零丢失）

1. **完整读一遍主文档**（不能只看开头），逐节标记：✅保留 / 🗜外迁归档（被新版取代的旧章节、会话流水、调参日志）/ ❌删除（仅限重复标题等纯编辑残留，且删除行也计入归档核对）。
2. **先归档、后重写**：从原始文件**一次性**抽取所有标记块。行号必须在重写前锁定——先改主文档会行号漂移。

```python
# extract_to_archive.py — 按行号逐字抽取（1-indexed，闭区间）
SRC = "PROJECT_STATUS.md"          # 必须是尚未修改的原文
BLOCKS = [(401, 480, "§6 攻关路线(v1已废)"), (900, 1250, "§9 会话流水")]
lines = open(SRC, encoding="utf-8").read().splitlines(keepends=True)
with open("docs/archive/2026-09-16_PROJECT_STATUS_v1归档.md", "w", encoding="utf-8") as f:
    f.write("# PROJECT_STATUS.md 外迁归档（逐字保留，勿编辑）\n\n")
    for a, b, title in BLOCKS:
        f.write(f"\n\n---\n\n<!-- {title} | 原第 {a}-{b} 行 -->\n\n")
        f.writelines(lines[a-1:b])
```

3. 重写主文档为固定骨架：`项目概览 → 各部分状态表 → 当前主线 → 接手须知 → 待办`；指向归档的引用写**实际存在的相对路径**。
4. 验证：

```bash
wc -l PROJECT_STATUS.md docs/archive/*_归档.md   # 主文档 ≤ 红线；归档行数 ≈ 被移出内容之和
git diff --stat                                   # 确认删除量集中在被标记章节
```

### Step 4 — 提交

```bash
git status && git add docs/ PROJECT_STATUS.md AGENTS.md   # 只 stage 文档相关变更，无关遗留不纳入
git -c user.name="Repo Author" -c user.email="repo@author.local" \
  commit -m "文档治理：AGENTS.md 加写入路由规范 + docs 目录分层 + PROJECT_STATUS 瘦身"
git log --stat -1 | grep -i "rename"   # 确认 rename 被识别（100% 相似度=历史保留）
git log --follow --oneline -3 docs/archive/2026-06-21_目录审计报告.md  # 抽查历史可追溯
```

commit message 用中文、匹配仓库既有风格；作者身份取仓库历史（`git log -1 --format='%an <%ae>'`），不改 git config。

## 验证清单

- [ ] 路由表覆盖了 `git ls-files` 中全部文档，无「无家可归」类型
- [ ] 主文档行数 ≤ 体量红线
- [ ] 归档行数 ≥ 被移出章节行数之和（抽查首尾各一块为逐字原文）
- [ ] `git mv` 的文件用 `--follow` 能追溯到迁移前历史
- [ ] 主文档内所有文件引用/链接指向实际存在的路径
- [ ] 未 stage 与本任务无关的变更

## 陷阱

- **直接删除而非归档** → 信息永久丢失。任何"看起来没用了"的章节都走外迁，让 git 历史做最后兜底。
- **普通 `mv` 替代 `git mv`** → rename 无法被识别，历史断链。
- **先改主文档再抽取** → 行号漂移抽错内容。必须从原始文件一次性抽取完毕、核对后，才允许重写主文档。
- **README 保留工具说明** → 与 tools/ 长期重复、双双过期。README 只做导航。
- **瘦身后忘改主文档里的归档引用** → 指向不存在路径的断链。
- **只瘦身不改规范** → 下次会话继续往同一文件追加，膨胀复发。顺序必须：规范 → 目录 → 瘦身。
- **用全局 git config 换身份提交** → 污染用户机器配置。用 `git -c` 内联。
