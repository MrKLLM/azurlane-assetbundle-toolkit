# Progress Tracker

自动维护项目进度文档的技能。在完成任务阶段后，读取、解析并更新进度文件。

## 触发条件

以下情况应使用此技能：
- 完成一个任务阶段（如导出、扫描、修复）
- 用户要求更新进度
- 运行脚本并产生新结果
- 发现新的技术问题或阻塞

## 工作流程

### 1. 读取进度文件

```bash
# 读取当前进度
Read PROJECT_STATUS.md
```

识别文件结构：
- 顶部元数据（生成时间）
- 各章节标题（`## N. 名称`）
- 子章节（`### 2.X 名称 状态emoji`）

### 2. 定位并更新对应章节

根据完成的任务，找到对应的 `### 2.X` 章节：

**状态更新规则**：
| 当前状态 | 完成后变为 | 说明 |
|---|---|---|
| ⏳ 未处理 | ✅ 已完成 | 任务完全成功 |
| ⏳ 未处理 | ⚠️ 部分完成 | 有失败但核心完成 |
| ⚠️ 部分完成 | ✅ 已完成 | 之前的问题已解决 |
| ✅ 已完成 | ✅ 已完成 | 状态不变，更新数值 |

**指标更新**：
- 更新表格中的数值（文件数、大小、耗时等）
- 新增指标行（如有新的统计维度）
- 更新路径信息（如有新输出目录）

**问题记录**：
- 新问题添加到 `**已知问题**:` 下
- 已解决的问题移到 `**状态**:` 说明中
- 更新 `**待解决**:` 列表

### 3. 更新元数据

更新文件顶部的 `**生成时间**` 为当前日期。

### 4. 扩展更新（可选）

如果任务产生了以下影响，同时更新相关章节：
- 新工具需求 → `## 4. 工具链` 的"需要安装/补充"表
- 任务完成释放了阻塞 → `## 6. 接下来的任务` 的优先级
- 新脚本 → `## 5. 关键文件清单` 的脚本表

### 5. 确认输出

在终端输出：
```
已更新 PROJECT_STATUS.md — [更新的章节名称]
```

## 格式规范

### 状态标记
- ✅ 已完成 — 任务成功完成
- ⚠️ 警告/部分完成 — 有但非致命问题
- ⏳ 未处理 — 尚未开始

### 指标表格
```markdown
| 指标 | 数值 |
|---|---|
| 文件数 | 1,234 |
| 总大小 | 5.6 GB |
| 失败数 | 0 |
```

### 子章节模板
```markdown
### 2.X 名称 状态emoji

| 指标 | 数值 |
|---|---|
| ... | ... |

**脚本**: `scripts/xxx.py`
**状态**: 描述

**已知问题**:
- 问题描述

**待解决**:
- 待办事项
```

## 支持的文件

- `PROJECT_STATUS.md` — 主要进度文件
- `DEV_LOG.md` — 操作手册（仅在流程变更时更新）
- `ERRORS.log` — 错误日志（追加模式）

## 注意事项

- 更新前先读取文件，确认当前状态
- 不要删除已有的问题记录，只新增或标记解决
- 保持原有格式风格，不要引入新的标记系统
- 如果不确定某个值，保留原值并在旁边添加 `[待确认]` 标记
