# Workflow Recorder

将当前会话的工作流程整理成可复用指南，追加到项目根目录的 `WORKFLOWS.md`。

## 触发条件

用户说出以下任意短语时激活：
- 总结工作流
- 记录工作流
- workflow summary
- 总结本次流程

## 执行流程

### 1. 回顾会话

扫描本次会话的完整对话历史，提取：
- **目标**：本次会话要解决什么问题
- **关键步骤**：按时间顺序的操作（脚本、命令、文件修改）
- **决策点**：遇到分支选择时的决定及原因
- **问题与解决**：踩过的坑和对应的解决方案
- **涉及文件**：修改/创建/读取的关键文件

### 2. 生成工作流条目

按以下格式整理（替换 `{N}` 为递增序号）：

```markdown
### WF-{N}: {简短标题，如"Live2D 模型批量还原"}

**日期**: YYYY-MM-DD
**目标**: 一句话描述本次会话完成的事情
**适用场景**: 什么情况下可以复用这套流程

**步骤**:
1. {具体操作，含命令或脚本}
2. {具体操作}
3. ...

**关键决策**:
- {决策点} → {选择}，原因：{为什么}

**踩坑记录**:
- {问题现象} → {解决方案}

**涉及文件**: `{文件路径1}`, `{文件路径2}`, ...
```

### 3. 去重检查

读取 {项目根目录}/WORKFLOWS.md，将新生成的条目与已有条目逐条对比：

- **对比维度**：目标 + 核心步骤（忽略日期和序号差异）
- **已存在**：若已有条目覆盖了相同的目标和步骤组合，跳过写入，输出 工作流已记录过，跳过：{标题}
- **部分重叠**：若已有条目只覆盖了部分内容，仅补充差异部分到已有条目（追加到该条目的踩坑记录或步骤中），不新建条目
- **全新**：继续执行步骤 4

若文件不存在，创建它并写入标题和分隔线，然后继续执行步骤 4。

### 4. 追加到 WORKFLOWS.md

将去重后的新条目追加到 WORKFLOWS.md 末尾。

### 5. 确认输出

在终端输出：
```
已记录工作流 WF-{N}: {标题} → WORKFLOWS.md
```

## 注意事项

- **去重优先**：相同目标+步骤的工作流不重复写入，已有条目可补充差异部分
- **只追加不覆盖**：永远不要删除或修改已有条目的核心内容
- **序号递增**：WF-1, WF-2, ... 按文件中已有的最大序号 +1
- **精简为主**：每条控制在 30 行以内，重点突出可复用的部分
- **保持中文**：除非原始内容是英文
