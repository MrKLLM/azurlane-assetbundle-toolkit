# 管线修复安全落地：定位→验证→小范围重跑→换入

数据驱动的批量管线（一个脚本从源数据推导出成百上千个产物文件）中，修复了某个系统性 bug 后，**不要盲目全量重跑**。全量重跑会打乱已验证正常的产物、耗时数十倍、且无法回答"哪些结果变了、变得对不对"。本技能用 7 步把风险收敛到真正受影响的子集。

## 适用场景

- 修改了合成/导出/渲染批处理脚本的某段通用逻辑（坐标、画框、缩放、依赖解析等），需要重跑既有产物
- 需要向用户证明"这次修复不会弄坏已正常的 N 个产物"
- 产物目录旁挂着派生物（缩略图、索引、gallery 数据），换入后需同步重建
- 切换了元数据主源 / 改了字段解析优先级（如把 index 的 `cn_name`、`faction` 从旧映射表换成新 JSON 表），产物是结构化 JSON 而非像素，需证零回退 → 走「分支 B」
- 内部不变式（曲线数 / 时长 / 字段映射 / 量程）全部通过、载荷也非空自洽，但**观感仍系统性错**（动作乱摆 / 颜色偏 / 时序怪），怀疑是**数值口径 / 单位 / 量级**类错误 → 走「分支 D」：用被测系统之外的权威实现产出做外部基准 diff

不适用：产物本来就全是错的/首次全量生成（直接全量跑）；产物无已验证存量（没有可保护的东西）。

## 横切原则：验证判据必须落在载荷上，而非状态标签

贯穿本技能所有分支（含分支 C）的一条铁律：**判"产物对不对"，永远看载荷本身非空且真的生效，不看"它是否被加载/启动了/状态变了"**。

- 反例（真实翻车）：无头验证断言 `state.currentGroup` 变了来判"动画在播"——这只证明动作**启动了**；一个 `"Curves": []` 的空壳同样能启动、同样让 `currentGroup` 变化，于是 260/260 全绿却人人都在"能播但不动"。
- 正例判据（动效类）：**数曲线条数**（`len(Curves) > 0`）+ **采样目标值随时间变化**（同一参数在两个时间戳取值不同）。静态/元数据类同理：字段级 diff 比的是值本身，不是"记录存在"。
- 推论：任何"通过"结论都要能回答"你检查的是内容还是外壳"。检查的是外壳的验证一律不算验证。
- **载荷非空且自洽 ≠ 数值正确**：本横切原则能保证"不是空壳、真的生效"，保证不了"取值口径对"。单位 / 量级类错误（贝塞尔控制点归一化分数 vs 绝对值、像素 vs 逻辑坐标）会让曲线数、时长、映射、量程**全部一起变绿**，因为错得自洽。判这类"数值对不对"，唯一可靠手段是抓**被测系统之外的权威实现**产出的同一资产做外部基准比对（见分支 D）。

## 工作流

### 第 0 步：修复前先建 git 基线

换入前工作区必须干净，且修复逻辑的 diff 可单独 review。若管线仓库在 git 下，先 `git add -A && git commit` 当前状态；产物不在 git 里也没关系，第 6 步的文件级备份兜底。

### 第 1 步：只读扫描，定位受影响全集

写一段**只解析元数据**的扫描逻辑（或复用主管线的解析函数，只跑到"拿到结构/尺寸信息"为止，**不解码纹理、不渲染**），对全量源数据跑一遍，判据是"新逻辑与旧逻辑对该条数据是否会分叉"（例如比较两个尺寸字段是否相等）。输出清单落盘，例如 `.diag/frame_mismatch.txt`，每行 `名称\t部件\t旧值\t新值`，供后续 shell/循环直接复用。

扫描必须带进度与错误计数（`errors: 0`），有异常条目单独列出而不是静默跳过。

### 第 2 步：语义豁免——区分"逻辑变了"与"结果可见变化"

名义受影响的子集往往远大于真正需要重跑的。对清单按数据特征分类，并**证明像素级 no-op** 后才允许豁免：

- 例：540/556 条命中项是 4×4 全透明占位贴图（alpha 通道最大值为 0）——无论旧逻辑缩小还是新逻辑拉伸，绘制结果都不变，无需重渲。抽样解码这些贴图的 alpha 极值来证明，而不是想当然。
- 例：某部件最终被其他层完全遮挡、或新旧 bbox 并集不变——可通过对比合成尺寸/包围盒预判，再交给第 4 步对照组兜底验证。

豁免结论要写成一句可复核的话（"全透明→alpha 遮罩下任何变换均不改像素"），并保留至少 1 个豁免类样本进入对照组让逐像素 diff 检验。

### 第 3 步：受影响项 + 对照组重渲到临时目录

只重渲：① 第 2 步筛出的真实受影响项全集；② 3-5 个**对照组**样本——从未受影响的产物中挑，且必须包含"边界案例"（被豁免的类型、结构最复杂的、随机抽查的普通案例）。全部输出到独立临时目录（如 `.diag/xxx-fix/`），**绝不直接写正式产物目录**。

### 第 4 步：对照组逐像素校验，证明零回退

对每个对照样本：`现产物 PNG vs 临时目录新渲 PNG`，尺寸必须一致，逐通道 `np.abs(...).max() == 0`（maxdiff=0）。任何一个对照样本 diff≠0 都说明扫描判据漏了某类分叉——回到第 1 步扩大判据，不得继续。同时记录受影响项的新旧尺寸差（如 `junzhu_5 高度 +50`）作为旁证。

### 第 5 步：改前/改后对比总览 → 用户确认闸门

为**每个**受影响项生成并排对比图（左旧右新、深色底合成、带文件名标注；数量多时再拼总览大图），临时目录存放（如 `.diag/cmp_xxx/*.jpg`）。agent 先自行 Read 逐张审阅确认修复方向正确（该变好的变好了、不该动的没乱），再呈现给用户，明确等待确认后进入换入。这是硬闸门：未经用户确认不得覆盖任何正式产物。

### 第 6 步：备份 → 换入

1. 把受影响项的旧产物整体复制到带日期/用途的备份目录（如 `.diag/backup_before_framefix/`），换入前先确认备份文件数==受影响文件数。
2. 用临时目录中的新产物按同名覆盖正式产物目录。
3. 逐字节核对换入后的文件与临时目录源一致（`cmp` / 哈希）。

### 第 7 步：增量重建派生产物 → 提交

派生物（缩略图、索引、gallery JSON）不要全量重建：删除受影响项对应的派生文件，然后跑**只补缺项**的增量生成器（天然跳过已存在项），输出里确认"新建数==受影响数、跳过数≈其余"。最后 git 提交，message 写明修复内容与换入数量。

## 分支 B：非视觉元数据 / 生成索引的权威源切换

上面 7 步假设产物是**像素可比对**（PNG 逐通道 `maxdiff==0`）。但当改的是**元数据推导口径**——例如把 gallery `index.json` 的 `cn_name`、`faction` 从旧映射表（`SHIP_NAME_MAP`+Wiki）切换到新的权威 JSON 表（`ship_meta.json`）——产物是结构化 JSON，没有像素可比。**用户又明确拒绝逐条人工审阅**（"上千条我看不过来"），此时不能靠"看着像修正"放行，必须让机器承担裁判责任。本分支把 7 步方法论平移到这个场景。

核心思路：`git show` 旧脚本重生成旧基线 → env 开关把新产物写临时目录 → 逐条目 × 逐字段三分类 diff → **用领域不变式把 `changed` 自动判成"修正"或"回退"** → 意外回退走根因反转而非打补丁 → 换入后逐字节核对。

### B0：用 `git show` 旧脚本重生成旧基线（不改工作区）

不要靠"当前正式产物就是旧基线"——正式产物可能已被别的改动污染。直接从 git 取**修改前版本的脚本**跑一遍，得到干净基线：

```
git show HEAD:scripts/build_gallery_index.py > .diag/_old_bgi_tmp.py
# 用旧脚本输出到 .diag/old_gal/index.json（旧脚本若无输出开关，临时改它的 OUT 常量到临时目录再跑）
```

`HEAD` 必须是"改动前最后一次提交"；若本次改动尚未提交，先按第 0 步建基线再改。旧基线脚本是临时脚手架，换入后送回收站，不入库。

### B1：给新脚本加 env 输出开关，新产物写临时目录

新脚本增加一个环境变量（如 `GALLERY_OUT_DIR`）：默认落正式目录，设了该变量就落临时目录（如 `.diag/b_test/`）。**正式目录零污染**，验证通过前绝不写 `Output/`。这与主线第 3 步"输出到独立临时目录"同构，只是落点从图片目录换成 index 目录。

### B2：逐条目 × 逐字段 diff，三分类 lost / changed / gained

以主键（船名 / stem）对齐新旧 index，对每条目的关键字段（`cn_name`、`faction`、`category`、`skins` 列表等）逐一比较，把差异分三类：

- **lost**：旧有新无的条目 / 字段值从有变空 → 几乎总是回退，红线，必须为 0（除非声明了合并豁免）。
- **changed**：同一条目字段值不同 → 需 B3 裁判是修正还是回退。
- **gained**：新多出的条目 / 字段从空变有 → 可能是修正，也可能是 B4 的预期结构变化。

输出三分类计数 + 每类清单落盘（如 `.diag/_field_diff.txt`），供 shell 直接消费，不手抄。

### B3：领域不变式自动裁判 changed（替代人眼）

这是本分支相对主线第 5 步的**关键差异**：用户不看，就得有可计算的规则替他把每个 `changed` 判成"对"或"错"。不变式必须是**独立于被测数据源**的事实，否则自证循环。常用不变式（按项目挑选 / 新增）：

- **磁盘 stem == 正确中文名拼音**：`index` 里 `cn_name` 对应的 PNG 文件名 stem，必须等于该中文名的拼音（`pypinyin` 生成）。谁违反谁错——若新表让某船 `cn_name` 变了导致 stem≠拼音，说明新表这个值可疑；若旧值本就错、新值让拼音对齐了，则是修正。
- **占位符命中数 == 0**：字段值里不得出现 `{namecode}` 之类未解析占位符。新表若引入占位符（如 `ship_skin_template.name` 含数百个占位符），命中即回退。
- **阵营 / 类别归属规则**：faction=META 的形态不得作为皮肤并进本体船（见 B4 的 META 独立卡），category 取值必须在白名单内。
- **非空字段不得变空**：某船旧有 `cn_name` 新为空 → 回退。

对每个 `changed`：跑全部适用不变式。**通过 = 修正**（自动放行并记入修正清单）；**违反 = 回退**（拦下，转 B5 根因）。**不变式覆盖不到的字段必须显式回落到人工**——不能因为"用户不想看"就默认放行；此时按 **B3-H** 的固定规范生成带缩略图内嵌的 Markdown 复核清单交用户勾选（不是 CSV），勾完再落白名单重建。用户拒绝逐条 = 不变式覆盖率就是安全边界，边界外的必须暴露而不是藏起来。

### B3-H：人工复核清单输出规范（不变式覆盖不到时的交付物）

不变式判不了的疑难残余，导给用户人工复核时**固定用带缩略图内嵌的 Markdown 文件**（如项目根目录 `story_review.md`），**不是 CSV**——用户要边看图边勾选，CSV 无法内嵌图片（实际会话中已被明确否掉）。勾选完成后 `grep '\[x\]'` 提取条目，落入白名单（如 `build_gallery_index.reclassify` 的 `EXTRA_SHIP`）重建。格式五要素：

1. **图片用相对路径，禁止 `file://` 绝对路径**。`.md` 放项目根目录时，缩略图引用写 `Output/gallery_v2/thumbs/xxx.webp` 这类相对路径即可。踩坑实录：初版用 `file:///D:/Azur%20Lane%20Assets/...` 绝对 URL，Markdown 预览器/浏览器因安全策略全部拦截显示"加载失败"，换相对路径后正常。
2. **排序：越像目标类别越靠前**——有阵营/舰种/Spine/Live2D 等指向性特征的条目放最前，降低用户翻页成本。
3. **每条固定结构**：三级标题 `### 001 中文名 \`key\``（编号 + 中文名 + 反引号 key）→ 元数据行（阵营 / 舰种 / 稀有度 / 皮肤数 / Spine / Live2D / source）→ 缩略图 `![名称](相对路径)` → 一条 GFM 任务列表项 `- [ ] 自机?`（问题文字按场景定）。
4. **勾选框必须用 GFM 任务列表语法**：`- [ ] 文字`（短横线 + 空格 + `[ ]` + 空格 + 文字），支持 GFM 的预览器才会渲染成可点击的真实 checkbox；写成 `- 自机? []` 这类纯文本方括号**不会**渲染成交互控件。用户勾完后 `- [ ]` 变 `- [x]`，据此提取落白名单。
5. **文件开头加一行勾选规则说明**：告诉用户把 `- [ ]` 改成 `- [x]`（或直接报条目编号 / key 均可）。

### B4：声明预期结构变化，把 gained 与漏字段区分开

主动的建模改动（例：META 形态从本体船拆成独立卡，`gained` +54 条）会同时抬高 gained/changed 计数，若不声明就会和"意外新增/回退"混淆。在跑 diff 前，用一份清单**显式声明预期 delta**（"META 独立成卡：预期 gained 56 个 `_meta`/`_alter` 卡、本体船 skins 减少对应项"）。命中清单的结构变化计入"预期"，清单外的 gained 才需 B3 裁判。这一步让"总船数 954→1008"这类数字变成可核对的预期值，而不是吓人的意外。

### B5：意外回退走根因反转，不打补丁

若 B3 抓出某类 `changed` 是回退（例：`kelei` 克利夫兰切新表后舰名反退成占位符），**第一反应不是给这条写 if 兜底**，而是质疑"新数据源 / 新字段优先级是否本来就更准"。常见错假设是"权威表一定 > 旧映射表"——实测可能是"字段 A 更准但字段 B 更差"。此时反转字段优先级（例：`cn_name` 取 `ship_data_statistics.name` 而非 `ship_skin_template.name`，因为后者含占位符），从根因上让占位符归零 + 舰名修复一次做完。这条可复用排错路径：**先怀疑源与优先级，再怀疑单条数据**。

### B6：换入 + 逐字节核对

验证全绿（lost=0、changed 全部命中修正清单、gained=预期结构变化）后，**unset 输出 env 正常跑一次**让新 index 落 `Output/`，再与已验证的临时版 `cmp`（逐字节一致）才罢休。这与主线第 6 步"换入文件与临时目录源哈希一致"同理，只是比对对象从图片换成 JSON。脚手架旧基线脚本送回收站，index 派生重建走主线第 7 步的增量逻辑。

## 分支 C：占位 / 降级产物伪装成功（静默失败这一整类）

分支 A/B 都假设"产物有数据、只是数据可能错"。但有一类更隐蔽、破坏力更大的失败：**生成脚本在解析/提取失败时，悄悄写下一个结构完全合法、却没有任何有效载荷的占位（或降级）文件**。它能被加载、能通过"是否存在/是否启动"这类外壳检查，于是批量验证一路报绿，实际内容却全是空壳。真实案例：`reconstruct_live2d.py` 在 `extract_motions.py` 提取失败时写 `"Curves": []` 占位壳，而提取失败的根因是一个护栏 `num_keys > 100` 误杀了帧 0（帧 0 是 `time≈-3.4e38` 的参考姿态、一帧合法写全部曲线，大模型几百参数必越界）→ 整 clip 返回 `None` → 占位壳静默留存。磁盘实测 8154 条动作里 5037 条是空壳（61.8%），另 38.2% 曲线名按位置猜错，**真正正确的 0 条，潜伏一年多**。判"动画在播"若只看 `state.currentGroup` 变了（外壳），空壳也能启动，于是"能播但不动 / 乱飘 / 乱闪 / 没反应"全被漏过。本分支给四条硬规则。

### C1：解析失败绝不写占位/降级文件，必须显式报错并非零退出

生成脚本的失败路径**不允许**留下"能被加载但载荷为空"的文件。宁可让产物**缺失**（下游表现为 404 / 显式报错），也不要用占位结构把它伪装成数据。落地：
- 提取/解析返回空结果时，`raise` 或 `sys.exit(1)`（或累计 `bad_models` 后让 `main()` 返回非零码），**不写**该文件的占位版。
- 上游"补占位"的分支（如 reconstruct 写 `"Curves": []`）整段删除，改为一行提示"该文件应由 XX 提取脚本生成，缺失即显式失败"。
- 例外须显式声明：确属源数据本身为空（如游戏里就是空动画的 `effect` clip），要**单独记录为已核对的空**，而不是和静默失败混在同一个占位路径里。

### C2：写独立审计脚本，分类 shell / 错位 / ok；换入前后各跑一次当门禁

审计脚本必须**独立于被测生成逻辑**（自己判自己 = 自证循环）。它重新从权威源（如 bundle 的 `genericBindings`）推导每个产物"应当是什么"，把磁盘产物分类为 `shell`（载荷为空）/ `misassign`（载荷非空但映射/内容错）/ `ok`。用法铁律：**换入前对正式目录跑一次、换入后对正式目录再跑一次同一脚本**，两次都必须 `0 shell / 0 错位` 才算通过（本轮修复前 shell 61.8% + misassign 38.2% = 100% 坏，正是门禁数值）。审计脚本应带 env 输出目录开关（如 `L2D_OUT_DIR`），以便对临时目录先审再审正式目录。

### C3：验证判据落在载荷本身 + 独立不变式裁定，而非外壳状态、非自证

呼应顶部横切原则。动效类：`len(Curves) > 0` **且** 采样目标参数在两个时间点取值不同（真的在动）。裁判"新旧谁对"要引入**与被测数据独立**的不变式，而不是"和我的映射逻辑一致"——本轮用的是「同名参数的物理合理取值域」（`ParamEyeLOpen/ROpen` 恒 0..1、`ParamAngle*` ≈ ±30），旧版 23.1% 越域、新版 2.9%，从外部证明新对旧错；再叠加 `crc32` 绑定链跨模型 100% 可解析、91.7% 曲线索引严格升序（随机配对不可能产生）作旁证。

### C4：换入用 move/重命名，不用同名覆盖

第 6 步"复制备份 + 同名覆盖"在面对占位壳时有残留风险：半覆盖会新旧混血，且旧壳若被引用路径漏改会潜伏。改用**原子 move**：先把正式目录旧产物整体 `move`（重命名）进带日期/用途的备份目录，确认到达后再把临时目录新产物 `move` 进正式位置。换入后仍逐字节核对新位置==临时源；确认无误后备份目录再送回收站。move 天然避免"覆盖到一半失败留下混合态"，也让占位壳不可能因覆盖遗漏而残留。

## 分支 D：内部不变式全绿、观感仍错 → 外部权威基准逐字段比对

分支 A/B/C 的共同前提是**判据落在载荷本身 + 用与被测数据独立的不变式裁判**。这能可靠挡住"空壳 / 降级 / 映射错 / 字段变空"。但有一类失败它们全都挡不住——**载荷非空、结构合法、所有内部不变式一路绿灯，观感却仍然错**。因为错在**数值口径 / 单位 / 量级**，而这种错误"错得自洽"，内部证据看不见自己看不见。真实案例：`extract_motions.py` 把 motion3.json 的贝塞尔控制点写成**归一化分数**（`0.333 / by1 / 0.667 / by2`），而 Cubism 运行时解析器 `points[a]=new j(seg[l+1],seg[l+2])` 是**按绝对 (时间,值) 直读、不做任何反归一化**——于是控制点被当成"t=0.333 秒、值≈0.667"，落在段外且接近 0，每条贝塞尔先猛蹿到 0 再跳回目标 → 部件乱摆。可曲线数、时长、crc32 绑定映射、参数量程**全部命中 moc3、全部自洽、全部绿色**，自检完全看不见这个数量级错误。本轮在"呼吸层 / 插值降级护栏"上误判两轮，直到拿到第三方权威实现（l2d.su）对同一资产的导出做数值 diff，才一次锁定根因。本分支给三步流程 + 两条判据。

### D0：先确认"内部已全绿仍错"，才升级到外部取证

不是所有观感错都走 D。先跑遍分支 A/B/C 的内部判据（载荷非空、映射命中、量程不越界、关键帧 / 结构对齐）。任一项红 → 那是 A/B/C 的场景，不必引入外部源。**只有当内部判据全绿、观感仍系统性错、且怀疑指向"数值口径 / 单位 / 量级"这类自检天然看不见的维度时才升级**。核心命题：内部不变式只能证"结构对、非空、自洽"，证不了"取值口径对"；判数值对错必须引入**被测系统之外的权威实现**产出的同一资产做基准。

### D1：反查外部权威源的资源路径，抓到同资产的权威导出

优先找**独立实现了同一运行时 / 协议**的第三方（本例 l2d.su 也是 Live2D Cubism Web viewer，其 motion3.json 就是"正确答案"的近似）。定位其资源直链：

1. 抓目标站前端 SPA 主 bundle（`.../assets/index-*.js`），**grep 里面的路径模板字符串**（如 `'live2d/Z23/Z23.model3.json'`），反推出资源命名规律与 base 前缀（线索常散在别处，如页面里 `https://static.l2d.su//azurlane/squareicon/antu_2.webp` 暴露了 CDN 根）。
2. 拼出候选 URL，用 `curl -s -o /dev/null -w "%{http_code} %{size_download}"` **探活**，命中 200 再实拉；写循环批量探多个候选 key，**404 直接跳过**（404 常返回一段 HTML、体积易与真文件混淆，落地后先验 JSON 能否解析）。
3. 接受**覆盖是子集**（本例 14 个抽样 key 只命中 8 个）——外部源不要求全覆盖，够做抽样 oracle 即可。抓 `<KEY>.model3.json` + 若干 `motion/*.motion3.json` 落 `.diag/_ref/`。
4. 附带红利：读**被测运行时自己的解析器源码**（min.js 里 grep 段处理 / 求值函数），确认它到底怎么消费字段——这是判"格式对不对"的终极权威，比任何规范文档都硬。

### D2：按被测运行时的真实求值语义采样比对，而非逐 Segment / 逐字段比原始数组

拿到基准后**不要**拿两边的 Segment 原始数组逐项 diff——同一动作可以有多种合法表示（参考版 5% 贝塞尔 + 大量线性 / 阶梯，我们可能全贝塞尔），逐数组比会把表示差异判成海量假阳性。正确做法：**在稠密时间点上，用与运行时一致的求值公式分别解出被测产物与基准的曲线取值，再比解出来的数值**。

- 对每条同名曲线，按运行时语义把 Segments 展平成 (时间, 值) 关键点 + 段类型（线性 / 贝塞尔 / 阶梯），在密集采样时刻插值求出值，比被测 vs 基准的逐点偏差。
- 输出三项指标：**偏差中位数**（整体对不对）、**超阈值曲线数 / 占比**（有多少条错）、**最大偏差**（最坏多糟）。本例据此把三个候选一次判清：旧产出品均差 1.376、92/98 曲线偏 >0.5（判死）；绝对贝塞尔版中位 0 但 88/278 偏、最大 **296**（更差！）；**纯线性版中位 0、仅 11/278 偏、最大 1.95**（复现基准）——最终换入线性版。
- 跨 clip / 跨模型抽多个样本确认结论一致（本例四个 clip 线性版中位 0.07–0.20 vs 旧版 2.4–2.6），别拿单条曲线定生死。

### D3：用「结构完全正确时的真实残差」校准 WARN 阈值

比对必然有残差（表示法不同、基准自身也是近似），阈值不能拍脑袋。本例初版把 WARN 卡在 **5%** 太死——`touch_body` 9.6% 恰好落在"参考版贝塞尔占比 ~7% 的天花板"上，是**可达残差上限**而非 bug。校准方法：

- 拿"已知结构完全正确"的场景（基准自比 / 表示法最优版）测出**正常残差分布**，把 WARN 阈值定在这条实测可达上限**之上**；
- 阈值分档设红线（中位 = 0 才叫对齐；超阈值曲线占比、最大偏差各自单独设线）；
- 把校准依据写进工具 / 文档（"5% 太死，按 7% 贝塞尔天花板放宽"），下一位才知道阈值不是随手取的。

### 判据①：格式规范正确 ≠ 验收通过（以基准 diff 定胜负，不许规范自证）

"符合 Cubism 规范写法"只是**合规**，不是**验收**。本例绝对贝塞尔控制点写法完全符合规范、运行时也确实按绝对值读——但对权威基准的偏差最大 296，反而是候选里**最差**的那个；线性版谈不上"精确还原贝塞尔"，却最贴近基准。**两个都合规的导出谁对，只能靠外部基准 diff 判，不能靠"我符合规范"自证。** 差点按"规范里怎么写"换入更差的绝对贝塞尔版，是基准 diff 把它反转回线性版。推论：交接文档 / 重导命令里写的环境开关，必须与**实际换入并通过验收的那一版**一致（本轮交接初稿误写 `L2D_MOTION_ABSOLUTE_CP=1`，实换入的是线性版——照命令重跑会直接返工，发现后当场改正）。

### 判据②：交接文档必须列「已排除假设清单」

排查型任务写交接 / TROUBLESHOOTING 时，除"根因是什么"，**必须显式列出"哪些假设已被什么证据排除、排除依据是什么"**，否则下一位会把这些死路重新走一遍。本例已排除清单（每条带证据）：呼吸层只碰头部 5 参数、管不到小臂；字段布局 f1=入切线 / f2=出切线 / f4=值，与已导出 motion3 精确互推 → 取值自洽、非错位；98 条曲线全部落在合法量程内、不会被硬钳；`m_Enabled` 全 1、无"游戏禁用我们照驱"的参数；180 条 ConstantClip 里 179 条等于 moc3 默认值、丢弃几乎无损（不是根因）；"1.5 秒间隔的键不该拿 1/60 秒割线当导数"这类**判据本身写错**也要主动收回。清单让根因的说服力建立在"排除法"上，而不是又一次猜测。

### 换入仍沿用主线闸门

D2 选定"对基准偏差最小"的候选后，仍走分支 A 第 3–7 步 / 分支 C4：临时目录产出 → 对照组逐字节证零回退（本轮对照组 104/104 一致）→ 改前改后对比交用户确认 → move / 重命名换入 → 逐字节核对 → 派生重建。**外部基准只解决"选哪一版对"，不替代安全落地流程。**

## Pitfalls

- **禁止盲目全量重跑**：即使"感觉都可能受影响"，也先做第 1 步扫描拿数据说话；扫描比全量重跑便宜几个数量级。
- 扫描阶段误用完整解码路径（读纹理像素、初始化渲染器）会把"秒级扫描"变成"小时级"——只要元数据。
- 豁免未经像素级/no-op 证明就跳过重跑，是本流程最常见的漏改来源；存疑就放进对照组或受影响集。
- 临时目录名与正式目录混用会直接覆盖产物；第 3 步开始前用一行断言检查输出路径前缀。
- 换入前忘记备份；第 4 步 maxdiff=0 未达成就硬换入；忘记重建派生缩略图导致 gallery 里新旧不一致——这三件事各自都有真实翻车案例。
- 受影响清单落盘后要用 `cut`/循环直接消费，避免手抄名单漏项。
- **元数据场景不能靠"看着像修正"**：没有逐像素可比时，必须用独立于被测数据源的领域不变式（拼音、占位符、归属规则）裁判每个 `changed`，否则把回退当修正放行。
- **"新数据源不一定更准"**：切主源前默认"权威表 > 旧映射"是错的；先跑一次字段级 diff 摸清 lost/changed/gained 结构，再决定字段优先级（见 B5），别先入为主。
- **预期结构变化必须显式声明**：拆分 / 合并 / 新增类别（如 META 独立卡 +54）不写进豁免清单，就会在 diff 里和意外回退混淆。
- **不变式覆盖不到的字段不能默认放行**：用户拒绝逐条审阅时，边界外的字段要暴露给人工抽样，而不是藏进"通过"。
- **人工复核清单里图片别用 `file://` 绝对路径**：Markdown 预览器/浏览器的安全策略会拦截本地 file:// 图片、全部显示"加载失败"；`.md` 放项目根目录用 `Output/...` 相对路径即可（见 B3-H）。
- **勾选框别写成纯文本方括号**：`- 自机? []` 在支持 GFM 的预览器里不渲染成可点击控件；必须用任务列表语法 `- [ ] 文字`（短横线+空格+`[ ]`+空格+文字），用户勾完才能变成 `- [x]` 供提取（见 B3-H）。
- **shell 反引号 / `$` 会污染文档追加与内联 PS**：写 markdown（含反引号）、跑带变量的 PowerShell 时，用 Write 工具落脚本文件再执行，别 `echo ... >> file` 或内联拼接。
- **占位/降级文件伪装成功**：解析失败时写结构合法的空壳（如 `"Curves": []`），下游能加载、能"启动"，批量验证全绿却内容全空——潜伏期可达数月甚至一年以上。失败必须显式报错并非零退出，产物宁可缺失也不要伪装（见 C1）。
- **验证判据看外壳状态而非载荷**：用"是否被加载 / `currentGroup` 是否变 / 记录是否存在"判通过，是这类静默失败的帮凶。判据必须落在载荷本身（非空 + 真的生效），见顶部横切原则与 C3。
- **提取护栏在批量下静默毁掉整批**：诸如 `num_keys > 100` 之类"防越界"护栏，会在正常大输入（如参考姿态帧 0 一次写全部曲线）上误杀 → 返回空 → 触发占位壳。改/加任何护栏后，必须先小规模跑真实分布、并以独立审计脚本证 shell 率为 0，别只测单个小样本。
- **审计脚本自己判自己 = 自证循环**：验证逻辑若复用被测脚本的映射/解析口径，错也错得一致、必然全绿。审计须从独立权威源重建期望值（见 C2/C3）。
- **内部不变式全绿 ≠ 数值正确**：单位 / 量级类错误（贝塞尔控制点写成归一化分数、运行时按绝对 (时间,值) 直读）"错得自洽"，曲线数 / 时长 / 映射 / 量程能同时全绿。这类错内部证据挡不住，唯一解法是抓第三方权威实现对同一资产做外部基准比对（见分支 D）。
- **别拿"符合规范格式"当验收标准**：规范自证不算数，合规的两个导出可能一个比另一个差一个数量级（本例绝对贝塞尔版偏差 296 > 线性版 1.95）。谁对以外部基准 diff 定，不以规范定（见分支 D 判据①）。
- **比对别拿 Segment / 字段原始数组逐项 diff**：同一动作有多种合法表示（全贝塞尔 vs 大部分线性），逐数组比会把表示差异判成海量假阳性。必须按被测运行时的真实求值语义在稠密时间点上采样后再比值（见 D2）。
- **WARN 阈值别拍脑袋**：5% 卡太死会把"表示法天花板"（如 7% 贝塞尔导致的 9.6% 正常残差）误判成回退。用"结构完全正确时的真实残差"校准阈值、并把校准依据写进工具（见 D3）。
- **交接文档只写根因、不列已排除假设 = 逼下一位重走弯路**：排查型交接必须附"哪些假设已被何证据排除"清单；同时重导命令 / 环境开关要和实际换入并通过验收的那版一致，别写候选里更差的一版（见分支 D 判据①②）。
