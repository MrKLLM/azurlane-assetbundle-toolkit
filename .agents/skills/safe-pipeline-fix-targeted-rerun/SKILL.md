# 管线修复安全落地：定位→验证→小范围重跑→换入

数据驱动的批量管线（一个脚本从源数据推导出成百上千个产物文件）中，修复了某个系统性 bug 后，**不要盲目全量重跑**。全量重跑会打乱已验证正常的产物、耗时数十倍、且无法回答"哪些结果变了、变得对不对"。本技能用 7 步把风险收敛到真正受影响的子集。

## 适用场景

- 修改了合成/导出/渲染批处理脚本的某段通用逻辑（坐标、画框、缩放、依赖解析等），需要重跑既有产物
- 需要向用户证明"这次修复不会弄坏已正常的 N 个产物"
- 产物目录旁挂着派生物（缩略图、索引、gallery 数据），换入后需同步重建
- 切换了元数据主源 / 改了字段解析优先级（如把 index 的 `cn_name`、`faction` 从旧映射表换成新 JSON 表），产物是结构化 JSON 而非像素，需证零回退 → 走「分支 B」

不适用：产物本来就全是错的/首次全量生成（直接全量跑）；产物无已验证存量（没有可保护的东西）。

## 工作流

### 第 0 步：修复前先建 git 基线

换入前工作区必须干净，且修复逻辑的 diff 可单独 review。若管线仓库在 git 下，先 `git add -A && git commit` 当前状态；产物不在 git 里也没关系，第 6 步的文件级备份兜底。

### 第 1 步：只读扫描，定位受影响全集

写一段**只解析元数据**的扫描逻辑（或复用主管线的解析函数，只跑到"拿到结构/尺寸信息"为止，**不解码纹理、不渲染**），对全量源数据跑一遍，判据是"新逻辑与旧逻辑对该条数据是否会分叉"（例如比较两个尺寸字段是否相等）。输出清单落盘，例如 `.diag/frame_mismatch.txt`，每行 `名称\t部件\t旧值\t新值`，供后续 shell/循环直接复用。

扫描必须带进度与错误计数（`errors: 0`），有异常条目单独列出而不是静默跳过。

### 第 2 步：语义豁免——区分"逻辑变了"与"结果可见变化"

名义受影响的子集往往远大于真正需要重跑的。对清单按数据特征分类，并**证明像素级 no-op** 后才允许豁免：

- 例：540/556 条命中项是 4×4 全透明占位贴图（alpha 通道最大值为 0）——无论旧逻辑缩小还是新逻辑拉伸，绘制结果都不变，无需重渲。抽样解码这些贴图的 alpha 极值来证明，而不是想当然。
- 例：某部件最终被其他层完全遮挡、或新旧 bbox 并集不变——可通过对比合成尺寸/包围盒预判，再交给第 4 步对照组兜底验证。

豁免结论要写成一句可复核的话（"全透明→alpha 遮罩下任何变换均不改像素"），并保留至少 1 个豁免类样本进入对照组让逐像素 diff 检验。

### 第 3 步：受影响项 + 对照组重渲到临时目录

只重渲：① 第 2 步筛出的真实受影响项全集；② 3-5 个**对照组**样本——从未受影响的产物中挑，且必须包含"边界案例"（被豁免的类型、结构最复杂的、随机抽查的普通案例）。全部输出到独立临时目录（如 `.diag/xxx-fix/`），**绝不直接写正式产物目录**。

### 第 4 步：对照组逐像素校验，证明零回退

对每个对照样本：`现产物 PNG vs 临时目录新渲 PNG`，尺寸必须一致，逐通道 `np.abs(...).max() == 0`（maxdiff=0）。任何一个对照样本 diff≠0 都说明扫描判据漏了某类分叉——回到第 1 步扩大判据，不得继续。同时记录受影响项的新旧尺寸差（如 `junzhu_5 高度 +50`）作为旁证。

### 第 5 步：改前/改后对比总览 → 用户确认闸门

为**每个**受影响项生成并排对比图（左旧右新、深色底合成、带文件名标注；数量多时再拼总览大图），临时目录存放（如 `.diag/cmp_xxx/*.jpg`）。agent 先自行 Read 逐张审阅确认修复方向正确（该变好的变好了、不该动的没乱），再呈现给用户，明确等待确认后进入换入。这是硬闸门：未经用户确认不得覆盖任何正式产物。

**机器指标不能替代目视，两者是互补而非可互替**（实测教训）：某次 35 张重渲的量化口径显示"改动旧像素占比"最高者达 71.7%，但目视才确认那一张是**回退**（改前已是完整清晰的另一表情，叠层把它换掉了）；而指标次高的几张（42%/37%）目视确认改前是淡化半脸/白块/缺头，属正确修复。也就是说：**指标用来排序和缩小人工范围，最终判定必须看图**。据此筛出的误判样本，修法应是**收紧判据**（换成按叠层自身落笔足迹度量），而不是在代码里写手工例外名单。

### 第 6 步：备份 → 换入

0. **换入前必做两项预检**：
   - **硬链接预检**：逐个 `os.stat(f).st_nlink`，`>1` 的文件**不能直接覆写**（`open('wb')`/copy 会穿透链接同时改掉孪生文件）。要么先 `os.remove` 断链再写入（孪生保留旧内容），要么把同组文件一起纳入本次改动范围。资产目录做过去重的仓库尤其危险。
   - **引用面预检**：确认这些文件被谁按什么引用（索引 JSON / 缩略图 / 图片墙）。若消费方按文件名引用，路径不能变；若索引里存了尺寸等派生字段，需一并重建。
1. 把受影响项的旧产物整体复制到带日期/用途的备份目录（如 `.diag/backup_before_framefix/`），换入前先确认备份文件数==受影响文件数。
2. 用临时目录中的新产物按同名覆盖正式产物目录。
3. 逐字节核对换入后的文件与临时目录源一致（`cmp` / 哈希）；**再证"没误伤别人"**：统计未涉及文件的 `mtime` 是否全部未变（`time.time()-os.path.getmtime(f) < 本次运行窗口` 的应为 0 个），这比"抽查几张"更能证明改动范围受控。

### 第 7 步：增量重建派生产物 → 提交

派生物（缩略图、索引、gallery JSON）不要全量重建：删除受影响项对应的派生文件，然后跑**只补缺项**的增量生成器（天然跳过已存在项），输出里确认"新建数==受影响数、跳过数≈其余"。最后 git 提交，message 写明修复内容与换入数量。

## 分支 B：非视觉元数据 / 生成索引的权威源切换

上面 7 步假设产物是**像素可比对**（PNG 逐通道 `maxdiff==0`）。但当改的是**元数据推导口径**——例如把 gallery `index.json` 的 `cn_name`、`faction` 从旧映射表（`SHIP_NAME_MAP`+Wiki）切换到新的权威 JSON 表（`ship_meta.json`）——产物是结构化 JSON，没有像素可比。**用户又明确拒绝逐条人工审阅**（"上千条我看不过来"），此时不能靠"看着像修正"放行，必须让机器承担裁判责任。本分支把 7 步方法论平移到这个场景。

核心思路：`git show` 旧脚本重生成旧基线 → env 开关把新产物写临时目录 → 逐条目 × 逐字段三分类 diff → **用领域不变式把 `changed` 自动判成"修正"或"回退"** → 意外回退走根因反转而非打补丁 → 换入后逐字节核对。

### B0：用 `git show` 旧脚本重生成旧基线（不改工作区）

不要靠"当前正式产物就是旧基线"——正式产物可能已被别的改动污染。直接从 git 取**修改前版本的脚本**跑一遍，得到干净基线：

```
git show HEAD:scripts/build_gallery_index.py > .diag/_old_bgi_tmp.py
# 用旧脚本输出到 .diag/old_gal/index.json（旧脚本若无输出开关，临时改它的 OUT 常量到临时目录再跑）
```

`HEAD` 必须是"改动前最后一次提交"；若本次改动尚未提交，先按第 0 步建基线再改。旧基线脚本是临时脚手架，换入后送回收站，不入库。

### B1：给新脚本加 env 输出开关，新产物写临时目录

新脚本增加一个环境变量（如 `GALLERY_OUT_DIR`）：默认落正式目录，设了该变量就落临时目录（如 `.diag/b_test/`）。**正式目录零污染**，验证通过前绝不写 `Output/`。这与主线第 3 步"输出到独立临时目录"同构，只是落点从图片目录换成 index 目录。

### B2：逐条目 × 逐字段 diff，三分类 lost / changed / gained

以主键（船名 / stem）对齐新旧 index，对每条目的关键字段（`cn_name`、`faction`、`category`、`skins` 列表等）逐一比较，把差异分三类：

- **lost**：旧有新无的条目 / 字段值从有变空 → 几乎总是回退，红线，必须为 0（除非声明了合并豁免）。
- **changed**：同一条目字段值不同 → 需 B3 裁判是修正还是回退。
- **gained**：新多出的条目 / 字段从空变有 → 可能是修正，也可能是 B4 的预期结构变化。

输出三分类计数 + 每类清单落盘（如 `.diag/_field_diff.txt`），供 shell 直接消费，不手抄。

### B3：领域不变式自动裁判 changed（替代人眼）

这是本分支相对主线第 5 步的**关键差异**：用户不看，就得有可计算的规则替他把每个 `changed` 判成"对"或"错"。不变式必须是**独立于被测数据源**的事实，否则自证循环。常用不变式（按项目挑选 / 新增）：

- **磁盘 stem == 正确中文名拼音**：`index` 里 `cn_name` 对应的 PNG 文件名 stem，必须等于该中文名的拼音（`pypinyin` 生成）。谁违反谁错——若新表让某船 `cn_name` 变了导致 stem≠拼音，说明新表这个值可疑；若旧值本就错、新值让拼音对齐了，则是修正。
- **占位符命中数 == 0**：字段值里不得出现 `{namecode}` 之类未解析占位符。新表若引入占位符（如 `ship_skin_template.name` 含数百个占位符），命中即回退。
- **阵营 / 类别归属规则**：faction=META 的形态不得作为皮肤并进本体船（见 B4 的 META 独立卡），category 取值必须在白名单内。
- **非空字段不得变空**：某船旧有 `cn_name` 新为空 → 回退。

对每个 `changed`：跑全部适用不变式。**通过 = 修正**（自动放行并记入修正清单）；**违反 = 回退**（拦下，转 B5 根因）。**不变式覆盖不到的字段必须显式回落到人工**——不能因为"用户不想看"就默认放行；此时向用户报告"这些字段无不变式可判，需要抽样看"，让用户决定。用户拒绝逐条 = 不变式覆盖率就是安全边界，边界外的必须暴露而不是藏起来。

### B4：声明预期结构变化，把 gained 与漏字段区分开

主动的建模改动（例：META 形态从本体船拆成独立卡，`gained` +54 条）会同时抬高 gained/changed 计数，若不声明就会和"意外新增/回退"混淆。在跑 diff 前，用一份清单**显式声明预期 delta**（"META 独立成卡：预期 gained 56 个 `_meta`/`_alter` 卡、本体船 skins 减少对应项"）。命中清单的结构变化计入"预期"，清单外的 gained 才需 B3 裁判。这一步让"总船数 954→1008"这类数字变成可核对的预期值，而不是吓人的意外。

### B5：意外回退走根因反转，不打补丁

若 B3 抓出某类 `changed` 是回退（例：`kelei` 克利夫兰切新表后舰名反退成占位符），**第一反应不是给这条写 if 兜底**，而是质疑"新数据源 / 新字段优先级是否本来就更准"。常见错假设是"权威表一定 > 旧映射表"——实测可能是"字段 A 更准但字段 B 更差"。此时反转字段优先级（例：`cn_name` 取 `ship_data_statistics.name` 而非 `ship_skin_template.name`，因为后者含占位符），从根因上让占位符归零 + 舰名修复一次做完。这条可复用排错路径：**先怀疑源与优先级，再怀疑单条数据**。

### B6：换入 + 逐字节核对

验证全绿（lost=0、changed 全部命中修正清单、gained=预期结构变化）后，**unset 输出 env 正常跑一次**让新 index 落 `Output/`，再与已验证的临时版 `cmp`（逐字节一致）才罢休。这与主线第 6 步"换入文件与临时目录源哈希一致"同理，只是比对对象从图片换成 JSON。脚手架旧基线脚本送回收站，index 派生重建走主线第 7 步的增量逻辑。

## Pitfalls

- **禁止盲目全量重跑**：即使"感觉都可能受影响"，也先做第 1 步扫描拿数据说话；扫描比全量重跑便宜几个数量级。
- 扫描阶段误用完整解码路径（读纹理像素、初始化渲染器）会把"秒级扫描"变成"小时级"——只要元数据。
- 豁免未经像素级/no-op 证明就跳过重跑，是本流程最常见的漏改来源；存疑就放进对照组或受影响集。
- 临时目录名与正式目录混用会直接覆盖产物；第 3 步开始前用一行断言检查输出路径前缀。
- 换入前忘记备份；第 4 步 maxdiff=0 未达成就硬换入；忘记重建派生缩略图导致 gallery 里新旧不一致——这三件事各自都有真实翻车案例。
- 受影响清单落盘后要用 `cut`/循环直接消费，避免手抄名单漏项。
- **元数据场景不能靠"看着像修正"**：没有逐像素可比时，必须用独立于被测数据源的领域不变式（拼音、占位符、归属规则）裁判每个 `changed`，否则把回退当修正放行。
- **"新数据源不一定更准"**：切主源前默认"权威表 > 旧映射"是错的；先跑一次字段级 diff 摸清 lost/changed/gained 结构，再决定字段优先级（见 B5），别先入为主。
- **预期结构变化必须显式声明**：拆分 / 合并 / 新增类别（如 META 独立卡 +54）不写进豁免清单，就会在 diff 里和意外回退混淆。
- **不变式覆盖不到的字段不能默认放行**：用户拒绝逐条审阅时，边界外的字段要暴露给人工抽样，而不是藏进"通过"。
- **shell 反引号 / `$` 会污染文档追加与内联 PS**：写 markdown（含反引号）、跑带变量的 PowerShell 时，用 Write 工具落脚本文件再执行，别 `echo ... >> file` 或内联拼接。

## Verification

- 第 1 步：扫描 errors=0，受影响数与后续分类总和一致（481 名义 → 540 行 no-op 分类 + 10 重渲，能对上账）。
- 第 4 步：全部对照样本 maxdiff=0。
- 第 6 步：备份目录计数==换入计数；换入文件与临时目录源哈希一致。
- 第 7 步：增量生成器报告"补建 N 项"且 N==受影响项数；`git status` 干净、提交信息含修复描述与数量。
- 分支 B - B2：`lost == 0`（红线）；`changed` 全部命中修正清单；`gained` 数量 == 声明的预期结构变化数（如 META 56）。
- 分支 B - B3：占位符命中数 == 0；对"修正"类 changed，拼音一致率 == 100%；无"非空字段变空"；不变式未覆盖的字段已列明并交人工抽样，未默认放行。
- 分支 B - B6：正式目录新 index 与已验证临时版 `cmp` 逐字节一致；脚手架旧基线脚本已清除、不入库。
