# 管线修复安全落地：定位→验证→小范围重跑→换入

数据驱动的批量管线（一个脚本从源数据推导出成百上千个产物文件）中，修复了某个系统性 bug 后，**不要盲目全量重跑**。全量重跑会打乱已验证正常的产物、耗时数十倍、且无法回答"哪些结果变了、变得对不对"。本技能用 7 步把风险收敛到真正受影响的子集。

## 适用场景

- 修改了合成/导出/渲染批处理脚本的某段通用逻辑（坐标、画框、缩放、依赖解析等），需要重跑既有产物
- 需要向用户证明"这次修复不会弄坏已正常的 N 个产物"
- 产物目录旁挂着派生物（缩略图、索引、gallery 数据），换入后需同步重建
- 切换了元数据主源 / 改了字段解析优先级（如把 index 的 `cn_name`、`faction` 从旧映射表换成新 JSON 表），产物是结构化 JSON 而非像素，需证零回退 → 走「分支 B」
- 内部不变式（曲线数 / 时长 / 字段映射 / 量程）全部通过、载荷也非空自洽，但**观感仍系统性错**（动作乱摆 / 颜色偏 / 时序怪），怀疑是**数值口径 / 单位 / 量级**类错误 → 走「分支 D」：用被测系统之外的权威实现产出做外部基准 diff

不适用：产物本来就全是错的/首次全量生成（直接全量跑）；产物无已验证存量（没有可保护的东西）。

## 横切原则：验证判据必须落在载荷上，而非状态标签

贯穿本技能所有分支（含分支 C）的一条铁律：**判"产物对不对"，永远看载荷本身非空且真的生效，不看"它是否被加载/启动了/状态变了"**。

- 反例（真实翻车）：无头验证断言 `state.currentGroup` 变了来判"动画在播"——这只证明动作**启动了**；一个 `"Curves": []` 的空壳同样能启动、同样让 `currentGroup` 变化，于是 260/260 全绿却人人都在"能播但不动"。
- 正例判据（动效类）：**数曲线条数**（`len(Curves) > 0`）+ **采样目标值随时间变化**（同一参数在两个时间戳取值不同）。静态/元数据类同理：字段级 diff 比的是值本身，不是"记录存在"。
- 推论：任何"通过"结论都要能回答"你检查的是内容还是外壳"。检查的是外壳的验证一律不算验证。
- **载荷非空且自洽 ≠ 数值正确**：本横切原则能保证"不是空壳、真的生效"，保证不了"取值口径对"。单位 / 量级类错误（贝塞尔控制点归一化分数 vs 绝对值、像素 vs 逻辑坐标）会让曲线数、时长、映射、量程**全部一起变绿**，因为错得自洽。判这类"数值对不对"，唯一可靠手段是抓**被测系统之外的权威实现**产出的同一资产做外部基准比对（见分支 D）。

## 工作流

### 第 0 步：修复前先建 git 基线

换入前工作区必须干净，且修复逻辑的 diff 可单独 review。若管线仓库在 git 下，先 `git add -A && git commit` 当前状态；产物不在 git 里也没关系，第 6 步的文件级备份兜底。

### 第 1 步：只读扫描，定位受影响全集

写一段**只解析元数据**的扫描逻辑（或复用主管线的解析函数，只跑到"拿到结构/尺寸信息"为止，**不解码纹理、不渲染**），对全量源数据跑一遍，判据是"新逻辑与旧逻辑对该条数据是否会分叉"（例如比较两个尺寸字段是否相等）。输出清单落盘，例如 `.diag/frame_mismatch.txt`，每行 `名称\t部件\t旧值\t新值`，供后续 shell/循环直接复用。

扫描必须带进度与错误计数（`errors: 0`），有异常条目单独列出而不是静默跳过。

⚠️ 这一步的产物是**预测量**：漏一条就永久静默。所以每次系统性修复收尾都要走**第 8 步的全库逐字节普查**兜底，别只信这里算出的集合。

### 第 2 步：语义豁免——区分"逻辑变了"与"结果可见变化"

名义受影响的子集往往远大于真正需要重跑的。对清单按数据特征分类，并**证明像素级 no-op** 后才允许豁免：

- 例：540/556 条命中项是 4×4 全透明占位贴图（alpha 通道最大值为 0）——无论旧逻辑缩小还是新逻辑拉伸，绘制结果都不变，无需重渲。抽样解码这些贴图的 alpha 极值来证明，而不是想当然。
- 例：某部件最终被其他层完全遮挡、或新旧 bbox 并集不变——可通过对比合成尺寸/包围盒预判，再交给第 4 步对照组兜底验证。

豁免结论要写成一句可复核的话（"全透明→alpha 遮罩下任何变换均不改像素"），并保留至少 1 个豁免类样本进入对照组让逐像素 diff 检验。

### 第 3 步：受影响项 + 对照组重渲到临时目录

只重渲：① 第 2 步筛出的真实受影响项全集；② 3-5 个**对照组**样本——从未受影响的产物中挑，且必须包含"边界案例"（被豁免的类型、结构最复杂的、随机抽查的普通案例）。全部输出到独立临时目录（如 `.diag/xxx-fix/`），**绝不直接写正式产物目录**。

### 第 4 步：对照组逐像素校验，证明零回退

对每个对照样本：`现产物 PNG vs 临时目录新渲 PNG`，尺寸必须一致，逐通道 `np.abs(...).max() == 0`（maxdiff=0）。任何一个对照样本 diff≠0 都说明扫描判据漏了某类分叉——回到第 1 步扩大判据，不得继续。同时记录受影响项的新旧尺寸差（如 `junzhu_5 高度 +50`）作为旁证。

### 第 5 步：改前/改后对比总览 → 用户确认闸门

为**每个**受影响项生成并排对比图（左旧右新、深色底合成、带文件名标注；数量多时再拼总览大图），临时目录存放（如 `.diag/cmp_xxx/*.jpg`）。agent 先自行 Read 逐张审阅确认修复方向正确（该变好的变好了、不该动的没乱），再呈现给用户，明确等待确认后进入换入。这是硬闸门：未经用户确认不得覆盖任何正式产物。

### 第 6 步：备份 → 换入

1. 把受影响项的旧产物整体复制到带日期/用途的备份目录（如 `.diag/backup_before_framefix/`），换入前先确认备份文件数==受影响文件数。
2. 用临时目录中的新产物按同名覆盖正式产物目录。
3. 逐字节核对换入后的文件与临时目录源一致（`cmp` / 哈希）。

### 第 7 步：增量重建派生产物 → 提交

派生物（缩略图、索引、gallery JSON）不要全量重建：删除受影响项对应的派生文件，然后跑**只补缺项**的增量生成器（天然跳过已存在项），输出里确认"新建数==受影响数、跳过数≈其余"。最后 git 提交，message 写明修复内容与换入数量。

### 第 8 步：全库「产物 vs 当前管线」逐字节普查 —— 本流程自身的兜底闸门

**为什么必须有这一步**：第 1 步产出的"受影响全集"是**预测量**，而本流程只重跑这个预测集合。
⇒ **预测漏一条，那条就永久静默停在旧行为上**，而且没有任何信号。
实证（同一项目两次独立漏判，9 天后才被发现）：09-18 那次嵌套容器错位换入 85 张、
09-19 那次 mesh 越框换入 55 张，两次各自的受影响扫描**分别漏了 2 张和 7 张**；
直到把全库 4488 张逐张「当前管线重渲 vs 磁盘 md5」比一遍才浮出来（§52）。

**怎么做**（只读、不动正式产物、逐条落盘可续跑）：
```bash
py -3 scripts/diag/painting_staleness_scan.py --stamp <日期>            # 全库比对，出差异清单
py -3 scripts/diag/painting_staleness_scan.py --stamp <日期> --resume   # 中断后续跑
```
判据：**差异清单应为空**。非空则逐条定性，且**先量再盯图**：
按「差异像素里 `max(α_旧,α_新) ≥ 40` 才算可见」+ 可见处最大色差分档 ——
色差 ≤6/255 是重采样舍入级（肉眼不可能看见，可批量放过），上百的才需要人工过目。
⚠️ **分型指标一片 0 时先怀疑量尺**：第一版用「消失/新增/仅颜色/半透明」四个桶，
四个桶都不收"低 alpha 像素的颜色差异"，于是 4 张真差异全报 0.0%。

**考古归因法**（发现不一致后，别停在"它不一样"）：把历代脚本从 git 里取出分别重渲，
看在盘文件能被**哪一个提交**逐字节复现，即可直接指认"它漏掉了哪一次修复"：
```bash
git show <commit>:scripts/compose_paintings_v2.py > .diag/oc_<commit>.py
# 逐个提交重渲同一张，比对 md5：能被 c1 复现、不能被 c2 复现 ⇒ 它停在 c1，漏掉了 c2 那次修复
```

**换入用同一个工具**（第 6 步的四道硬检查已固化，别再手搓）：
`py -3 scripts/diag/painting_swap_in.py --list <清单> --from <临时目录> --bak <备份目录>`
—— ① 目标 `st_nlink==1` ② 备份与原文件 md5 全等 ③ 换入后与临时渲染 md5 全等
④ **全目录快照**：mtime/nlink 变化必须正好等于本次清单（清单外 0 个）。
换入后复跑比对，报"与在盘相同 N / 有差异 0"才算闭环 —— 此后"盘上 == 当前管线"这条不变式
才真的可以当回归闸门用。

## 分支 B：非视觉元数据 / 生成索引的权威源切换

上面 7 步假设产物是**像素可比对**（PNG 逐通道 `maxdiff==0`）。但当改的是**元数据推导口径**——例如把 gallery `index.json` 的 `cn_name`、`faction` 从旧映射表（`SHIP_NAME_MAP`+Wiki）切换到新的权威 JSON 表（`ship_meta.json`）——产物是结构化 JSON，没有像素可比。**用户又明确拒绝逐条人工审阅**（"上千条我看不过来"），此时不能靠"看着像修正"放行，必须让机器承担裁判责任。本分支把 7 步方法论平移到这个场景。

核心思路：`git show` 旧脚本重生成旧基线 → env 开关把新产物写临时目录 → 逐条目 × 逐字段三分类 diff → **用领域不变式把 `changed` 自动判成"修正"或"回退"** → 意外回退走根因反转而非打补丁 → 换入后逐字节核对。

### B0：用 `git show` 旧脚本重生成旧基线（不改工作区）

不要靠"当前正式产物就是旧基线"——正式产物可能已被别的改动污染。直接从 git 取**修改前版本的脚本**跑一遍，得到干净基线：

```
git show HEAD:scripts/build_gallery_index.py > .diag/_old_bgi_tmp.py
# 用旧脚本输出到 .diag/old_gal/index.json（旧脚本若无输出开关，临时改它的 OUT 常量到临时目录再跑）
```

`HEAD` 必须是"改动前最后一次提交"；若本次改动尚未提交，先按第 0 步建基线再改。旧基线脚本是临时脚手架，换入后送回收站，不入库。

### B1：给新脚本加 env 输出开关，新产物写临时目录

新脚本增加一个环境变量（如 `GALLERY_OUT_DIR`）：默认落正式目录，设了该变量就落临时目录（如 `.diag/b_test/`）。**正式目录零污染**，验证通过前绝不写 `Output/`。这与主线第 3 步"输出到独立临时目录"同构，只是落点从图片目录换成 index 目录。

### B2：逐条目 × 逐字段 diff，三分类 lost / changed / gained

以主键（船名 / stem）对齐新旧 index，对每条目的关键字段（`cn_name`、`faction`、`category`、`skins` 列表等）逐一比较，把差异分三类：

- **lost**：旧有新无的条目 / 字段值从有变空 → 几乎总是回退，红线，必须为 0（除非声明了合并豁免）。
- **changed**：同一条目字段值不同 → 需 B3 裁判是修正还是回退。
- **gained**：新多出的条目 / 字段从空变有 → 可能是修正，也可能是 B4 的预期结构变化。

输出三分类计数 + 每类清单落盘（如 `.diag/_field_diff.txt`），供 shell 直接消费，不手抄。

### B3：领域不变式自动裁判 changed（替代人眼）

这是本分支相对主线第 5 步的**关键差异**：用户不看，就得有可计算的规则替他把每个 `changed` 判成"对"或"错"。不变式必须是**独立于被测数据源**的事实，否则自证循环。常用不变式（按项目挑选 / 新增）：

- **磁盘 stem == 正确中文名拼音**：`index` 里 `cn_name` 对应的 PNG 文件名 stem，必须等于该中文名的拼音（`pypinyin` 生成）。谁违反谁错——若新表让某船 `cn_name` 变了导致 stem≠拼音，说明新表这个值可疑；若旧值本就错、新值让拼音对齐了，则是修正。
- **占位符命中数 == 0**：字段值里不得出现 `{namecode}` 之类未解析占位符。新表若引入占位符（如 `ship_skin_template.name` 含数百个占位符），命中即回退。
  - ⚠️ **文本要端给人看时，这条必须落到"渲染后的页面"上，不能只落到中间字段上**（2026-09-27 撞过）：
    游戏配置里的台词**自带运行时占位符**（`{namecode:NN}` 由 `name_code` 表展开），结构判据（行数 / 逐字对齐 / 可播）
    全绿也看不见——它已经在页面上挂了整整一天、影响 862 个能播的皮肤行。
    ⇒ 三条一起做：① **生成侧展开**，展开表要带对齐证明（含零假设对照：可解析率、自称率 vs 随机重分配、整行人读），
    别拿"能查到"当"查得对"；② 产物里命中即 `SystemExit`（零容忍，不是记个数了事）；
    ③ 页面级断言（DOM 文本里出现占位符 = 红）。
  - **查不到就原样留着并计数，绝不编一个值填上**——宁可让用户看见 `{namecode:99}`，也不能让管线替游戏造台词。
- **阵营 / 类别归属规则**：faction=META 的形态不得作为皮肤并进本体船（见 B4 的 META 独立卡），category 取值必须在白名单内。
- **非空字段不得变空**：某船旧有 `cn_name` 新为空 → 回退。

对每个 `changed`：跑全部适用不变式。**通过 = 修正**（自动放行并记入修正清单）；**违反 = 回退**（拦下，转 B5 根因）。**不变式覆盖不到的字段必须显式回落到人工**——不能因为"用户不想看"就默认放行；此时按 **B3-H** 的固定规范生成带缩略图内嵌的 Markdown 复核清单交用户勾选（不是 CSV），勾完再落白名单重建。用户拒绝逐条 = 不变式覆盖率就是安全边界，边界外的必须暴露而不是藏起来。

**`lost`（归零 / 字段消失）和 `changed` 一样要裁定，别一律当回退拦、也别一律放行**。换权威源时"某条从有到无"有两种完全不同的成因：新源确实没这个值（回退），或**旧值本来就不属于这一行**（修正——旧口径把别人的数据派给了它）。可复用的裁定不变式形状：**拿旧值指向的实体回查权威主键，看它是否落在本行的归属集合里**；不在 = 修正，在 = 回退。真实案例：旧社区表把 `cv-20705`（可畏）的语音记成"可雷"，切到游戏自己的皮肤表后归零 ⇒ 该行的包号集合是 `{90040}`，旧包号不在其中 = 修正。**这个判定必须是规则，不许落成"某几个名字豁免"的例外名单**——例外名单会让下一个同类错配原样溜过。

### B3-G：比对闸门自身的两类失效（它红不代表产品坏，它绿更不代表产品好）

- **"允许变化的字段"必须仍然参与比较**。第一版常写成 `scalars(d, skip = 白名单 | {...})`，把白名单字段整个剔出比较集 —— 于是"这个字段从有到无"那条判据**在结构上不可达**，闸门对着最该拦的东西给绿灯。正确形状：全部标量都比，比出差异后再按白名单分流成"期望变化 / 回退"。凡新增判据，先构造一条**它必然为红的输入**验一遍（本例：故意留一条真回退，看闸门是否报红）。
- **哈希台账要按"落盘字节"算，不是按内存里的字符串算**。Windows 上 `open(p,'w')` 文本模式会把 `\n` 写成 `\r\n`，于是 `bytes`/`sha256` 记的是 LF 版本、盘上是 CRLF 版本 —— 只要产物带换行，校验脚本就**永久报 DRIFT**（假红灯挂久了，真漂移就混在噪声里看不见）。发布脚本一律 `open(p,'wb').write(blob.encode('utf-8'))`。同一类："校验一直红"和"校验一直绿"都要怀疑校验本身，先用一个已知一致的样本反测。

### B3-H：人工复核清单输出规范（不变式覆盖不到时的交付物）

不变式判不了的疑难残余，导给用户人工复核时**固定用带缩略图内嵌的 Markdown 文件**（如项目根目录 `story_review.md`），**不是 CSV**——用户要边看图边勾选，CSV 无法内嵌图片（实际会话中已被明确否掉）。勾选完成后 `grep '\[x\]'` 提取条目，落入白名单（如 `build_gallery_index.reclassify` 的 `EXTRA_SHIP`）重建。格式五要素：

1. **图片用相对路径，禁止 `file://` 绝对路径**。`.md` 放项目根目录时，缩略图引用写 `Output/gallery_v2/thumbs/xxx.webp` 这类相对路径即可。踩坑实录：初版用 `file:///D:/Azur%20Lane%20Assets/...` 绝对 URL，Markdown 预览器/浏览器因安全策略全部拦截显示"加载失败"，换相对路径后正常。
2. **排序：越像目标类别越靠前**——有阵营/舰种/Spine/Live2D 等指向性特征的条目放最前，降低用户翻页成本。
3. **每条固定结构**：三级标题 `### 001 中文名 \`key\``（编号 + 中文名 + 反引号 key）→ 元数据行（阵营 / 舰种 / 稀有度 / 皮肤数 / Spine / Live2D / source）→ 缩略图 `![名称](相对路径)` → 一条 GFM 任务列表项 `- [ ] 自机?`（问题文字按场景定）。
4. **勾选框必须用 GFM 任务列表语法**：`- [ ] 文字`（短横线 + 空格 + `[ ]` + 空格 + 文字），支持 GFM 的预览器才会渲染成可点击的真实 checkbox；写成 `- 自机? []` 这类纯文本方括号**不会**渲染成交互控件。用户勾完后 `- [ ]` 变 `- [x]`，据此提取落白名单。
5. **文件开头加一行勾选规则说明**：告诉用户把 `- [ ]` 改成 `- [x]`（或直接报条目编号 / key 均可）。

### B4：声明预期结构变化，把 gained 与漏字段区分开

主动的建模改动（例：META 形态从本体船拆成独立卡，`gained` +54 条）会同时抬高 gained/changed 计数，若不声明就会和"意外新增/回退"混淆。在跑 diff 前，用一份清单**显式声明预期 delta**（"META 独立成卡：预期 gained 56 个 `_meta`/`_alter` 卡、本体船 skins 减少对应项"）。命中清单的结构变化计入"预期"，清单外的 gained 才需 B3 裁判。这一步让"总船数 954→1008"这类数字变成可核对的预期值，而不是吓人的意外。

### B5：意外回退走根因反转，不打补丁

若 B3 抓出某类 `changed` 是回退（例：`kelei` 克利夫兰切新表后舰名反退成占位符），**第一反应不是给这条写 if 兜底**，而是质疑"新数据源 / 新字段优先级是否本来就更准"。常见错假设是"权威表一定 > 旧映射表"——实测可能是"字段 A 更准但字段 B 更差"。此时反转字段优先级（例：`cn_name` 取 `ship_data_statistics.name` 而非 `ship_skin_template.name`，因为后者含占位符），从根因上让占位符归零 + 舰名修复一次做完。这条可复用排错路径：**先怀疑源与优先级，再怀疑单条数据**。

### B6：换入 + 逐字节核对

验证全绿（lost=0、changed 全部命中修正清单、gained=预期结构变化）后，**unset 输出 env 正常跑一次**让新 index 落 `Output/`，再与已验证的临时版 `cmp`（逐字节一致）才罢休。这与主线第 6 步"换入文件与临时目录源哈希一致"同理，只是比对对象从图片换成 JSON。脚手架旧基线脚本送回收站，index 派生重建走主线第 7 步的增量逻辑。

### B7：审计"处理不了的那一批"——按可救性分解，判据必须比该子集更上游（2026-09-27 撞过）

管线跑完总剩一批 🔇/跳过/失败项。只报总数（"还有 354 张无解"）没法拍板，且会被当成待办反复重提。两条要求：

1. **按可救性分类，四类动作完全不同**：等上游下发（本机与设备两侧都查过）/ 换权威源就能定 /
   需要人裁定语义 / 结构性没有。分类表要带"其中还能拿到什么"这一列（例：音频缺但正文齐全 ⇒ 那是产品口径缺口，不是数据缺口）。
2. **循环判据（最贵的一类假结论）**：拿派生表回答关于派生条件的问题。
   例——词表的 `m` 是**只遍历已解析出声的条目**建出来的，用它问"无解条目有没有正文"恒为 0，
   看起来像"它们连正文也没有"，其实是同一筛选条件的自我复述；换成直接查权威表后是 100/354。
   **通用形状：凡是 "A 是从 B 筛出来的"，就不能用 A 回答关于 B\A 的问题。**
   配套：审计工具必须 `import` 管线自己的解析函数，另写一份判据审的就是另一个东西。
3. **裁定"能不能继承父条目"要非循环证据**：别问"剥掉这个后缀能不能命中"（必然能），去问上游表自己：
   这类后缀**有没有被单独立行**？那些行**有没有对应数据**？实测——画法后缀确实会被单独立行，
   而那些行既无音频也无正文 ⇒ 上游本就没配，"剥后缀继承"= 把父条目的数据冒充成它的（不报错的语义错）。
   再配一条独立旁证（这批文件在产物里只有静态图、没有可交互模型；父条目本就挂着多份画法），三条一起才构成否证。
   **反例也记一条**：别把"某字段 = -1"读成"没有值"——实测 -1 是"本行未配置（继承）"，
   真按它判会把 140 条"缺数据（可等下发）"错标成"结构性无解"，等于自己造一条否证；判据要收到只认 `0`。

## 分支 C：占位 / 降级产物伪装成功（静默失败这一整类）

分支 A/B 都假设"产物有数据、只是数据可能错"。但有一类更隐蔽、破坏力更大的失败：**生成脚本在解析/提取失败时，悄悄写下一个结构完全合法、却没有任何有效载荷的占位（或降级）文件**。它能被加载、能通过"是否存在/是否启动"这类外壳检查，于是批量验证一路报绿，实际内容却全是空壳。真实案例：`reconstruct_live2d.py` 在 `extract_motions.py` 提取失败时写 `"Curves": []` 占位壳，而提取失败的根因是一个护栏 `num_keys > 100` 误杀了帧 0（帧 0 是 `time≈-3.4e38` 的参考姿态、一帧合法写全部曲线，大模型几百参数必越界）→ 整 clip 返回 `None` → 占位壳静默留存。磁盘实测 8154 条动作里 5037 条是空壳（61.8%），另 38.2% 曲线名按位置猜错，**真正正确的 0 条，潜伏一年多**。判"动画在播"若只看 `state.currentGroup` 变了（外壳），空壳也能启动，于是"能播但不动 / 乱飘 / 乱闪 / 没反应"全被漏过。本分支给四条硬规则。

### C1：解析失败绝不写占位/降级文件，必须显式报错并非零退出

生成脚本的失败路径**不允许**留下"能被加载但载荷为空"的文件。宁可让产物**缺失**（下游表现为 404 / 显式报错），也不要用占位结构把它伪装成数据。落地：
- 提取/解析返回空结果时，`raise` 或 `sys.exit(1)`（或累计 `bad_models` 后让 `main()` 返回非零码），**不写**该文件的占位版。
- 上游"补占位"的分支（如 reconstruct 写 `"Curves": []`）整段删除，改为一行提示"该文件应由 XX 提取脚本生成，缺失即显式失败"。
- 例外须显式声明：确属源数据本身为空（如游戏里就是空动画的 `effect` clip），要**单独记录为已核对的空**，而不是和静默失败混在同一个占位路径里。

### C2：写独立审计脚本，分类 shell / 错位 / ok；换入前后各跑一次当门禁

审计脚本必须**独立于被测生成逻辑**（自己判自己 = 自证循环）。它重新从权威源（如 bundle 的 `genericBindings`）推导每个产物"应当是什么"，把磁盘产物分类为 `shell`（载荷为空）/ `misassign`（载荷非空但映射/内容错）/ `ok`。用法铁律：**换入前对正式目录跑一次、换入后对正式目录再跑一次同一脚本**，两次都必须 `0 shell / 0 错位` 才算通过（本轮修复前 shell 61.8% + misassign 38.2% = 100% 坏，正是门禁数值）。审计脚本应带 env 输出目录开关（如 `L2D_OUT_DIR`），以便对临时目录先审再审正式目录。

### C3：验证判据落在载荷本身 + 独立不变式裁定，而非外壳状态、非自证

呼应顶部横切原则。动效类：`len(Curves) > 0` **且** 采样目标参数在两个时间点取值不同（真的在动）。裁判"新旧谁对"要引入**与被测数据独立**的不变式，而不是"和我的映射逻辑一致"——本轮用的是「同名参数的物理合理取值域」（`ParamEyeLOpen/ROpen` 恒 0..1、`ParamAngle*` ≈ ±30），旧版 23.1% 越域、新版 2.9%，从外部证明新对旧错；再叠加 `crc32` 绑定链跨模型 100% 可解析、91.7% 曲线索引严格升序（随机配对不可能产生）作旁证。

### C4：换入用 move/重命名，不用同名覆盖

第 6 步"复制备份 + 同名覆盖"在面对占位壳时有残留风险：半覆盖会新旧混血，且旧壳若被引用路径漏改会潜伏。改用**原子 move**：先把正式目录旧产物整体 `move`（重命名）进带日期/用途的备份目录，确认到达后再把临时目录新产物 `move` 进正式位置。换入后仍逐字节核对新位置==临时源；确认无误后备份目录再送回收站。move 天然避免"覆盖到一半失败留下混合态"，也让占位壳不可能因覆盖遗漏而残留。

## 分支 D：内部不变式全绿、观感仍错 → 外部权威基准逐字段比对

分支 A/B/C 的共同前提是**判据落在载荷本身 + 用与被测数据独立的不变式裁判**。这能可靠挡住"空壳 / 降级 / 映射错 / 字段变空"。但有一类失败它们全都挡不住——**载荷非空、结构合法、所有内部不变式一路绿灯，观感却仍然错**。因为错在**数值口径 / 单位 / 量级**，而这种错误"错得自洽"，内部证据看不见自己看不见。真实案例：`extract_motions.py` 把 motion3.json 的贝塞尔控制点写成**归一化分数**（`0.333 / by1 / 0.667 / by2`），而 Cubism 运行时解析器 `points[a]=new j(seg[l+1],seg[l+2])` 是**按绝对 (时间,值) 直读、不做任何反归一化**——于是控制点被当成"t=0.333 秒、值≈0.667"，落在段外且接近 0，每条贝塞尔先猛蹿到 0 再跳回目标 → 部件乱摆。可曲线数、时长、crc32 绑定映射、参数量程**全部命中 moc3、全部自洽、全部绿色**，自检完全看不见这个数量级错误。本轮在"呼吸层 / 插值降级护栏"上误判两轮，直到拿到第三方权威实现（l2d.su）对同一资产的导出做数值 diff，才一次锁定根因。本分支给三步流程 + 两条判据。

### D0：先确认"内部已全绿仍错"，才升级到外部取证

不是所有观感错都走 D。先跑遍分支 A/B/C 的内部判据（载荷非空、映射命中、量程不越界、关键帧 / 结构对齐）。任一项红 → 那是 A/B/C 的场景，不必引入外部源。**只有当内部判据全绿、观感仍系统性错、且怀疑指向"数值口径 / 单位 / 量级"这类自检天然看不见的维度时才升级**。核心命题：内部不变式只能证"结构对、非空、自洽"，证不了"取值口径对"；判数值对错必须引入**被测系统之外的权威实现**产出的同一资产做基准。

### D1：反查外部权威源的资源路径，抓到同资产的权威导出

优先找**独立实现了同一运行时 / 协议**的第三方（本例 l2d.su 也是 Live2D Cubism Web viewer，其 motion3.json 就是"正确答案"的近似）。定位其资源直链：

1. 抓目标站前端 SPA 主 bundle（`.../assets/index-*.js`），**grep 里面的路径模板字符串**（如 `'live2d/Z23/Z23.model3.json'`），反推出资源命名规律与 base 前缀（线索常散在别处，如页面里 `https://static.l2d.su//azurlane/squareicon/antu_2.webp` 暴露了 CDN 根）。
2. 拼出候选 URL，用 `curl -s -o /dev/null -w "%{http_code} %{size_download}"` **探活**，命中 200 再实拉；写循环批量探多个候选 key，**404 直接跳过**（404 常返回一段 HTML、体积易与真文件混淆，落地后先验 JSON 能否解析）。
3. 接受**覆盖是子集**（本例 14 个抽样 key 只命中 8 个）——外部源不要求全覆盖，够做抽样 oracle 即可。抓 `<KEY>.model3.json` + 若干 `motion/*.motion3.json` 落 `.diag/_ref/`。
4. 附带红利：读**被测运行时自己的解析器源码**（min.js 里 grep 段处理 / 求值函数），确认它到底怎么消费字段——这是判"格式对不对"的终极权威，比任何规范文档都硬。

### D2：按被测运行时的真实求值语义采样比对，而非逐 Segment / 逐字段比原始数组

拿到基准后**不要**拿两边的 Segment 原始数组逐项 diff——同一动作可以有多种合法表示（参考版 5% 贝塞尔 + 大量线性 / 阶梯，我们可能全贝塞尔），逐数组比会把表示差异判成海量假阳性。正确做法：**在稠密时间点上，用与运行时一致的求值公式分别解出被测产物与基准的曲线取值，再比解出来的数值**。

- 对每条同名曲线，按运行时语义把 Segments 展平成 (时间, 值) 关键点 + 段类型（线性 / 贝塞尔 / 阶梯），在密集采样时刻插值求出值，比被测 vs 基准的逐点偏差。
- 输出三项指标：**偏差中位数**（整体对不对）、**超阈值曲线数 / 占比**（有多少条错）、**最大偏差**（最坏多糟）。本例据此把三个候选一次判清：旧产出品均差 1.376、92/98 曲线偏 >0.5（判死）；绝对贝塞尔版中位 0 但 88/278 偏、最大 **296**（更差！）；**纯线性版中位 0、仅 11/278 偏、最大 1.95**（复现基准）——最终换入线性版。
- 跨 clip / 跨模型抽多个样本确认结论一致（本例四个 clip 线性版中位 0.07–0.20 vs 旧版 2.4–2.6），别拿单条曲线定生死。

### D3：用「结构完全正确时的真实残差」校准 WARN 阈值

比对必然有残差（表示法不同、基准自身也是近似），阈值不能拍脑袋。本例初版把 WARN 卡在 **5%** 太死——`touch_body` 9.6% 恰好落在"参考版贝塞尔占比 ~7% 的天花板"上，是**可达残差上限**而非 bug。校准方法：

- 拿"已知结构完全正确"的场景（基准自比 / 表示法最优版）测出**正常残差分布**，把 WARN 阈值定在这条实测可达上限**之上**；
- 阈值分档设红线（中位 = 0 才叫对齐；超阈值曲线占比、最大偏差各自单独设线）；
- 把校准依据写进工具 / 文档（"5% 太死，按 7% 贝塞尔天花板放宽"），下一位才知道阈值不是随手取的。

### 判据①：格式规范正确 ≠ 验收通过（以基准 diff 定胜负，不许规范自证）

"符合 Cubism 规范写法"只是**合规**，不是**验收**。本例绝对贝塞尔控制点写法完全符合规范、运行时也确实按绝对值读——但对权威基准的偏差最大 296，反而是候选里**最差**的那个；线性版谈不上"精确还原贝塞尔"，却最贴近基准。**两个都合规的导出谁对，只能靠外部基准 diff 判，不能靠"我符合规范"自证。** 差点按"规范里怎么写"换入更差的绝对贝塞尔版，是基准 diff 把它反转回线性版。推论：交接文档 / 重导命令里写的环境开关，必须与**实际换入并通过验收的那一版**一致（本轮交接初稿误写 `L2D_MOTION_ABSOLUTE_CP=1`，实换入的是线性版——照命令重跑会直接返工，发现后当场改正）。

### 判据②：交接文档必须列「已排除假设清单」

排查型任务写交接 / TROUBLESHOOTING 时，除"根因是什么"，**必须显式列出"哪些假设已被什么证据排除、排除依据是什么"**，否则下一位会把这些死路重新走一遍。本例已排除清单（每条带证据）：呼吸层只碰头部 5 参数、管不到小臂；字段布局 f1=入切线 / f2=出切线 / f4=值，与已导出 motion3 精确互推 → 取值自洽、非错位；98 条曲线全部落在合法量程内、不会被硬钳；`m_Enabled` 全 1、无"游戏禁用我们照驱"的参数；180 条 ConstantClip 里 179 条等于 moc3 默认值、丢弃几乎无损（不是根因）；"1.5 秒间隔的键不该拿 1/60 秒割线当导数"这类**判据本身写错**也要主动收回。清单让根因的说服力建立在"排除法"上，而不是又一次猜测。

### 换入仍沿用主线闸门

D2 选定"对基准偏差最小"的候选后，仍走分支 A 第 3–7 步 / 分支 C4：临时目录产出 → 对照组逐字节证零回退（本轮对照组 104/104 一致）→ 改前改后对比交用户确认 → move / 重命名换入 → 逐字节核对 → 派生重建。**外部基准只解决"选哪一版对"，不替代安全落地流程。**

## 分支 E：观感 / 尺寸类前端改动（无报错、无产物差异、无外部基准）→ 同机 A/B 对照页

分支 A–D 都能拿到"客观答案"：A 有像素 diff，B 有领域不变式，C 有载荷非空，D 有第三方权威基准。但有一类改动四条路全落空——**用户说"看起来太小 / 太挤 / 不对味"**。它不报错、产物字节没变（同一份资源，只是画得大或小）、也没有外部权威能告诉你"这个 viewer 该多大"。**唯一的出路是把观感换成一个可测的物理量，再造一个只随本次改动变化的对照组。**

### E0：先确认落在 E，再动手

三条都成立才用本分支：① 跑一遍不报错、产物结构不变（否则回 A/B/C）；② 差异只在"渲染出来的几何 / 尺寸 / 位置"；③ 没有权威基准可比（有就回 D）。核心命题：**"不报错"和"没崩"都不是观感的判据**，必须另找能红的数。

### E1：把主观反馈拆成可独立修的层

"打开就小"通常是**两层叠加**：外层容器尺寸（弹窗/画布的 CSS 上限）与内层内容取景（按什么包围盒适配）。混在一起谈会各修一半、两边都不够。**先分别量出两层的实际数字**（容器占屏比例、内容占容器比例），再决定各让多少。

### E2：对照页用 `git show HEAD:<正本>` 就地造，同一次运行里跑新旧两页

```
git show HEAD:gallery_src/index.html > Output/gallery_v2/index_old.html   # 跑完删（在 gitignore 目录里）
```
同一台服务器、同一份数据、同一次进程 → **排掉了模型加载时序与机器状态这两个混淆源**，比"上周截图 vs 现在截图"硬一个数量级。样本按固定步长从全库抽（`step=len//n`），并把 1~2 个基线样本钉到最前。

**同一张对照页还直接交给用户自己切着看**（"美化 / 观感"类尤其如此）：把样板挂在**同一个本地服务器的另一个文件名**上，让用户开两个标签来回切。这比任何截图都准——本轮据此被用户当场否掉一整版换色方案（"不如之前"），代价是零（正本一行未改）。**被否也要落记录**：截图与"别再走这条路"的原因写进状态文档的待办区，否则下一个会话会原样重做一遍。

### E3：判据用「绝对像素」，不用「占容器比例」

改容器尺寸会**同时改掉参照系本身**，于是占比是代理指标、会假报回退。实测：同一批样本按面积比给出 5/10 "变小"，按绝对像素则是 10/10 变大（x1.69~x3.89）。**用户看到的是像素，不是比例。**

### E4：动 `min(px, vw/vh)` 这类常量，交叉点两侧各测一档

"数值更大 = 更宽松"是错觉：把 `96vh` 写成 `94vh` 想让上限更松，结果在窗口高度不足（`innerHeight < ~917`）的机器上 `94vh` **小于**原来的 880px 硬上限 → 容器反而变矮，高度受限的那类内容直接回退。⇒ **必须同时在"小于像素上限"和"大于像素上限"两档窗口下各跑一次对照**（`--win 1600,1000` 与 `--win 2560,1600`）。本轮就是靠小窗口当场抓出这条自伤。

### E5：判据要能红——给每条断言配一条"它是空的"守卫

观感类断言极易写成永真式，两类必须显式挡：
- **恢复/记忆类**：先断言"操作确实改变了被测状态"（`|操作后 − 默认| > 阈值`），否则"重开 == 操作后 == 默认"三者相等也算过。
- **仿真/改尺寸类**：先断言"注入真的生效"（如 CDP `setDeviceMetricsOverride` 后基准宽必须真的变），否则"往返后偏移 0.000"只是压根没测到东西。

### E6：无头量"内容有多大"之前，先把背景刷成纯色

按阈值找"落笔像素"包围盒时，**装饰性背景（棋盘格、渐变、骨架屏灰）会整屏越过阈值**——实测 `#12172a` 的 max 通道 =42，任何合理阈值都挡不住，结果比例恒为 0.999（假数据，且看起来很像"成功"）。同时**基准框要按视图取**：带底部控制条的视图，条上的浅色字会被算成内容把高度顶满。

### E7：动效 / 交互反馈类改动——先证明"环境会出帧"，再证明"退化真的发生"

观感改动里最容易被放行的一类，因为它**结构上永远全绿**：动画没跑、类没摘、开关失灵，页面都不报错。
四条判据顺序不能换（每条都对应一次真实假红灯或假绿灯）：

1. **环境自证放在最前**：`document.visibilityState==='visible'`。前台但被切到后台的标签页**不出帧**，
   于是 CSS 动画冻结在起始关键帧（`getAnimations()` 返回一堆 `currentTime=0`）、`loading=lazy` 的图
   一张都不加载——"transform 不是 3D""图没淡入"全是假红灯。要么用会出帧的无头实例，要么别测。
2. **量位置一律用 `offsetLeft/offsetWidth`，不用 `getBoundingClientRect`**：祖先元素在播
   `scale()` 入场动画时 rect 被缩放（实测把 83px 的标签量成 9.97px，看起来像产品错了 8 倍）。
   `offset*` 是布局值、天然免疫 transform——**产品代码和探针要用同一套**，否则探针比的是两种东西。
3. **异步落值的判据要延后读**：`document.startViewTransition(cb)` 的回调在快照之后才执行，
   点击那一刻读 `dataset.theme`/localStorage 必然还是旧值。同一时刻只断言**同步写入**的东西（如 CSS 变量）。
4. **报错断言必须与改前页取差集**：第三方 vendor 自带的报错（本项目 `spine-all.js` 的 `THREE is not defined`）
   正本同样有。"页面有报错"不是判据，"比改前页多出报错"才是。

配套两条：

- **反向证据不可省**：`Emulation.setEmulatedMedia({features:[{name:'prefers-reduced-motion',value:'reduce'}]})`
  后必须重测一遍——动画类不再挂上、**靠 load 事件才显形的东西（如淡入的图）此时 `opacity` 必须是 1**、
  关闭路径仍能真关上。"加了动效"与"关动效时不瞎"是两次验收。
  ⚠️ 测完这条要**撤掉模拟**再做后续，否则后面所有走退化分支的路径都拿不到动画对象。
  **它真的抓到过 bug**：自续型 `requestAnimationFrame` 循环若不在函数开头判 kill switch，
  外部 `cancelAnimationFrame` 只取消当前排队的那一帧，队列里的回调会把自己重新接上 ⇒ 循环永不停
  （表现是"容器已经 `display:none` 了 rAF 还在跑"）。⇒ **任何自续循环必须在自身内部决定要不要续帧**，
  而这条只有"关掉之后再量一次它还在不在跑"才测得出来——反向证据判据不是形式主义。
- **"有没有效果"的门槛要按人眼校准，不按"非零"校准**：量到 9/255 的亮度差就判通过，
  用户肉眼会说"约等于 0"。先在最终显示介质上问"这个差值分得出来吗"，分不出来就把门槛
  抬到分得出来（本轮把鼠标扰动门槛定在 ≥6 亮度单位、且固定在最弱的那套主题下量）。
  亮度类判据同理要给**区间**（如 120~240）：只判"没削顶到 255"会放过"整体过曝"。
  读"底图"前先把指针停到角落，否则量到的是交互光斑本身。
- **判"画面里有没有内容"要看方差，不看均值**：纯白和纯黑都是均值极值、标准差 0，
  而人眼看到的"什么都没有"恰恰是这两种。加性光效（光柱 / 亮带 / bloom）在浅色主题下
  最容易整屏削顶到 1.0 —— 同一套参数在深色主题正常，所以**必须两套主题各读一次像素**。
- **主观观感词要翻译成结构量才判得动**："像海"= 横向特征比竖向宽（比较相邻列差与相邻行差，
  各向异性 ≥1.25）+ 上浅下深（顶段亮度减负段 ≥6，注意 `readPixels` 的 y=0 在底部）。
  翻成这样的数之后，"不像"就变成一条能红的断言，而不是再来三轮口味往返。
- **成本计时也要自带"它测的是不是真东西"的守卫**：`mousemove` 里"读矩形 → 写 CSS 变量"构成强制回流，
  1000+ 节点列表上会掉帧 ⇒ 矩形按元素缓存、滚动时作废。计时循环必须同时断言末次写入的变量非零、
  且**全场只有当前那张卡带角度**（换卡时上一张归零是设计的一部分），否则测的只是 `getBoundingClientRect` 空转。

补三条同类（都是"判据测了个代理指标"）：

- **`:focus` 类判据要先开焦点模拟**：无头实例没有真窗口焦点，`document.activeElement` 会设上、
  但 `:focus` **不匹配**，于是"聚焦变宽"恒假。正确做法 `Emulation.setFocusEmulationEnabled{enabled:true}`，
  且断言要看 `el.matches(':focus')`（真可观测量），**不要看 `activeElement`**（代理指标，它绿着而规则没命中时最坑）。
- **过渡/动画类判据的等待时长要按"够走完这条过渡"来定，不是随手 0.4s**：无头 ~8fps，
  280ms 的过渡在只出了 3 帧的窗口里可能一步没走，量到起始值。要么等满（≥1.2s），要么读**规范值**而不是用值。
- **量"有没有在动"要量时钟，不要量帧数**：给动画加一个 `clock += dt` 累加器，断言它在墙钟 0.5s 内
  落在 `(0.15, 0.55]`。帧数在无头里天然低（判帧率会把环境当缺陷）；而"快过真实时间"才是真 bug
  （dt 单位写成 ms 这类），下界则证明 dt 真接上了。

**判"高级不高级"之前先把参照物拆开读**：`curl` 拿 HTML/JS，grep `getContext(` / `uniform ` / 默认参数对象，十分钟就能确定参照是着色器还是 2D 画点 —— 层次不对时调参调三轮都不如换实现一次。
换成着色器后判据的参照系要跟着换三处：**① `draw` 与 `readPixels` 必须在同一次求值里**（`preserveDrawingBuffer:false` 下跨调用读到空缓冲，会误判"没画"）；**② GPU 成本只计提交会假便宜、每帧补同步读回会假贵**（软件光栅把读回全算进去），无头环境量不出真机帧预算就别声称量得出 —— 把这条判据降级成"只抓病态"并写明它是上限；**③ 动画时钟对帧时间线（rAF 时间戳差）判，不对墙钟判**，否则无头里"时钟比墙钟慢"会被当成缺陷。

**背景层这一类的专属判据**（加装饰性背景最容易犯的错是"画了但没人看得见"）：
`pointer-events:none` + `z-index` 低于内容只是及格线；**必须量"露出来的面积"**——卡片/面板是不透明的，
铺满视口的背景 95% 被盖住，截图上和没加一模一样。要么给滚动容器留一条不滚动的空带
（`margin-bottom`，不是 `padding-bottom`——后者只在滚到底时露出来），要么把某块 chrome 改半透明
（`color-mix(... transparent)` + `backdrop-filter`）。验收就是**同视角拍"开/关"两张图自己看差别**，
差别看不出来 = 这条功能没上线。

## 分支 F：把整条管线编成「一键跑」的编排器时

前面几条分支都在讲"一次改动怎么安全落地"。当你要把十几个脚本串成一个阶段机
（让下次游戏更新不必人肉照 runbook 敲命令），会撞上**另一类**失效——编排器本身很容易
变成一台"自动生产假绿灯"的机器。三条硬约束：

1. **绝不拿子进程退出码当通过证据。** 先做一张接口表：哪些被调脚本**失败时照样 exit 0**
   （打印了 `Failed: N` / `err=3` / `✗ xxx` 却不反映到退出码）。这类脚本在真实项目里往往是
   多数。每个阶段因此必须自带 `judge()`：数汇总行（`完成N 跳过N 失败N`）、要求收尾行
   （`[SUMMARY] i/n`）、或直接跑该产物已有的 gate 脚本。**没有判据的阶段标"未证"，不许算通过。**
2. **区分三档写权限，并把不可逆的那档设成默认关。** `read`（只读检查）/ `staged`（只写临时区）/
   `live`（写正式目录）。`live` 必须**逐个点名放行**（`--approve deps meta`），未放行时该阶段
   仍应跑完它的**只读那半**（重生成到临时区、算出与现状的差异、报告"丢了几个/多了几个"）再停下——
   这样"不签字"不等于"不知道会发生什么"。一键全自动覆写一切 = 把项目里"全量运行前必须确认"
   这条约定直接删掉。
3. **缓存策略是安全属性，不是性能属性。** 只缓存**判绿的 staged 档**；
   `read` 档（preflight / 一致性检查）**永不缓存**，失败**绝不写入完成态**。
   否则第一次跑红、第二次直接跳过 = 一条从此不再复查的流水线。缓存键必须是**输入指纹**
   （源文件数 + 关键中间产物的哈希），不是时间戳；指纹变了自动全部作废。
4. **"没有范围"和"整个范围"必须是两个不同的值。** 一条最常见的暗坑：范围清单读不到时
   `return None`，而下游 `if todo is None: 跑全部` —— 一个哨兵值同时表示两种**失效方向相反**
   的语义，于是"默认增量"在清单从没生成过的那天上悄悄变成"默认全量覆写"。
   做法：定一个四态返回（`full / ok / missing / stale`），`missing`、`stale` 一律**判红停下**，
   并把"要全量请显式 `--full`"写进结论；计划输出（`--plan`）也要说实话，别印"增量：尚未 detect"。
   同理：**写清单和写它的指纹戳必须是一个函数**（两份文件分开写，迟早只写成一份）。
5. **凡是"签名里收了权限参数"的函数，都要配一条反向可观测判据。** `def st_x(approved)` 却
   一行都没检查 `approved`，肉眼 review 和界面文案都发现不了（界面上还写着"未签字只跑读半边"）。
   闸门测试**不看文案看行动**：把"跑子进程"那个函数替换成记录器，断言
   ① 未签字时**没有 spawn 那个会写正式区的子进程**；② **签了字它必须真的 spawn**（否则门是焊死的）；
   ③ 结论里保留前端用来认状态的那个标记串。三件事一次测完。
6. **要给前台看进度，就不能用 `capture_output=True`。** 它不是缓冲，是**必须等子进程结束**才返回，
   于是 43 分钟的长阶段期间编排器自己的 stdout 一个字都没有，界面看着就是死掉（`PYTHONUNBUFFERED` 救不了）。
   改成两条流各一条读者线程 + 逐行转发（命中关键词必转、其余按秒限速并计"抑制 N 行"），
   全文照旧拼起来返回给判据。超时同理：`subprocess.run(timeout=)` 只杀直接子进程，
   起浏览器/浏览器的脚本会漏整棵树 ⇒ 自己 `taskkill /T /F` 后再抛超时让阶段判红。
7. **资源与耗时的问题要用工具回答，不要用感觉回答。** "跑一次要多少 G"这种数会直接决定用户
   敢不敢同时开别的程序：按**进程树**采峰值 WorkingSet（快照枚举子进程 + `GetProcessMemoryInfo`），
   并且**先拿一个已知分配量自测准头**（比如故意占住 400MB）再采信它。实测常和文档里的老数字
   差一个数量级（本项目全量立绘从"数十小时"变成 1.5 小时），旧数字留在 runbook 里会继续误导调度决策。
8. **测"按盘上事实裁判"的映射逻辑，样本必须取自盘上真名。** 两个方向都会栽：
   ① 用编造的名字当 fixture，被正确的存在性过滤器滤掉 ⇒ 假红，你会去"修"没坏的代码；
   ② 反过来，"这算不算一个真产物"若只靠**后缀表**判断，一定会被带编号的变体绕过
   （后缀写 `_bj`，真名字是 `_bj1`）⇒ 下游按不存在的包去渲染报错、整条线判红停住。
   ⇒ 后缀只当预筛，最终裁判落在**磁盘上有没有那个本体**。
9. **"零结果"是合法状态，不是错误；而且修它时最容易二次伤害。** 编排器里 `新增 0 / 变更 0 /
   命中 0` 这类结论必须有自己的分支（判绿 + 写明"本轮无事可做"），不能落进"读不到东西"那条
   判红路径——用户刚做完一次真更新，再点一次检查就必然撞上 0。
   ⚠️ 更要紧的是：**别在"零结果"分支里顺手写空产物**。上一轮的有效清单会被冲成 0 条，
   于是"无事可做"和"范围丢了"在盘上长得一模一样，下一次整条线静默空转。
   正确顺序是：先看有没有**当前指纹下的有效清单**可沿用，没有才写空。
   配套判据两条：结论判绿 + **清单内容一字未改**。
   ⚠️ 这条的"有效清单"如果按**整条输入指纹**判新鲜度，会漏掉一种真实组合：
   `零结果 + 旧清单已被判过期` —— 两者一叠加，写空就会把非空清单冲掉（本项目 2026-10-01
   真把 1154 条范围清单冲成 0 条，且 `.diag/` 在 gitignore 里**没有 git 兜底**）。
   ⇒ 兜底要写在**写盘函数**里而不是调用方：新清单为空而旧清单非空 ⇒ 原样保住旧的、只重盖戳；
   两边都非空且不同 ⇒ 先备份成 `*.prev.txt` 再写。别指望每个调用分支都记得判断。
10. **"一律判红"的保守闸门会在第一次真跑时被上游自己的正常变更卡死。** 例：要求新依赖表是旧表超集、
    少一条就拒——可游戏自己就会删条目（本项目是 4 个 `iconframe` 项），于是一道保护我们的闸门
    变成每次版本更新都要人工放行一次无关噪声。⇒ 把闸门按**它到底保护什么**分级：
    只对本管线**消费的域**判红，其余丢失**打出来但不拦**，并给"只丢非消费项不得算 fatal"配一条
    阴性对照判据。收紧判据 ≠ 放宽闸门：前者是让红得更准。
11. **凡是"第一次跑必然没有数据"的显示量，要有兜底来源并标注来源。** ETA 只认历史均值 ⇒
    全新阶段（本项目 13 个里 9 个从没真跑过）永远显示"未知"，用户读到的是"卡住了"。
    兜底按可信度排：历史均值 > 实测速率 × 本次项数 > 实测固定常量 > 未知；
    **只填量过的数**，没量过的计入 missing 并让界面只报下限（`≥`）而不是假装精确。
    同理，日志侧每一步把"本次要处理多少项 / 预计多久 / 实际用了多久"打出来，
    界面和日志两处能互相对账。
12. **写进文档与界面的每个数字都要带来源。** 本项目真实事故：把另一条目里"全库重扫 43 分钟"
    安到了某个阶段头上，据此告诉用户"一轮增量 1 小时出头、这一步是地板"——实测该阶段 **3 秒**。
    错数字的代价不是难看，是用户据此决定"现在跑不跑、能不能同时开别的程序"。
13. **新鲜度判据只能看它保护的那个量。** 输入指纹常常是"源包数 + 若干派生产物哈希"拼出来的，
    拿整条去判一份**描述源包变化**的清单是否有效，等于规定「同步 → 换入派生表 → 跑导出」
    这条唯一正确的顺序必然自我作废（换入那一刻哈希就变了）。表现不是报错，是**下游集体
    "无事可做"并判绿**——最难发现的那类静默失效。⇒ 把指纹拆成具名分量（`bundles=` / `deps=`），
    每份产物只比它真正依赖的那几段；并给"正常顺序走完清单仍有效"配一条判据。
14. **结论缓存的"新鲜度章"必须覆盖它依赖的**每一个**输入维度。** 只盖"输入指纹"一枚章不够：
    清单/范围/配置这类**派生的决策输入**变了，上一批记的"已完成/无事可做"就不再是这轮的结论。
    本项目连吃三层（§75）：界面只看本步就宣布完成 → `verdict` 少一枚范围章 →
    **跳过缓存 `done` 也少一枚**（这层最疼：它不是骗界面，是真的会少跑一批产物）。
    ⇒ 每写一处"上次结论/已完成"的缓存，先问它依赖哪些维度，逐个盖章；并且
    **没盖章的旧条目一律不算这轮的**——失效方向必须是"多跑一次"，绝不能是"少跑一次"。
    配套判据要**成对**：一条断"不许宣布完成"，另一条断"必须报出差在哪几项"——
    只写前一条，实现会退化成一个含糊的"还没完"就交差（含糊不等于诚实）。
15. **"界面上有开关"不等于"开关接在线路上"。** 授权类控件（复选框/开关/确认框）必须有
    一条判据直接看**发出去的请求体**：勾上它 → 触发主按钮 → 断请求里带上对应的字段。
    本项目真实事故：卡片上的"签字放行"只有那颗"单独跑"会读，主按钮发的 `approve` 永远是空的，
    用户勾完照旧被当成没签字，来回三次。同类：状态别只存在 DOM 上（重绘即丢），
    要有一个集合当唯一真源，并在主屏把"当前已授权什么"**显示出来**——勾是瞬时的，写盘不可逆。
    ⚠️ 写这类判据时桩必须**只截不发**：转发一次就等于在验收里真跑一次不可逆写入。
16. **可迁移性收口成"一个出口 + 一个闸门"，闸门分档才拦得住。** 把散落在十几个脚本里的绝对路径
    收进单一模块（根目录由 `__file__` 推导、环境变量可整体覆盖、**推导不出就抛错**——留一个"猜的
    默认值"比报错危险，它会把资产写进别人的目录），然后必须配一个漂移探测器扫"还有谁写死了"。
    ⚠️ 探测器**必须分档**：调用链上算硬失败、一次性脚本只报数（`--strict` 才一起算红）。
    一次扫出 46 个全判红的闸门当天就会被绕过；分档之后它是绿的、拦得住新增的写死路径，
    还把欠账数量摆在明面上。本项目这条当场抓出改漏的 3 处（都是"改了同文件的其他行、漏了这行"）。
17. **"部分比对"不得冒充"完整范围"。** 给同步工具加类型过滤（只拉 painting/cue）时，
    过滤后的 diff 与全量 diff 产出的"0 差异"含义完全不同：前者会让下游读成"别处都没变"，
    是一类静默少跑。⇒ 让"写范围清单"这个出口与"带过滤"**硬互斥**（直接退出码 2，不是警告），
    并在输出里明写这是部分比对。
18. **"清磁盘省地方"这种删除，必须先把"删了以后 diff 怎么看"设计出来。** 目录树比对型工具
    （路径+大小）一旦文件被删，会把它们全报成"新增"⇒ 白下一遍。正解不是"别删"，而是
    把删除变成**有记录的归档**：删之前留一份"路径→删除时大小"，比对时把"归档过且设备上
    大小没变"的从新增里摘出来单独报数；**设备上大小变了的照旧算新版本**（不许被台账吞掉）；
    没有台账时一律不吞。台账本身要能导出/导入（换设备、重装系统的迁移单元），
    且 schema 对不上就拒绝合并、不猜格式。
19. **"已还原/可删"的判据必须包含"依据此刻还对得上"。** 只看"产物存在"是不够的：
    产物可能是上一版源包生成的，删掉当前源包就再也复现不了。⇒ 记溯源时要连源包**大小+哈希**
    一起记，判定时回读盘上现状核对，并**把"大小变了"和"哈希变了"分成两条原因**
    （人才知道该去查什么）。记录点选在"产物刚进正式区的那一刻"，不是渲染完那一刻。
20. **枚举型扫描必须自己验"记全了"。** 建台账时只扫第一层 ⇒ 嵌套目录整批漏记；
    只遍历子目录 ⇒ 根目录下的散文件一个都不记（本项目真实有 41 个无后缀源包直接放在包根下）。
    两类漏记都不报错，只会让"差额"以后变成误判。⇒ 拿一条独立口径（全盘 `os.walk` 计数）
    对账，并把"嵌套的"和"根下散着的"各写进判据。
21. **增量比对必须显式分三类，"目标侧不存在"要算进要换的集合。** 只写"不同 / 其他"两类，
    实现里几乎必然长成 `if 目标侧存在 and 哈希不同` —— 于是**全新产物被排除在换入清单之外**：
    每一档都绿（各自检查的都没错），但新内容永远落不了地，用户只会问"我怎么知道新增了什么"。
    ⇒ 三档各自计数并各自落盘（新增 / 内容有变 / 逐字节相同），换入清单 = 前两者之并集；
    对照表也要能画"没有改前"的那种行（画一块明确的占位，而不是跳过——它恰恰最需要人看）。
22. **验收类阶段的结果永不缓存——缓存章覆盖不了"它验的东西后来变了"。** 换入正式区之后，
    输入指纹与范围清单可能**一个字都没变**，变的正是那批验收要查的产物；此时若命中缓存，
    界面报的是上一轮的绿（本项目实测：swap-in 换入 12 张后 regress 直接 ⏭ 跳过）。
    ⇒ 阶段分"生产/验收"两种属性，验收属性一律不缓存（代价通常只是几分钟）。
    同族第二层：**换入/覆盖类工具要能处理"目标侧不存在"**——对每个名字无条件 stat 目标文件，
    第一次换入新资产就会抛异常；新增项没有旧文件可备份、也没有硬链风险，要单列并报出来。
23. **一次请求里别把贵操作算 N 遍。** 面板一次 `/api/state` 里各自调了 4~6 次"walk 9 万个文件"
    的指纹计算，冷缓存那一拍 5.8 秒 ⇒ 前端轮询超时，用户读到的是"进度卡住"。
    ⇒ 入口算一次、往下当参数传（`fp=`），并把这条做成可量判据（同一拍耗时）。实测 5.8s → 1.6s。
24. **"缺口 = 0" 必须按解析来源分档，软回退单列。** 覆盖率/缺口类审计的"可解析"桶常常是三档
    合成：精确命中权威表（`row`）→ 剥已承认的画法后缀再命中（`strip`）→ **同船/同族回退**
    （`sibling`，包内关键序号 `idx` 定不下来）。第三档被算进"可解析"、不进缺口清单 ⇒
    对用户就能说出"本轮新增零缺口"这种**由回退机制给的绿灯**。⇒ 报数必须同时给三档计数，
    **新增样本要逐名回查它落在哪一档**；"它没出现在缺口清单里"不构成证据。
    （真实案例：12 张新皮肤 10 张走 `sibling`——本地元数据快照里根本没有这几行，
    誓约皮肤 `_h` 与三套新皮肤都是新内容，快照滞后。）
    顺带一条**什么才算真绿**：双向计数（表里有磁盘没有 / 磁盘有表里没引用）同时为 0，那个 0 才有意义；
    只有单向 0 的，先怀疑它是分档合成出来的。
25. **改了权威源之后，之前跑过的"派生产物重建"档必须重跑——判据是比时间戳 + 逐字段看回落值。**
    时间线上 `derive`(22:48) 早于 `meta` 换入(23:13)，两档的缓存章都"新鲜"（同一枚指纹、同一枚
    范围章），编排器不会提醒；但产物里那批新行的 `label` 还是回落值（`h`、`皮肤9（无背景版）`）。
    ⇒ 收尾时把"本轮换入过的权威源"与"依赖它的派生档"列成先后表，凡派生档时间戳早于权威源换入
    时间的，显式记成欠账并说给用户——别让它藏在"13/13 全绿"里。
26. **判"两个近似名字是重复还是两张不同资产"，必须在原生分辨率上比，不能在缩略图上判。**
    尺寸相同就先算逐像素差占比、alpha 通道单独比、再框出高差异区 bbox
    （实测 8.86% 像素不同 / alpha 仅 0.57% ⇒ 人物层一致、背景层不同 = 两张不同资产，不是重复文件）。
    ⚠️ 反面：620px 高的并排缩略图上"像压了一条矩形暗色遮罩"，裁到原生分辨率那东西并不存在——
    **在缩略图上判合成缺陷会产出假红灯**，白查一轮。
27. **切换权威数据源时，闸门必须能区分"有据升级"与"回退"，而这条判据本身要能被反向测到。**
    真实序列：把社区快照升级成"设备侧解出的权威表"之后，零回退闸门第一次跑必红——它只写了
    "受保护字段改动须为 0"，而这次改动**恰恰是合法的**（表里新增了两行，`base_painting` 从远亲变本名）。
    ⇒ 三条做法：① 判据写成**方向性 + 可回查**的形式（"新值必须是权威表里真实存在的一行、且比旧值更贴近本名"），
       不要开例外名单、也不要往白名单里加个转换就完事；② 判据若是写在函数里的嵌套闭包，**提到模块级**，
       否则没法喂反向样本，"正向跑一遍全绿"对一条放行类判据等于零证据；③ 配一个对照测试，
       正反各几条（本项目 8 例：远→近=True，近→远 / 表里查无此行 / 不是前缀 / 旧值为空 / 新旧相同=False）。
    同族坑：闸门用 `importlib.util.spec_from_file_location` + `exec_module` 加载被测脚本时，
    `sys.path[0]` **不是**那个脚本所在的目录（只有 `python scripts/x.py` 才是），
    于是它新引入的兄弟模块导入直接 `ModuleNotFoundError` —— 报错点在闸门里，症状却像被测脚本坏了。
28. **"权威表里没有这一行"有三种成因，必须各自配一条独立证据再下结论。**
    本轮真实三例：① **快照滞后**（社区 azdata 缺 `aierdeliqi_9`/`mile_3`，设备侧有）⇒ 换源可修；
    ② **游戏提前下发、尚未开放**（信浓/尾张/斯库拉的誓约皮肤、英格拉罕第 3 套：立绘包在盘上，
       但**全部**已解出的配置表里都查不到，且客户端已在主界面、无下载任务、配置目录时间戳就是旧的）
       ⇒ 没有台词/没有皮肤名是**正确状态**，硬接就是派错人；
    ③ **我们自己漏抽**（本轮没有，但必须先排除掉才允许说"是 ②"）。
    ⚠️ 排除 ③ 时别用裸 `grep` 搜加密表——串是按位取反编码的，恒 0 命中不构成任何证据，必须走解析器。
    另：一条已知缺陷重新定量之前不要动手。本轮"改造皮肤剥后缀接错语音"上轮估 2 张，
    用**被测函数自己的输出**（`resolve()` 的 `src` 字段）复算实际是 55 张（37 张该改判、18 张该显式静音）——
    差 27 倍；而第一版复算脚本因为"重新推导了一遍解析逻辑"（还踩了 `(a|b)+` 的 `findall` 只返回最后一次重复）
    报的是 1 张。**量影响面必须调用被测函数，不要照抄它的逻辑。**

    尺寸相同就先算逐像素差占比、alpha 通道单独比、再框出高差异区 bbox
    （实测 8.86% 像素不同 / alpha 仅 0.57% ⇒ 人物层一致、背景层不同 = 两张不同资产，不是重复文件）。
    ⚠️ 反面：620px 高的并排缩略图上"像压了一条矩形暗色遮罩"，裁到原生分辨率那东西并不存在——
    **在缩略图上判合成缺陷会产出假红灯**，白查一轮。


配套两条：
- **覆写一批产物之前先扫 `st_nlink`**。这批文件若历史上做过逐字节去重，共享 inode 的两个名字
  "写一个变两个"，会让修复看起来完全失效（详见 `windows-hardlink-dedup-verify`）。
- **只有 env 通道能改输出目录的脚本，必须把注入值回读打印出来。** env 在脱离宿主进程下
  能否被子进程读到**不可复现**，这是原地覆写事故的根因；编排器要么给它加 argv，要么显式记录。

29. **切换权威源时，先枚举"这张表有几个读点"，全部接进同一个口再换入。** 同一份上游数据常被
    三四处各自 `json.load`（本项目：元数据生成器、语音解析器、画廊索引生成器各读一份快照）。
    只接两个就换入，第三个会继续读旧快照 —— 而它的产物看起来完全正常，只是**永远少那几行**，
    属于最难发现的那类漂移。⇒ 动手前 `grep -rn "<表文件名>" scripts/ tools/` 列全读点，
    换入后**逐读点比对产物**（本轮正是接完第三个读点，画廊索引才多出 2 处变体包语音；
    前两个读点接上时产物差异是 0，只跑它们会误判"换源没有效果"）。
    另：这类"有没有效果"的判据要落在**产物字段**上（条目数、逐字段 diff），不是"脚本退出码 0"。

30. **分类/回退类规则：统计字段要相对最初输入判定，合成 fixture 要每条规则有唯一落点。**
    本轮两个自己造的假成果：
    ① `resolve()` 里 `src`（命中方式）按**内层候选名**判定，于是"从 `_alter` 回退到本体"把自己标成
       `row` ⇒ 报出"43 个钉到自有行"，其中 6 个数值根本没变。**数值对、分类字段错**时，
       整份结论仍然错，而且最难发现（人只看计数）。⇒ 这类字段一律把"原始输入"显式传进去比较
       （`pick(name, orig)`），并额外断言一次"标签变了但数值没变"的数量应为 0。
    ② 反向对照测试的合成名写成 `_alt`（规则要的是 `_alter`）、`hei_nopack`（规则要的是以 `_hei` 结尾），
       于是那两条测的是"查无此名 ⇒ 无解"，**方向恰好相反才暴露**；另外"允许回退"那条没把回退目标行
       放进 fixture，期望值自然对不上。⇒ 写合成用例时先问：**这条规则不成立时结果会不一样吗？**
       一样的话它就是在白测；"允许"类规则必须配一条"应当拒绝"的孪生用例，且两者期望值必须不同。
31. **改完规则必须核对"错数据有没有被撤回"，并且闸门里"无从判定"要单独一档。**
    ① 缓存型/合并型产物（`old.update(new)` 这种）会让**改对的规则完全不生效**：本轮解析器已把
       12 个皮肤判成"无解"，映射文件里它们仍以 `src=strip` 挂着别人的包，画廊照样能播——
       只看"新数据写进去没有"会以为成功。⇒ 撤回范围要精确限定为
       **"本轮看过的键" ∩（算不出归属 ∪ 归属值已变）**，其余保守留着（否则增量跑会抹掉没看的部分）；
       验收看**条目净变化是否等于预期撤回数**（本轮 4152→4140，正好 −12）。
    ② 零回退闸门常见的两种错法：把 `空→有`（补全）算成回退 = **假红灯**；
       把"旧值无从判定"直接落进"判红"或"放行"= 分别等于**把不知道当证明**和**把不知道当安全**。
       ⇒ 三条：判据按方向写（只有"有→空"算回退）；"无从判定"独立一档；
       这一档必须挂一个**替代证据**才允许降级为"需人看"（本轮要求"撤掉语音后仍有台词"），
       拿不到替代证据仍然判红。
    ③ 同族：判"这条数据是不是它自己的"时，粒度要和语义一致——按"船"算会把
       同船另一实体（黑化版）的包误判成"它自己的"，应按**发声实体那一行**算。

**编排器自身的验收**：`--plan` 能列全阶段与档位；只读阶段在**没有任何上游产物**时也必须优雅
判绿而不是抛异常（第一版常栽在变量只在某个 if 分支里赋值）；给一个 2 行的子集清单跑一个
staged 阶段，断言正式目录一字未动；再跑一次断言命中缓存，加 `--force` 断言真的重跑。

## Pitfalls

- **禁止盲目全量重跑**：即使"感觉都可能受影响"，也先做第 1 步扫描拿数据说话；扫描比全量重跑便宜几个数量级。
- 扫描阶段误用完整解码路径（读纹理像素、初始化渲染器）会把"秒级扫描"变成"小时级"——只要元数据。
- 豁免未经像素级/no-op 证明就跳过重跑，是本流程最常见的漏改来源；存疑就放进对照组或受影响集。
- 临时目录名与正式目录混用会直接覆盖产物；第 3 步开始前用一行断言检查输出路径前缀。
- 换入前忘记备份；第 4 步 maxdiff=0 未达成就硬换入；忘记重建派生缩略图导致 gallery 里新旧不一致——这三件事各自都有真实翻车案例。
- 受影响清单落盘后要用 `cut`/循环直接消费，避免手抄名单漏项。
- **元数据场景不能靠"看着像修正"**：没有逐像素可比时，必须用独立于被测数据源的领域不变式（拼音、占位符、归属规则）裁判每个 `changed`，否则把回退当修正放行。
- **"新数据源不一定更准"**：切主源前默认"权威表 > 旧映射"是错的；先跑一次字段级 diff 摸清 lost/changed/gained 结构，再决定字段优先级（见 B5），别先入为主。
- **预期结构变化必须显式声明**：拆分 / 合并 / 新增类别（如 META 独立卡 +54）不写进豁免清单，就会在 diff 里和意外回退混淆。
- **不变式覆盖不到的字段不能默认放行**：用户拒绝逐条审阅时，边界外的字段要暴露给人工抽样，而不是藏进"通过"。
- **人工复核清单里图片别用 `file://` 绝对路径**：Markdown 预览器/浏览器的安全策略会拦截本地 file:// 图片、全部显示"加载失败"；`.md` 放项目根目录用 `Output/...` 相对路径即可（见 B3-H）。
- **勾选框别写成纯文本方括号**：`- 自机? []` 在支持 GFM 的预览器里不渲染成可点击控件；必须用任务列表语法 `- [ ] 文字`（短横线+空格+`[ ]`+空格+文字），用户勾完才能变成 `- [x]` 供提取（见 B3-H）。
- **shell 反引号 / `$` 会污染文档追加与内联 PS**：写 markdown（含反引号）、跑带变量的 PowerShell 时，用 Write 工具落脚本文件再执行，别 `echo ... >> file` 或内联拼接。
- **占位/降级文件伪装成功**：解析失败时写结构合法的空壳（如 `"Curves": []`），下游能加载、能"启动"，批量验证全绿却内容全空——潜伏期可达数月甚至一年以上。失败必须显式报错并非零退出，产物宁可缺失也不要伪装（见 C1）。
- **验证判据看外壳状态而非载荷**：用"是否被加载 / `currentGroup` 是否变 / 记录是否存在"判通过，是这类静默失败的帮凶。判据必须落在载荷本身（非空 + 真的生效），见顶部横切原则与 C3。
- **提取护栏在批量下静默毁掉整批**：诸如 `num_keys > 100` 之类"防越界"护栏，会在正常大输入（如参考姿态帧 0 一次写全部曲线）上误杀 → 返回空 → 触发占位壳。改/加任何护栏后，必须先小规模跑真实分布、并以独立审计脚本证 shell 率为 0，别只测单个小样本。
- **审计脚本自己判自己 = 自证循环**：验证逻辑若复用被测脚本的映射/解析口径，错也错得一致、必然全绿。审计须从独立权威源重建期望值（见 C2/C3）。
- **内部不变式全绿 ≠ 数值正确**：单位 / 量级类错误（贝塞尔控制点写成归一化分数、运行时按绝对 (时间,值) 直读）"错得自洽"，曲线数 / 时长 / 映射 / 量程能同时全绿。这类错内部证据挡不住，唯一解法是抓第三方权威实现对同一资产做外部基准比对（见分支 D）。
- **别拿"符合规范格式"当验收标准**：规范自证不算数，合规的两个导出可能一个比另一个差一个数量级（本例绝对贝塞尔版偏差 296 > 线性版 1.95）。谁对以外部基准 diff 定，不以规范定（见分支 D 判据①）。
- **比对别拿 Segment / 字段原始数组逐项 diff**：同一动作有多种合法表示（全贝塞尔 vs 大部分线性），逐数组比会把表示差异判成海量假阳性。必须按被测运行时的真实求值语义在稠密时间点上采样后再比值（见 D2）。
- **WARN 阈值别拍脑袋**：5% 卡太死会把"表示法天花板"（如 7% 贝塞尔导致的 9.6% 正常残差）误判成回退。用"结构完全正确时的真实残差"校准阈值、并把校准依据写进工具（见 D3）。
- **交接文档只写根因、不列已排除假设 = 逼下一位重走弯路**：排查型交接必须附"哪些假设已被何证据排除"清单；同时重导命令 / 环境开关要和实际换入并通过验收的那版一致，别写候选里更差的一版（见分支 D 判据①②）。
- **跨层照搬修法前先验本层前提**（真实返工）：同一类缺陷常在"消费层"（浏览器 viewer）与"生产层"（批量导出脚本）各有一份实现，看到消费层修好了就把同一段代码抄到生产层，**默认了两层取的是同一份数据语义**。本例 viewer 侧补 `setSkin` 就恢复了缺失部件，导出侧抄同一段却**零效果**——因为 viewer 播动画（附件经 skin 解析），导出渲染 setup pose（附件取自 `slotData.attachmentName`，与 skin 无关）。⇒ **动手前先在目标层做一次"改完会不会生效"的最小验证（数一下受影响元素改前改后的数量）**，别拿"另一层有效"当本层有效的证据；无效就去找本层真正缺的那一步（本例是补"应用动画第 0 帧"）。
- **语义类开关：默认关闭，且"全量或不动"**：改的是"产物按什么语义生成"（setup pose vs 动画帧、单位、坐标系、是否叠加某层）时，新语义做成**默认关闭**的开关，保证未确认前默认路径逐字节走原代码。要换就**全量重导**——只重导受影响子集，会在同一批产物里留下两种语义，比原来的统一错误更难排查。判据：重导前备份全量并**逐文件 md5 证备份与原件全等**，重导后报"变化 N / 总数 M"，**未变的那几个必须能被解释**（本例未变的 2 张正是已知加载失败的那 2 个资源，属于预期；解释不通就是漏跑）。

- **观感类改动拿"跑一遍没报错"当验收**：不报错只证明没崩，证明不了尺寸/位置对。必须走分支 E 造对照组与可测物理量。
- **改容器尺寸时拿占比当判据**：参照系自己被改掉了，占比会假报回退（实测 5/10 假阳性）。用绝对像素（见 E3）。
- **`min(px, vw/vh)` 只按"目标大屏"验证**：会漏掉小窗口那一侧的自伤（`94vh` 在矮窗口里小于原 880px 上限）。两档窗口各测一次（见 E4）。
- **无头测量忘了中和装饰性背景**：棋盘格/渐变会让"落笔像素"阈值整屏命中，产出看着正常的假数据（比例恒 0.999）。先刷成纯色再量（见 E6）。

## Verification

- 第 1 步：扫描 errors=0，受影响数与后续分类总和一致（481 名义 → 540 行 no-op 分类 + 10 重渲，能对上账）。
- 第 4 步：全部对照样本 maxdiff=0。
- 第 6 步：备份目录计数==换入计数；换入文件与临时目录源哈希一致。
- 第 7 步：增量生成器报告"补建 N 项"且 N==受影响项数；`git status` 干净、提交信息含修复描述与数量。
- 分支 B - B2：`lost == 0`（红线）；`changed` 全部命中修正清单；`gained` 数量 == 声明的预期结构变化数（如 META 56）。
- 分支 B - B3：占位符命中数 == 0；对"修正"类 changed，拼音一致率 == 100%；无"非空字段变空"；不变式未覆盖的字段已列明并交人工抽样，未默认放行。
- 分支 B - B3-H：复核清单内图片引用全为相对路径（`grep 'file://'` 命中数 == 0）；勾选框全为 GFM 任务列表 `- [ ] ` 语法（无 `- xxx []` 纯文本形式）；清单含文件开头勾选规则说明；用户勾完后 `grep '\[x\]'` 行数 == 落入白名单的条目数。
- 分支 B - B6：正式目录新 index 与已验证临时版 `cmp` 逐字节一致；脚手架旧基线脚本已清除、不入库。
- 分支 C - C1：制造一次解析失败路径（喂空/越界输入），断言脚本以非零码退出、且该产物**未生成占位文件**（宁可缺失）；确属源空的条目单独记录、不与静默失败混淆。
- 分支 C - C2：换入前、换入后各对正式目录跑**同一**独立审计脚本，两次都 `shell == 0 且 misassign == 0`；审计期望值来自独立权威源，不复用被测生成逻辑。
- 分支 C - C3：动效类抽样证明判据落在载荷上——`len(Curves) > 0` 且同一目标参数在两个时间点取值不同；并用独立不变式（如物理合理取值域越界率）给出新旧谁对的外部证据。
- 分支 C - C4：换入用 move（旧产物 move 到备份、确认到达后新产物 move 进来），换入后逐字节核对新位置==临时源；备份目录确认无误后再送回收站。
- 分支 D - D0：确认内部不变式（载荷非空 / 映射命中 / 量程不越界 / 结构对齐）已全部通过后才升级到外部基准；任一项红则交回 A/B/C，不引入外部源。
- 分支 D - D1：至少抓到 1 个外部权威源对**同一资产**的导出（覆盖可为子集）；探活时对 404 / HTML 假响应单独校验 JSON 可解析；已读被测运行时解析器源码、确认字段消费语义（绝对 vs 归一化、是否反缩放）。
- 分支 D - D2：候选 vs 基准按运行时求值语义采样后，给出偏差中位数 / 超阈值曲线占比 / 最大偏差三项；选定"对基准偏差最小"的候选；跨 clip / 跨模型抽样结论一致；对照组仍逐字节证零回退（本例 104/104）。
- 分支 D - D3：WARN 阈值有校准依据（基准自比或表示法天花板的实测残差），并在工具 / 文档注明来由，非随手取值。
- 分支 D - 判据①：换入者 = 基准偏差最小者，而非"最符合规范"者；两者冲突时以基准为准并记录；交接里的环境开关与实际换入并通过验收的版本逐字一致。
- 分支 D - 判据②：交接 / TROUBLESHOOTING 文档含「已排除假设清单」小节，逐条写"假设 + 排除依据"。
- 分支 E - E2：新旧两页在**同一次运行**里跑完，样本表由同一份数据按固定步长生成（两页拿到完全相同的 key 列表）。
- 分支 E - E3：给出每个样本「内容绝对像素 改前 → 改后」与倍数，**回退样本数 == 0**（阈值 x0.98）；同时报"占容器比例"以暴露视口形状变化，但**判据只认绝对像素**。
- 分支 E - E4：至少两档窗口（`innerHeight` 分别落在像素上限的两侧）各跑一次，两档都 0 回退才算过。
- 分支 E - E5：每条恢复/仿真断言都带一条"空断言守卫"，且守卫本身有真实数字输出（基准宽 1233→874→1233、默认面积 0.94→操作后 0.99），能一眼看出它不是恒真。
- 分支 E - E6：测量前把背景刷成纯色，并抽样目视核对截图（**数一遍内容包围盒确实贴着画面**），防止阈值判据悄悄退化。
