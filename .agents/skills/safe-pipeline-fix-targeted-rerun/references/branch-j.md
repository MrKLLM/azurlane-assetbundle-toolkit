## 分支 J：纯等价重构（屎山清理）——没有行为意图变更时，对照判据怎么选

### J0：适用判定
去重 / 路径收口 / 结构拆分，无权威源切换、无行为意图变更。与分支 B 的区别：
B 允许"预期的语义变化"并用不变式裁判；J 连预期变化都没有，**任何差异都按回退查**。

### J1：对照组 = git show 旧版 exec 加载，不建临时副本
`exec(compile(git_show_src, real_path, 'exec'), {'__file__': real_path, '__name__': 'old_x'})`
——`__file__` 指真实路径让 sys.path bootstrap 生效，`__name__` 非 `__main__` 跳过入口。
新旧模块同进程对照，工作区零污染。

### J2：判据按产物类型选，先跑旧vs旧证明判据有效
- 确定性二进制（wav）：逐字节。
- **容器类（ogg）**：解码后 PCM md5 + 文件长度。ffmpeg Ogg 每次封装随机 serialno，
  旧代码自己跑两次字节也不同——**旧vs旧也红 ⇒ 判据失效，不是产品回退**。
- 编排函数：rc + 返回输出 + 打印文本（计时行 `rc=N / X.Xs` 归一化）+ 超时分支分别对照。
- 报"新旧不一致"之前必须先跑旧vs旧对照，否则会把仪器失灵当结论。

### J3：内联大字符串拆独立文件——哈希不变 + 消费方全 grep
- 拆分前 grep 全部消费方：不只 import 的，还有**用正则从 .py 源码抽字符串的探针**
  （实例：check_page_js.py 的 `PAGE = r'''(.*?)'''`，拆分后必须同步改读新文件）。
- 断言三件套：内容逐字相等（新模块属性 == 旧模块属性）、派生哈希不变（BUILD）、
  起服务 GET / 的字节 == 服务函数输出。
- 写盘用字节拼接保住其余行 CRLF；整文件文本写回会因行尾归一炸出上千行噪声 diff。

### J4：真实入口样本 + 共享工作树纪律
走 argparse CLI 样本（不只调库函数），输出落临时区零生产写；
删"看似没用"的常量/导入前 grep 全部 import 方；提交只 add 本轮文件。
