## 分支 C：占位 / 降级产物伪装成功（静默失败这一整类）

分支 A/B 都假设"产物有数据、只是数据可能错"。但有一类更隐蔽、破坏力更大的失败：**生成脚本在解析/提取失败时，悄悄写下一个结构完全合法、却没有任何有效载荷的占位（或降级）文件**。它能被加载、能通过"是否存在/是否启动"这类外壳检查，于是批量验证一路报绿，实际内容却全是空壳。真实案例：`reconstruct_live2d.py` 在 `extract_motions.py` 提取失败时写 `"Curves": []` 占位壳，而提取失败的根因是一个护栏 `num_keys > 100` 误杀了帧 0（帧 0 是 `time≈-3.4e38` 的参考姿态、一帧合法写全部曲线，大模型几百参数必越界）→ 整 clip 返回 `None` → 占位壳静默留存。磁盘实测 8154 条动作里 5037 条是空壳（61.8%），另 38.2% 曲线名按位置猜错，**真正正确的 0 条，潜伏一年多**。判"动画在播"若只看 `state.currentGroup` 变了（外壳），空壳也能启动，于是"能播但不动 / 乱飘 / 乱闪 / 没反应"全被漏过。本分支给六条硬规则。

### C1：解析失败绝不写占位/降级文件，必须显式报错并非零退出

生成脚本的失败路径**不允许**留下"能被加载但载荷为空"的文件。宁可让产物**缺失**（下游表现为 404 / 显式报错），也不要用占位结构把它伪装成数据。落地：
- 提取/解析返回空结果时，`raise` 或 `sys.exit(1)`（或累计 `bad_models` 后让 `main()` 返回非零码），**不写**该文件的占位版。
- 上游"补占位"的分支（如 reconstruct 写 `"Curves": []`）整段删除，改为一行提示"该文件应由 XX 提取脚本生成，缺失即显式失败"。
- 例外须显式声明：确属源数据本身为空（如游戏里就是空动画的 `effect` clip），要**单独记录为已核对的空**，而不是和静默失败混在同一个占位路径里。

### C2：写独立审计脚本，分类 shell / 错位 / ok；换入前后各跑一次当门禁

审计脚本必须**独立于被测生成逻辑**（自己判自己 = 自证循环）。它重新从权威源（如 bundle 的 `genericBindings`）推导每个产物"应当是什么"，把磁盘产物分类为 `shell`（载荷为空）/ `misassign`（载荷非空但映射/内容错）/ `ok`。用法铁律：**换入前对正式目录跑一次、换入后对正式目录再跑一次同一脚本**，两次都必须 `0 shell / 0 错位` 才算通过（本轮修复前 shell 61.8% + misassign 38.2% = 100% 坏，正是门禁数值）。审计脚本应带 env 输出目录开关（如 `L2D_OUT_DIR`），以便对临时目录先审再审正式目录。

### C3：验证判据落在载荷本身 + 独立不变式裁定，而非外壳状态、非自证

呼应顶部横切原则。动效类：`len(Curves) > 0` **且** 采样目标参数在两个时间点取值不同（真的在动）。裁判"新旧谁对"要引入**与被测数据独立**的不变式，而不是"和我的映射逻辑一致"——本轮用的是「同名参数的物理合理取值域」（`ParamEyeLOpen/ROpen` 恒 0..1、`ParamAngle*` ≈ ±30），旧版 23.1% 越域、新版 2.9%，从外部证明新对旧错；再叠加 `crc32` 绑定链跨模型 100% 可解析、91.7% 曲线索引严格升序（随机配对不可能产生）作旁证。

### C4：换入用 move/重命名，不用同名覆盖

第 6 步"复制备份 + 同名覆盖"在面对占位壳时有残留风险：半覆盖会新旧混血，且旧壳若被引用路径漏改会潜伏。改用**原子 move**：先把正式目录旧产物整体 `move`（重命名）进带日期/用途的备份目录，确认到达后再把临时目录新产物 `move` 进正式位置。换入后仍逐字节核对新位置==临时源；确认无误后备份目录再送回收站。move 天然避免"覆盖到一半失败留下混合态"，也让占位壳不可能因覆盖遗漏而残留。

### C5：新加的"拒绝路径"必须自己真的非零退出，否则它就是下一个假绿灯

给脚本加装硬闸（拒绝覆写 / 拒绝换入 / 缺参数就停）之后，**先测退出码再收工**。
最常见的漏法：`if __name__ == '__main__': main()` —— Python 会**丢掉 `main()` 的返回值**，
于是终端上明明打了 `[FAIL] … 拒绝覆写`，`echo $?` 仍是 `0`，而所有上层 judge 只看退出码。
落地：一律 `sys.exit(main())`；并补一条**负例判据**——"闸门拦下时目标文件的 md5/mtime 必须没被动过"，
只看打印不算（真实案例：2026-10-06 给 `extract_spine_v2.py` 装备份闸，自测时负例退出码就是 0，
同一次改动里还顺带发现 Windows 直跑会把中文判据打成乱码 ⇒ 需要 `sys.stdout.reconfigure(encoding='utf-8')`，
而管线内跑靠调用方设 `PYTHONIOENCODING=utf-8`，两条路要分别成立）。
⚠️ 反过来也别顺手扩大：把"提取失败 N 条也 exit 非零"一起改掉前，**先去读调用方到底怎么判**——
"这条不能改，会动既有 judge 语义"这类写在文档里的放行前提，往往是当初没取证就写下的保守假设。
2026-10-07 复核 `extract_spine_v2`：两个程序化调用方（批跑器与编排器 stage）**都不看退出码**，
各自扫 stdout，所以补上非零退出对它们是纯增益、无需放行；那句"需另行放行"当场作废。
⇒ 收到文档里的约束时，默认动作是**取证后再决定继不继承它**，不是照抄。

### C5b：行首前缀匹配的 judge，会被塞在行尾的失败完全绕过

"数 `✗` 行"这种判据只认**行首**。于是"主步骤成功、附属清单失败"写成一行
`✓ name: 3 skel | parts.json ✗ 原因` 时，两个 judge 都数不到它，批跑器连错误日志都不落——
结构合法的前一行把失败信息当成了装饰。修法是把附属失败**顶到行首**（该条目直接判失败、计入 miss、
退出码非零），而不是指望下游去解析行尾。
判据怎么造：实数据里这类负例常常**已经不复现**（清单全量换入之后就找不到了），此时合法的桩边界是
只替叶子判定函数（`extract_one` / `write_parts`），仍然调真实的 `main()` 走完整计数与打印——
不算绕过入口函数。闸门 `scripts/diag/test_spine_exit_code.py`（6 例：附属失败 / 主失败 / 全成 /
混合批 / `--parts-only` 目录缺失 / 正式区无备份仍 exit 2，最后一例是防自己把闸门改松的阴性对照）。
⚠️ 跑这种闸门时**不要把输出 pipe 给 `tail` 再读 `$?`**——那拿到的是 `tail` 的退出码，恰好是本节说的假绿灯。

### C6：「0 命中 / 待删 0 个 / 拦下 0 个」三件事都必须自证，才允许当成结论

批量清理与去重里的静默失败，长得和"真的干净"一模一样。三条自证，缺一条结论不成立：
1. **闸门是活的**：拿一个**已知承重**的对象跑同一条命令，必须看到它被拦。
   实测对照：`--cat painting` 拦下 10,767 / 待删 0（它们本身就是产物根）；
   `--cat artresource` 拦下 105 且理由带真实传递链（`artresource/effect/.../fliud07` ← 根 `painting/chicheng_heihua`）。
   没有这两条，"dorm3d/island/char/ui 拦下 0 个"完全可能是 BFS 写错了。
2. **扫描没漏层**：每个类目的"待删数"要和**递归文件数**对账。
   实测：`dorm3d` 第一层 **0 个文件**、5,989 个包全埋在 4 个子目录里；`island` 第一层 7 / 递归 7,755。
   第一版按 `os.listdir` 只扫一层，报"待删 0 个"且一声不响 ⇒ 3.5 GB 静默放过。
3. **登记键的口径对得上**：删完不登记，下次 diff 会把整批报成"全部新增"、白下一遍。
   但登记键写错前缀（依赖表用 `painting/xxx`，同步器用 `AssetBundles/dorm3d/a/b`，同步根不同）
   ⇒ **看起来登记成功、实际永不生效**。验证不必连设备：进程内 `import` 那个比对函数，
   喂三行合成数据做对照——同尺寸 ⇒ 判归档；大小 +1 ⇒ 判真新版本要重拉；未登记的承重包 ⇒ 仍判要拉（阴性对照）。
   ⚠️ 顺带查反向通道：有没有"撤销登记"的口子。缺了它，将来想拉回来会被自己的归档判据静默跳过。

### C7：反过来——**放开**一条抑制名单类闸门（撤销归档/删除登记）同样是危险写操作

C6 第 3 条讲的是"登记要验生效"，它的镜像同样没人做：想拉回被自己闸门压住的一批时，
通常是**手工改那份台账 JSON**，而这类改动的失效方向和删库一样——**多放了闸、没人知道**。四条：

1. **HEAD == 工作区才动手**：那份台账一般在版本控制里，HEAD 就是永久回滚锚点
   （`git checkout -- <台账>` 一键关闸），另存当场备份只为对账。写盘前**重取文件哈希与读入时比对**——
   共享工作树里别的会话可能正在写它。
2. **断言写进代码，不靠眼睛**：改前逐名单分块计数并钉死数字；改后必须"被删键数 == 该前缀条数"
   **且**"留下的每一条 value 与原文件全等"**且**"新增键 0"。序列化格式要跟原文件一致
   （`separators`/`ensure_ascii` 不同 = 整文件重写，diff 里看不出内容没变）。
3. **判据必须含"其余名单仍被抑制"的阴性对照**，且**判据 = 重跑同一条只读命令、看那一行消失**。
   只验"目标放开了"是半个结论：它证明不了你没顺手把别人的闸门也拆了。
4. ⚠️ **窗口期副作用要显式写在交付里**：抑制名单一开，**所有**入口（含别的会话、别的批处理、控制台某档）
   都会把这批对象当成待处理新增，可能是几十 GB 的意外拉取/重建。⇒ 窗口要短，
   并且提前给出"若后续判据判死就一键关闸"的那条命令。

配套坑：**两份清单对不上时，先归一口径定"差集方向"，再用被测系统实测定性**。
同一批文件在两份清单里的键常差一个前缀/分隔符（本例台账用 `AssetBundles/dorm3d/a/b`、
校验清单用 `dorm3d/a/b`），不归一比对会假报"全部不同"；归一后 `csv ⊂ pruned`、差 8 条，
再逐个向**设备本身**探（`stat`）才定性得出"是那 8 个包被上游删了，不是台账记错"。
光比两份盘上清单永远分不出"我没登记对"和"源头真没有"。⚠️ 而且**台账独有项不会出现在比对输出的任何一行**
（源头没有它、本地也没有 ⇒ 归档行和新增行都不含它）——"台账 5,989 / 比对 5,981"这种落差**本身是信号**，
可复原上限要按比那个实测数报，不是按台账数。
