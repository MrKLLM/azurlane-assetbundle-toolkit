## 分支 H：按名字落盘的导出器 —— 「同名多对象静默覆盖」审计与定向重导

适用：导出器把包内对象按**资源名**写成文件（Unity/AssetBundle、protobuf 多 message、
任何"遍历对象 → `name.ext` 落盘"的循环）。这类循环的默认失效模式是**后写覆盖前写**，
不报错、产物数还看着对，只有内容少了。

**先定性，再动手**（三条机制互斥，各有修法）：
1. **同包同名多对象、内容不同** ⇒ 每包静默丢一整份。裁决**不能按尺寸、不能按顺序**：
   同尺寸的两份会打平，跨尺寸的"看起来像缩放版"可能其实是不同内容
   —— 把大的缩到小的尺寸后算平均色差，同图缩放应在个位数、几十就是不同图。
   正确规则：**按解码内容指纹分组，同内容留最大的一份、内容不同就全都留**（第 2 份起加 `__N` 后缀），
   组间按 `(-面积, 稳定 id)` 定序，保证重跑得到同一套文件名。
2. **同名的"裁剪版/子集版"顶掉完整版**（如 Unity Sprite 落的是 tight-bounds 裁剪）⇒
   完整版存在时直接丢裁剪版。⚠️ **元数据里的尺寸字段可能是"声明尺寸"**
   （Sprite 的 `m_Rect` 报图集尺寸、真实产物小几倍；有的版本 `m_Bounds` 干脆是 None）
   ⇒ **唯一可信的尺子是解码后的真实尺寸**。
3. **导出层比源包旧**（源包后来才拉进来）⇒ 整包无产物。定点补导，别整目录重导。

**落地三步**：
- **只读预演**：import 生产代码里那个裁决函数本身跑全量，算出「会改 / 会新增 / 会删」三张清单，
  于是"重导 N 千个包"缩成"重导命中的 N 十个包"，其余一字节不碰。
  ⚠️ 预演必须**比内容不能比尺寸**——比尺寸会漏报"同尺寸换了另一份"这一类（实测漏 6 个）。
- **对照臂**：把新策略关掉再跑一遍，产物必须与盘上现文件**逐字节相同** ⇒ 这才证明
  "重构没顺手改掉无关行为"。裁判要走在被测代码**不同的量法**上（真解码 vs 元数据字段），
  否则"产物等于上限"这种断言只是在复述实现。
- **定点重导的 CLI 过滤要防串包**：跨目录同名是常态，`--only <名>` 不限定目录就会顺手
  重写别的类目已验证的产物 ⇒ 歧义时**直接停下报错**，不要"多写几个也没事"。

**收尾双闸**：① 实际变更集 == 预演集、删除数 == 0；② **内容级全覆盖**——每个受影响包里
每一种不同内容都能在盘上找到（这才证明"换主文件名"没丢东西）。然后才轮到派生产物
（缩略图改了档位必须 `--rebuild`，增量会跳过旧图 → 页面看着还是糊的；索引；页面探针）。

**合并展示类目会制造新的重复**：把变体目录并进主类目后，"变体那份"可能和"补回来的 `__N` 那份"
   逐字节相同。⇒ 去重要按**内容**、在**合并后的类目内**做（按"同名配对"配不上——重复对象的
   名字可能压根不同），每条丢弃记 `same_as` 并断言"同内容那条确实在保留集里"。
   ⚠️ 交付时**分开报三个数**：文件数 / 索引条数 / 净增内容数——它们会分叉，只报最大的那个，
   下一轮就有人拿它做决策。

**命名与下游**：`__N` 后缀会污染"按名字查权威表"的 join ⇒ 查表前先剥后缀；
但**不能因此给第 2 份发"确定名"**——权威表按名字引用，同一个名字对应两份内容时它分不清是哪一份，
只能降级为"推断"并标 `same_name_of`。
