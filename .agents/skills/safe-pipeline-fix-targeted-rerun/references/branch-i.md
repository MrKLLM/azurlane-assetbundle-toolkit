## 分支 I：判据层的「假绿」与「结论盖章」——阶段机全绿 ≠ 管线正确

适用：给一条多阶段管线"体检"（用户说"检查一下还原管线有没有问题"）、或修完一处判据后
需要证明"下一轮不会把结论又清空"。本分支三组判据都来自真实事故（2026-10-21 一次修完）。

### I1：判据只认"脚本的结论行 + 退出码的语义"，不认日志形状

一个阶段脚本恒 `exit 0` 时，判据最容易写成"数里面有没有 ✗ 行"，而这类统计有三个经典漏法：

| 漏法 | 实例 | 判据怎么改 |
|---|---|---|
| 前缀匹配漏掉缩进 | `"  ✗ name: …"` 不满足 `startswith('✗')` | 只认每批**收尾汇总行**（`完成 N，失败 M`）；**没读到汇总行 = 该批全失败** |
| 缺汇总行默认通过 | 脚本崩在打 ✗ 之前，临时区还有上一批旧产物 ⇒ `n>0 且 fail==0` 判绿 | 没证据不许默认通过；"零样本"不能算过 |
| 退出码语义没进判据 | 批量脚本只数 ✗ 行，崩在打 ✗ 之前时 `0 >= len-1` 对单元素恒真；解码器 `rc=2 = 致命前置` | 批量 rc≠0 直接计失败；确认每个非零码的**唯一含义**后写进判据文案 |

**双向自测是硬要求**：每条修复都要在测试里放两个分支——"旧判据会绿的坏形状现在判红"
（拦得住）+ "正常形状仍判绿"（不误红）。只测拦截那半，迟早把判据写成恒真。

另：**测试自己也会假绿**。本项目一条闸门判据里 `json` 没 import，`NameError` 被
`except Exception: pass` 吞掉 ⇒ 这条判据**从上线起从未执行**。判据文件里任何 `except: pass`
都要配一条"防静默跳过"的断言（首跑输出里没有该 PASS 行 = 它没跑）。

### I2：结论的"盖章口径"必须与读取端逐字一致

现象：一轮跑完 20/20 判绿，下一轮启动/面板打开时**全部变回「未跑」**。
根因：写端用"本轮起点"的整条输入指纹给每条结论盖章，读端按**逐阶段**指纹（有些阶段
自己会改写输入，比如拉包/发布配置表/换依赖表）比对 ⇒ 这些阶段与其下游天然对不上。
修法：**每个阶段跑完现算一次它自己的阶段指纹再盖章**；读端按"要不要带某半段"各算一次
（最多两次）而不是逐条各算——20 条 verdict + 6 条 done 实测 46 次 walk / 11.25s → ≤2 次 / 0.2s。
判据：构造"20 verdict + 6 done"的真实状态，断言**旧写法全丢、新写法全保留**，并覆盖两种口径。

### I3：跨阶段派生产物"没有生产者"这一整类 —— 唯一能抓到它的是 e2e 重生成比对

现象：端到端验证红一项（"台词表重生成：字段不一致"），而阶段机全绿。
根因：某个派生产物（`skin_words.json`）由构建脚本生成，但**管线里没有任何阶段调用它**，
下游索引直接读盘上旧文件 ⇒ 这个文件可以一直烂下去，阶段机看不见（没有阶段读它、没人判它）。
修法：把重建接进应有的阶段（在消费它之前），双判据（rc=0 **且** 输出含"已写出"），
失败**拒绝继续**下游；并把它写进该阶段的 writes/判据文案。
**结论口径**：
- 阶段机只能判"自己读过的输入"，**跨阶段派生产物的新鲜度它没有能力看见**；
- 唯一能发现的是 e2e 的"用当前输入重生成一份、与盘上逐字段比"——所以这条验收**不是可选项**；
- 代码修复 ≠ 产物已更新：红了要去跑一次**签字**的那一步（会写生产区），别改判据来消红。

### I4：控制台/编排器的三个「进度假象」：锚点、写入、外部服务

阶段机自己跑对，不等于用户看到的「下一步」是对的。修这一层时按三个可观测点验收：

- **待办锚点必须是「正在跑的任务」，不是「第一个没绿的阶段」**。运行记录只写 `label/argv` 时，
  前端拿不到 `running.step`，只能退回「第一个 idle 阶段」；而多阶段任务里上游结论恰好会被下游改写的
  输入（依赖表/配置表）判失效 ⇒ 待办指回第 1 步（2026-10-23 实测：跑 cg 时显示「正在跑 01」）。
  修法：启动时从 `--only` 反查阶段的最小 step 落进运行记录；前端优先用它，再退回「第一个非通过」。
  另外给「整步 idle、但后面已有 fail/run/await/pass」的前缀步骤一个「本轮未复核」态，不要画成 0/N。
- **阶段缓存必须原子写**。读端按秒轮询，`json.dump(open(path,'w'))` 先截断再写 ⇒ 读端会看到半截 JSON；
  一次解析失败不能让整块结论变空（面板会显示五步全 0/N）。写端 tmp + `os.replace`（Windows 上重试），
  读端失败重试一次；截断窗口和「结论被清空」是两件事，别用同一个 `except: pass` 吞掉。
- **外部服务要在启动前探活，判据是「页面能加载」而不是「端口在听」**。无头批量导出页依赖本地 HTTP
  服务时，服务没起 ⇒ Chrome 停在错误页 ⇒ 驱动脚本等某个就绪标记直到超时（实测 30 分 03 秒），
  编排器只看到「仍在跑」。修法：启动前 GET 一次并读 1 字节；驱动脚本连上 CDP 后 N 秒内检查页面就绪
  标记，没有就非零退出；超时/无收尾行也非零退出。两条分支都要自测（不可达 → 秒级红；可达 → 正常跑）。
- **探活失败且服务可自启时，由编排器自启**：detached 起运行目录那份服务器 + 轮询到可达；只有起不来
  才把双击 bat 甩给用户。⚠️ 端口被占但页面 404（旧的无根启动器）不要起第二个——新进程会走
  `port_in_use` 复用旧进程、继续 404；提示关旧窗口。
- **暂存产物不是「换入」**：Spine/Live2D 这类阶段只写临时区，而消费者（CG 页/索引）读正式区；
  必须有一个显式换入（带备份）步骤，且换入后重建消费索引。判据：汇总行必须与本轮范围对账
  （`完成+跳过 == 范围`），`完成>0` 不足以证明没漏——旧索引会把新皮肤过滤掉，仍报「完成 2/6」。
- **复核目录也要做批次隔离**：每轮 review 先把上一批的对照图归档到 `archive/sheets_<时间>/`，
  列表按 mtime 倒序；主屏/摘要用 verdict 的「新增 N / 变化 M」，不要用目录里的图片文件数
  （否则旧图会把新表顶到列表底部，用户以为这轮没出表）。
- **文件数 ≠ 实体数**：新皮肤常有 `_n/_hx/_hei` 变体，36 个文件可能只是 9 个皮肤 + 5 个本体 +
  2 个黑影；元数据阶段要扫**临时区**（换入前）并用设备侧 stats 补社区快照缺的新船，否则新皮肤
  显示「元数据缺」；权威闸门必须在换入**之前**跑（先换再跑 = 拿新文件跟它自己比）。
  语音映射同理：`extract_cv_voice` 的 gallery keys 只扫正式区时，换入前的新皮肤没有声音
  （实测 4/5 新船 cue 包在，但 4 个 CV2 没解码）；复核对照表也要按实体分组，不要按文件前 N 个取。

**判据**：把面板状态接口和页面函数都量一遍——`/api/state` 的阶段完成数、`currentStep()` 的返回值、
运行记录的 `step`、右栏文案；再用「外部服务未起」的桩页跑一次驱动脚本，确认 10 秒级退出而不是等到超时。
