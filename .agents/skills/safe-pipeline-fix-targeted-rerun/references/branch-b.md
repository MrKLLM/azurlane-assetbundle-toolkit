## 分支 B：非视觉元数据 / 生成索引的权威源切换

上面 7 步假设产物是**像素可比对**（PNG 逐通道 `maxdiff==0`）。但当改的是**元数据推导口径**——例如把 gallery `index.json` 的 `cn_name`、`faction` 从旧映射表（`SHIP_NAME_MAP`+Wiki）切换到新的权威 JSON 表（`ship_meta.json`）——产物是结构化 JSON，没有像素可比。**用户又明确拒绝逐条人工审阅**（"上千条我看不过来"），此时不能靠"看着像修正"放行，必须让机器承担裁判责任。本分支把 7 步方法论平移到这个场景。

核心思路：`git show` 旧脚本重生成旧基线 → env 开关把新产物写临时目录 → 逐条目 × 逐字段三分类 diff → **用领域不变式把 `changed` 自动判成"修正"或"回退"** → 意外回退走根因反转而非打补丁 → 换入后逐字节核对。

### B-1：先问「关联键到底是哪一列」——选错键不是少几行，是整盘错位

权威表里常有好几个长得像 id 的列（`order`、`xxx_id`、`cover`、键序号 `#0..#9`）。**不要按"看起来应该对得上"选**：
把候选键各自的映射结果摊开、与外部权威（游戏界面 / 截图 / 官方站）逐组对一遍，只有**能同时解释所有组**的那个才是键。

实测反例（音乐专辑归属）：`music_collect_config.album_id` 被拿去对 `music_album.order`，
而 `order` 是 `10,9,8,7,6,1,2,3,4,5` 的排序值、键序号才是 1..10 ⇒ 十张专辑**两两互换**：
每张都"有几首歌"、错得很像对的，用户要逐张对着游戏截图才能发现。
真正的键是 `cover == "MusicCover{album_id}"`（`#0→MusicCover10 … #9→MusicCover1`）。

两个附带判据，缺一个就会留暗坑：
- **覆盖自检**：同一实体被两个组命中就告警，不许静默取第一个；
- **大小写 / 前缀归一**：源表常是驼峰（`bgm-theme-SeaAndSun-image`），盘上产物常全小写
  （`seaandsun`）⇒ 精确查找会"文件明明在、却挂不上名和归属"，表现成"缺 6 首/缺 6 个名"，
  其实只是查找失败。归一化要能**重复剥前缀**（表内名本身就带 `bgm-`）。

### B0：用 `git show` 旧脚本重生成旧基线（不改工作区）

不要靠"当前正式产物就是旧基线"——正式产物可能已被别的改动污染。直接从 git 取**修改前版本的脚本**跑一遍，得到干净基线：

```
git show HEAD:scripts/build_gallery_index.py > .diag/_old_bgi_tmp.py
# 用旧脚本输出到 .diag/old_gal/index.json（旧脚本若无输出开关，临时改它的 OUT 常量到临时目录再跑）
```

`HEAD` 必须是"改动前最后一次提交"；若本次改动尚未提交，先按第 0 步建基线再改。旧基线脚本是临时脚手架，换入后送回收站，不入库。

### B1：给新脚本加 env 输出开关，新产物写临时目录

新脚本增加一个环境变量（如 `GALLERY_OUT_DIR`）：默认落正式目录，设了该变量就落临时目录（如 `.diag/b_test/`）。**正式目录零污染**，验证通过前绝不写 `Output/`。这与主线第 3 步"输出到独立临时目录"同构，只是落点从图片目录换成 index 目录。

### B2：逐条目 × 逐字段 diff，三分类 lost / changed / gained

以主键（船名 / stem）对齐新旧 index，对每条目的关键字段（`cn_name`、`faction`、`category`、`skins` 列表等）逐一比较，把差异分三类：

- **lost**：旧有新无的条目 / 字段值从有变空 → 几乎总是回退，红线，必须为 0（除非声明了合并豁免）。
- **changed**：同一条目字段值不同 → 需 B3 裁判是修正还是回退。
- **gained**：新多出的条目 / 字段从空变有 → 可能是修正，也可能是 B4 的预期结构变化。

输出三分类计数 + 每类清单落盘（如 `.diag/_field_diff.txt`），供 shell 直接消费，不手抄。

### B3：领域不变式自动裁判 changed（替代人眼）

这是本分支相对主线第 5 步的**关键差异**：用户不看，就得有可计算的规则替他把每个 `changed` 判成"对"或"错"。不变式必须是**独立于被测数据源**的事实，否则自证循环。常用不变式（按项目挑选 / 新增）：

- **磁盘 stem == 正确中文名拼音**：`index` 里 `cn_name` 对应的 PNG 文件名 stem，必须等于该中文名的拼音（`pypinyin` 生成）。谁违反谁错——若新表让某船 `cn_name` 变了导致 stem≠拼音，说明新表这个值可疑；若旧值本就错、新值让拼音对齐了，则是修正。
- **占位符命中数 == 0**：字段值里不得出现 `{namecode}` 之类未解析占位符。新表若引入占位符（如 `ship_skin_template.name` 含数百个占位符），命中即回退。
  - ⚠️ **文本要端给人看时，这条必须落到"渲染后的页面"上，不能只落到中间字段上**（2026-09-27 撞过）：
    游戏配置里的台词**自带运行时占位符**（`{namecode:NN}` 由 `name_code` 表展开），结构判据（行数 / 逐字对齐 / 可播）
    全绿也看不见——它已经在页面上挂了整整一天、影响 862 个能播的皮肤行。
    ⇒ 三条一起做：① **生成侧展开**，展开表要带对齐证明（含零假设对照：可解析率、自称率 vs 随机重分配、整行人读），
    别拿"能查到"当"查得对"；② 产物里命中即 `SystemExit`（零容忍，不是记个数了事）；
    ③ 页面级断言（DOM 文本里出现占位符 = 红）。
  - **查不到就原样留着并计数，绝不编一个值填上**——宁可让用户看见 `{namecode:99}`，也不能让管线替游戏造台词。
- **阵营 / 类别归属规则**：faction=META 的形态不得作为皮肤并进本体船（见 B4 的 META 独立卡），category 取值必须在白名单内。
- **非空字段不得变空**：某船旧有 `cn_name` 新为空 → 回退。

对每个 `changed`：跑全部适用不变式。**通过 = 修正**（自动放行并记入修正清单）；**违反 = 回退**（拦下，转 B5 根因）。**不变式覆盖不到的字段必须显式回落到人工**——不能因为"用户不想看"就默认放行；此时按 **B3-H** 的固定规范生成带缩略图内嵌的 Markdown 复核清单交用户勾选（不是 CSV），勾完再落白名单重建。用户拒绝逐条 = 不变式覆盖率就是安全边界，边界外的必须暴露而不是藏起来。

**`lost`（归零 / 字段消失）和 `changed` 一样要裁定，别一律当回退拦、也别一律放行**。换权威源时"某条从有到无"有两种完全不同的成因：新源确实没这个值（回退），或**旧值本来就不属于这一行**（修正——旧口径把别人的数据派给了它）。可复用的裁定不变式形状：**拿旧值指向的实体回查权威主键，看它是否落在本行的归属集合里**；不在 = 修正，在 = 回退。真实案例：旧社区表把 `cv-20705`（可畏）的语音记成"可雷"，切到游戏自己的皮肤表后归零 ⇒ 该行的包号集合是 `{90040}`，旧包号不在其中 = 修正。**这个判定必须是规则，不许落成"某几个名字豁免"的例外名单**——例外名单会让下一个同类错配原样溜过。

- **推导式 join 键（`key = a*10 + b` 这类）是 `lost` 误判的头号来源**。若某字段是"由两个业务量算出来的主键"，
  先问：**这个等式从哪来、什么时候不成立**——它通常只是"老数据恰好如此"的巧合，一到某个边界就进位/串号。
  ⚠️ 它坏掉的方式是**静默**：`if not row: 记为无数据` 这类护栏只防"查不到"，**不防"查到了别人那一行"**，
  于是 join 成功、值非空、结构判据全绿，只有"字幕比语音短"这种人耳判得住的矛盾才露出来。
  ⇒ 键必须由权威表**查**得；查到后回查那一行的归属是否等于本条目的归属，不等就报错，别继续用。
  ✅ **正向做法：先去表里找那条真正的外键，别急着发明算式或打分器。** 这类"两个命名空间对不上"的问题，
  权威答案常常就在同一张表的某个**没用上的列**里（真实案例：语音包号 = 皮肤表的 `ship_group`，
  2865 行全有值；而"包内第几档"= 号段偏移只有 `0` 与 `+3000` 两种，于是老号段 `id%10`、
  新批次 `10 + 批次顺序号`——从此不需要任何猜测或分配器）。找法：拿一个**已知正例**去反查
  "哪个字段的值恰好等于我确认的那个数"，再统计该字段的取值分布是否只有少数几种离散形态。
  规则立起来后必须配两件事：① **独立信号互证**（与本规则来源不同的第二证据，如"这一档有哪些音频文件"
  ↔ "这一行有哪些科目有台词"做集合匹配），并**自报该信号的错率**（在真值已知的子集上跑同一套打分）——
  错率非零的信号只配用于排序与印证，不配单独下结论；② **证伪检查**（规则给的每个值都要在目标侧留下痕迹，
  留下"零痕迹"的条目要逐条查清是例外还是反例，查不清就不许声称通过）。
- **`lost` 的归属集合要含"同一实体的其它行"**，否则把自家另一行判成别人的（真实误拦 262 条：一个 painting
  在表里有多行——META/联动另开一档——取第一行正好取到没数据那行）。同类：回退到"父实体那一行"是否合法，
  取决于该实体是不是独立发声/独立数据主体，这是**业务裁定**，不能由字段有无来推。
- **还要问消费方"这一格到底渲不渲染"**：数据里少了一个键，但如果渲染层是按另一份清单（音频行/字段白名单）
  逐行画的，那个键从来没人看得见 ⇒ 记成"不可见回收"而不是回退，否则闸门常红、真回退就混在噪声里。
- **同一轮里多处改动要分开归因**：改了 A 让 B 的旧值失效（例：音频换档 ⇒ 那一档本来就没词），
  要单独记一档"待补"，既不算 A 的错、也不算 B 的坏。判据：**假设本轮只改 A，这条会不会变**？

### B3-F：改动对象是「选行规则」本身时——每处变化必须落到一条只放行正确方向的判据上

上一节说"取第一行正好取到没数据那行"是**消费侧**的坑；当你要修的是**产生侧的取行规则**
（同一 key 多行、组内多候选行），闸门不能退化成"什么都不能变"，也不能按字段名放行（那等于关掉检查）。

- **判据写成"任何一行都能套、反向必拦"的规则，不写例外名单**：例如
  「只有候选行**同时**满足『有配音』且『组查得到权威 stats 行』、而现状行不满足才改判」
  「组内取 (阵营,舰种,稀有度) **众数**那一族，且支持度必须**严格大于**旧行（并列不许自动放行）」。
- **判据函数放模块级**，并配反向对照样本（同一族内「真英文名→占位 `simulation`」必须拦、
  「多数派→少数派」必须拦）。闸门里的判据没法测就等于橡皮章。
- **探针必须与正本对账**：影响面探针自己复算的"应选行"要与正式代码实际选出的行**逐组相同**，
  否则报告说的是一个不存在的规则（做成硬断言 + 退出码）。
- **下游产物做"两头同源核对"**：索引/前端里每个变化的值要**同时**等于改前与改后那份元数据
  （旧值也对不上 ⇒ 是下游自己漂了，判红）。只核对新值 = 给漂移开门。
- ⚠️ **别拿"号段更大 = 更新"当 tie-break**：多行冲突里有一类是**不同实体复用同一 key**
  （真实反例：企业暗潮皮肤 / 领航员换装 / 两个塞壬 BOSS 共用立绘），按 id 取大会把它们一起改判成
  `？？？？？`。方向性判据必须只认"从缺到有"，不认"看起来更晚"。
- ⚠️ 换入前 `git status`：重建共享索引会把**别的会话**遗留在产物目录里的取证中间图变成假条目
  （本轮 11 张）。产物目录只放产物，中间图落 `.diag/`；索引器遇到对不上号的中间图要**点名打印**再跳过。

### B3-F2：外键写歪时用「跨表同号」配对信号救，而不是给个例开名单（2026-10-05）

表 A 的外键指向错行 ⇒ 按外键走的桥永远查不到数据，看起来像"这实体没有元数据"。
**配对信号**：这类表常另有一个恒等约定——**A.id == B.id**（本项目：`statistics.id == skin_template.id`，
900xxx 段两侧同号）。用它做两件事，都是**单向判据**：

- **救援**：外键桥查空时，取「`id` 同号 **且清洗后同名**」那一行。同名这半条必须在——
  实测放宽它，候选集从 53 涨到 198（等于把号段巧合当证据）。
- **并列 tie-break**：上一级判据（众数）并列、只能靠 `min(id)` 时，优先「`id` == 本组基行 id」那一条。
  ⚠️ 同一处外键写歪常有**两个受害方向**：本项目并列 `min(id)` 让别实体的名字顶在了一张
  **与正身 md5 逐字节相同**的图上。只修救援不修 tie-break，结果是**多出一张同名卡**。

配套要求（都是本轮真跑出来的）：
- **影响面要分「生效 / 惰性」两档**：救援集 53 条里 51 条惰性（同一 key 另有被选中的行），
  真正落到产物只有 2 条。分档判据 = 「该 key 实际选中的正是这一行」；探针给 `--max-gain` 上限，
  只报总数等于没报。
- **放宽一条判据跑一遍 = 阴性对照**：分别关掉每个必要条件，打印候选集大小，
  才知道哪条在干活（本项目 `nationality` 那条放宽后 53→53，是冗余保险，须写出来）。
- **判据函数只留一份**：把选行抽成模块级函数，探针与闸门**都 import 它**。手抄一份，
  那条"复算行 == 正本实际选行"的自检就变橡皮章。

### B3-F3：结论形如"游戏里没有 / 产物不存在"之前，先跑一次未归属产物差集（2026-10-05 被用户否证）

归属桥断掉的表现就是"查不到"，**它不能证明源数据不存在**。固定三步，成本约 5 秒：

1. **差集**：原始产物集 − 已归属集（本项目 `cue/` 950 个包 vs `Audio/CV2/` 902 个 ⇒ 48 个从未导出）。
   **差集非空就不许写"没有"**，只能写"取不到，缺的是哪一环"。
2. **按多种身份回查差集里每个号**：作为主键 / 作为外键目标 / 作为分组键 / 作为别的表里的类型码各查一遍；
   已发布的小表白名单**不算**全量证据，要去查全量解码目录（而全量目录常在可清理区 ⇒ 结论必须落进 docs 或补发布脚本）。
3. **号段邻居定位缺口**：系列号排到 `…112` 而盘上有 `…113` ⇒ 那就是下一位新实体，
   比"缺一行"精确得多（本项目据此认出 `970113` 是灵敏·META，2.3MB 整包一直在）。

⚠️ 结构一变要顺手复查借值：本轮一张外迁条目**独立成卡**后，卡片显示的语音其实是**借本体的包**
（管线里 `src='strip'` 这类剥后缀借包）。借来的东西跟着新卡一起被当成她自己的，比挂在别人卡下更误导。

**接着上一节：确认"缺的是起点行"之后，发一张补桥表，而不是改查找优先级**。四条可复用要点：
- **别发明命名规则**——先在相邻表里找"已经写着答案的那一列"（本项目：实体自己的**剧情行 `prefab` 列**
  就写着它的自机资源名，且产物目录里确有那张图）。找不到这种列就别接管。
- 连接键的强度**全押在唯一性**上：按名字 join 时「候选恰好 1 条」是硬前提，
  0 条=没出处、≥2 条=同名不同实体，两种一律不接管（不许"挑一条更看起来对的"）。
- **消费侧要一次补齐**：发布脚本 + 元数据查找优先级（**在"表命中之后、继续剥后缀之前"**，
  顺序反了就会把新实体并进本体）+ 取数侧（同名候选上先认补桥再认表），并给来源打标（`src='bridge'`），
  这样"借邻居"那一类降级会**自动消失**而不是被掩盖。
- 这类改动**允许字段变空**（原先的值是从本体错贴来的）⇒ 闸门的方向判据要显式写明这一点，
  同时拦住反方向与无出处接管；⚠️ 别顺手加"按中文名去第三方表兜底"，那命中的是**本体**，等于把错值再贴一遍。
- ⚠️ **新来源档要同步进闸门的"受保护档"名单**。给条目打上新的 `source` 值之后，如果保护名单还只列旧值，
  下一次改动这些条目时闸门会打印"字段改动 0 处"——**它不是绿，是没看见**。加档位 = 同时改保护名单 + 加方向判据 + 补反向对照。
- ⚠️ **人工/玩家口径的值必须落在发布脚本里**（产物目录常是不入库的可再生区，只改产物下次会被抹掉），
  并带 `confirmed_via` 出处串；口语档位要先翻译成码表值（`SR` 在很多码表里是 4 而不是 5）。

⚠️ **写"读同一份文件再写回"的台账/清单时，顺序是硬性的**：`open(f,'w')` 一执行就把文件截成 0 字节，
把读取写成 `json.dump(build_ledger(old_read(f)), f)` 会先清空再读 ⇒ 本轮真把入库台账清空过，
靠它已 commit 才恢复。**先算完新对象，再开写句柄。**

### B3-G：比对闸门自身的两类失效（它红不代表产品坏，它绿更不代表产品好）

- **"只作参考、恒 exit 0"的辅助脚本，退出码必须被消费——否则它坏了没有任何地方会变红。**
  真实案例：某审计脚本被注释成"恒 exit 0 只作参考"，调用方于是完全不看它的 rc；后来一次数据结构改动
  把它弄崩（解包异常），阶段结论照绿，**坏了整整一天**。这种脚本设计上不会返回非 0，
  所以 `rc≠0` 只有一个含义=它自己出故障了 ⇒ 必须让阶段判红，并在结论里点名是它崩。
  自查问法：**"如果这个辅助脚本现在抛异常，我这边有哪个信号会变红？"** 答不出来就是洞。
- **"会静默降级的分支"要落成点名清单，判据用「存量记账 + 新增即红」，不要用"有没有"。**
  数据形状变化时，代码最常见的行为不是报错，而是走一条兜底分支猜一个值（借邻居的包、按顺序填个空位、
  标签回落到占位名）。要求这些降级**归零**通常不现实，只会逼人给闸门开后门。⇒ 做法：
  ① 每个降级分支产出一份**具体条目清单**（皮肤名/主键，**不是计数**——计数会把"3 条旧的换成 3 条新的"
  这种最该报警的情况吞掉）；② 把当前存量记进一份**提交进仓库的基线台账**；③ 只对"基线里没有的新条目"判红，
  并说明修法是补权威判据、**不是**把新条目写进基线；④ 做红路径实测：从基线抹掉一条真实存量，闸门必须报"新增"。
  ⚠️ 清噪声时别用过宽的单值判据：本例"偏移不认识"的 240 条里有 365 条是另一种**合法形状**
  （独立实体行的组字段存的是组首 id），但也不能只看那个号段——同段里另有 369 条偏移恰好正常。
  ⇒ 判据要同时看两个条件，否则要么常年噪声、要么误杀可用行。

- **给闸门加"合法变化"白名单时，白名单必须双向可核，且要拿一次伪造删除证明它掩盖不了真回退。**
  最危险的写法是**按名字/条数放行**（`if key in EXPECTED_GONE`）——那等于把闸门改成"这次我说过的都放行"，
  下一个真删除会原样溜过。合格形状是三条同时成立的断言：
  ① 掉出的条目**确实出现在新归属清单里**（不是凭空消失，是搬走了）；
  ② 它满足那条**类别判据**（本例：键必须是黑化后缀，且类别判据要与生产侧共用同一份定义，不许两处各写一份正则）；
  ③ 它**不得同时**还留在旧位置（两边都在 = 没做干净，也判红）。
  加完必须立刻做一次**伪造删除**：从主清单抹掉一条不满足上述条件的条目、新归属清单不动，
  闸门**必须仍然红**。这条对照没跑过，就不许声称白名单是安全的。

- **"拿被测对象的取值函数当期望值"= 空断言**。前端验收里最常见：`期望 = 页面自己的 w[key]`，
  于是"键取错了行 / 派给了别的实体"这类错**在结构上不可判**，页面错一整天探针一路绿。
  ⇒ 期望值必须来自**被测对象之外**的权威源（本例：把页面实际用的行 id 交回 Python，
  再拿主数据表 + 同一份归属规则反查那一行属不属于这个条目）。
  与"验证不得绕过被测入口"是**一对**：既要走真实入口，又不能让真实入口自己给自己出题。
  ⚠️ 反向的坑也真发生过：产品规则改了（某类行故意不再配字幕），这条判据先报了 `对齐=False` 的**假红**
  ⇒ 改产品规则时，验收侧的期望式必须同批改，否则下次真错混在假红里分不出。



- **"允许变化的字段"必须仍然参与比较**。第一版常写成 `scalars(d, skip = 白名单 | {...})`，把白名单字段整个剔出比较集 —— 于是"这个字段从有到无"那条判据**在结构上不可达**，闸门对着最该拦的东西给绿灯。正确形状：全部标量都比，比出差异后再按白名单分流成"期望变化 / 回退"。凡新增判据，先构造一条**它必然为红的输入**验一遍（本例：故意留一条真回退，看闸门是否报红）。
- **哈希台账要按"落盘字节"算，不是按内存里的字符串算**。Windows 上 `open(p,'w')` 文本模式会把 `\n` 写成 `\r\n`，于是 `bytes`/`sha256` 记的是 LF 版本、盘上是 CRLF 版本 —— 只要产物带换行，校验脚本就**永久报 DRIFT**（假红灯挂久了，真漂移就混在噪声里看不见）。发布脚本一律 `open(p,'wb').write(blob.encode('utf-8'))`。同一类："校验一直红"和"校验一直绿"都要怀疑校验本身，先用一个已知一致的样本反测。

### B3-H：人工复核清单输出规范（不变式覆盖不到时的交付物）

不变式判不了的疑难残余，导给用户人工复核时**固定用带缩略图内嵌的 Markdown 文件**（如项目根目录 `story_review.md`），**不是 CSV**——用户要边看图边勾选，CSV 无法内嵌图片（实际会话中已被明确否掉）。勾选完成后 `grep '\[x\]'` 提取条目，落入白名单（如 `build_gallery_index.reclassify` 的 `EXTRA_SHIP`）重建。格式五要素：

1. **图片用相对路径，禁止 `file://` 绝对路径**。`.md` 放项目根目录时，缩略图引用写 `Output/gallery_v2/thumbs/xxx.webp` 这类相对路径即可。踩坑实录：初版用 `file:///D:/Azur%20Lane%20Assets/...` 绝对 URL，Markdown 预览器/浏览器因安全策略全部拦截显示"加载失败"，换相对路径后正常。
   ⚠️ **相对路径的基准是"这个 .md 自己所在的目录"，不是仓库根**。.md 放进 `docs/` 子目录时，引用仓库根的资产必须写 `../Output/...`——写 `Output/...` 会被解析成 `docs/Output/...`，预览里**每一张图都是"加载失败"**（2026-10-03 实测：清单里 149 张缩略图全灭，文件其实都在）。落地后自查一句：`grep` 出前几条路径，从 .md 所在目录拼一遍确认文件存在，别只看生成器打出的"已写出"。
2. **排序：越像目标类别越靠前**——有阵营/舰种/Spine/Live2D 等指向性特征的条目放最前，降低用户翻页成本。
3. **每条固定结构**：三级标题 `### 001 中文名 \`key\``（编号 + 中文名 + 反引号 key）→ 元数据行（阵营 / 舰种 / 稀有度 / 皮肤数 / Spine / Live2D / source）→ 缩略图 `![名称](相对路径)` → 一条 GFM 任务列表项 `- [ ] 自机?`（问题文字按场景定）。
4. **勾选框必须用 GFM 任务列表语法**：`- [ ] 文字`（短横线 + 空格 + `[ ]` + 空格 + 文字），支持 GFM 的预览器才会渲染成可点击的真实 checkbox；写成 `- 自机? []` 这类纯文本方括号**不会**渲染成交互控件。用户勾完后 `- [ ]` 变 `- [x]`，据此提取落白名单。
5. **文件开头加一行勾选规则说明**：告诉用户把 `- [ ]` 改成 `- [x]`（或直接报条目编号 / key 均可）。

### B4：声明预期结构变化，把 gained 与漏字段区分开

主动的建模改动（例：META 形态从本体船拆成独立卡，`gained` +54 条）会同时抬高 gained/changed 计数，若不声明就会和"意外新增/回退"混淆。在跑 diff 前，用一份清单**显式声明预期 delta**（"META 独立成卡：预期 gained 56 个 `_meta`/`_alter` 卡、本体船 skins 减少对应项"）。命中清单的结构变化计入"预期"，清单外的 gained 才需 B3 裁判。这一步让"总船数 954→1008"这类数字变成可核对的预期值，而不是吓人的意外。

### B5：意外回退走根因反转，不打补丁

若 B3 抓出某类 `changed` 是回退（例：`kelei` 克利夫兰切新表后舰名反退成占位符），**第一反应不是给这条写 if 兜底**，而是质疑"新数据源 / 新字段优先级是否本来就更准"。常见错假设是"权威表一定 > 旧映射表"——实测可能是"字段 A 更准但字段 B 更差"。此时反转字段优先级（例：`cn_name` 取 `ship_data_statistics.name` 而非 `ship_skin_template.name`，因为后者含占位符），从根因上让占位符归零 + 舰名修复一次做完。这条可复用排错路径：**先怀疑源与优先级，再怀疑单条数据**。

### B6：换入 + 逐字节核对

验证全绿（lost=0、changed 全部命中修正清单、gained=预期结构变化）后，**unset 输出 env 正常跑一次**让新 index 落 `Output/`，再与已验证的临时版 `cmp`（逐字节一致）才罢休。这与主线第 6 步"换入文件与临时目录源哈希一致"同理，只是比对对象从图片换成 JSON。脚手架旧基线脚本送回收站，index 派生重建走主线第 7 步的增量逻辑。

### B7：审计"处理不了的那一批"——按可救性分解，判据必须比该子集更上游（2026-09-27 撞过）

管线跑完总剩一批 🔇/跳过/失败项。只报总数（"还有 354 张无解"）没法拍板，且会被当成待办反复重提。两条要求：

1. **按可救性分类，四类动作完全不同**：等上游下发（本机与设备两侧都查过）/ 换权威源就能定 /
   需要人裁定语义 / 结构性没有。分类表要带"其中还能拿到什么"这一列（例：音频缺但正文齐全 ⇒ 那是产品口径缺口，不是数据缺口）。
2. **循环判据（最贵的一类假结论）**：拿派生表回答关于派生条件的问题。
   例——词表的 `m` 是**只遍历已解析出声的条目**建出来的，用它问"无解条目有没有正文"恒为 0，
   看起来像"它们连正文也没有"，其实是同一筛选条件的自我复述；换成直接查权威表后是 100/354。
   **通用形状：凡是 "A 是从 B 筛出来的"，就不能用 A 回答关于 B\A 的问题。**
   配套：审计工具必须 `import` 管线自己的解析函数，另写一份判据审的就是另一个东西。
3. **裁定"能不能继承父条目"要非循环证据**：别问"剥掉这个后缀能不能命中"（必然能），去问上游表自己：
   这类后缀**有没有被单独立行**？那些行**有没有对应数据**？实测——画法后缀确实会被单独立行，
   而那些行既无音频也无正文 ⇒ 上游本就没配，"剥后缀继承"= 把父条目的数据冒充成它的（不报错的语义错）。
   再配一条独立旁证（这批文件在产物里只有静态图、没有可交互模型；父条目本就挂着多份画法），三条一起才构成否证。
   **反例也记一条**：别把"某字段 = -1"读成"没有值"——实测 -1 是"本行未配置（继承）"，
   真按它判会把 140 条"缺数据（可等下发）"错标成"结构性无解"，等于自己造一条否证；判据要收到只认 `0`。

### C8：红路径自测本身也会写错——两条必查项（2026-10-07）

变异/对照测试是"证明闸门会红"的手段，但它自己有两类典型失效，**都要当 bug 查**：

1. **变异样本必须真的改变被测物理量**。反例：验"静止态蒙皮是否正确"时，
   把所有权重整列改成 `(1,0,0,0)`（全模型只跟 0 号骨）——偏差仍是 1e-6 量级，
   因为 `B0·inv0·bind ≈ bind`，这类"换骨不换姿态"的扰动对静止态判据**天然不可见**。
   换成"每顶点首骨改成中段骨并独占权重"才爆开。⇒ 加完对照先问一句：
   **它在被测的那个量上真的产生位移吗？** 用被测判据本身去量变异样本，偏差为 0 就是无效对照。
2. **判据的极性本身要有对照**。收集"失衡网格"的谓词写成 `if maxDev < 阈值`（收集的是健康项），
   于是坏样本"PASS"、好样本"FAIL"，两边都看起来像真结果。
   ⇒ 变异测试要**同时断言好样本绿、坏样本红**，只断言一边等于没断言。
3. **"对照红了"不等于对照有效——要按它排除了哪一条具体约定来设计**。
   反例（2026-10-08 跨包 PPtr 解析）：配了一条"拿错 SerializedFile 的 externals"的对照，它 20/20 全塌，
   但塌的原因是那些 `path_id` 在错表指向的包里**根本不存在**（细分全是 `notfound`）⇒ 这条只证明了
   "错表会连包都找不到"，**根本没碰**「`file_id` 从 1 起 → `externals[file_id-1]`」这条真正要验的下标约定。
   真正钉住它的是另配的一条：**同一份 externals 下标 ±1**，同样 20/20 塌。
   ⇒ 加对照先写下"它排除哪个具体错误"；写不出来就是无效对照。
   同族判据：**分桶细分要打印**（`oob/builtin/miss/notfound` 分开），"全红"这一句本身没有信息量。

4. **锚点必须自带"敏感度声明"，否则退化样本会伪装成通过**。
   反例（2026-10-08 房间装配）：验"镜像只做了一次"用的是「文件侧世界盒中心 vs 源包侧世界盒中心，
   应 x 反号、y/z 相等」。第一次拿两个几何中心**恰好在原点**的网格跑反向对照（故意不做镜像）——
   做与不做两种结果**重合**，锚点照样报 1.4e-09 通过。
   ⇒ 每条锚点都要显式剔除"给不出证据"的样本、把剔除数打印出来、并规定**有效分母不足即判红**；
   修完同一批对照在 264 个有效对象上报出 5.8e-02（正常版 7.4e-08，差 7 个数量级），这条判据才算活着。
   同族：落笔占比若按"像素与背景**不同**"数，则无光时模型一片纯黑也会报 1.0（黑与深色背景"不同"）
   ⇒ 要按**亮度**数（`max(r,g,b) > 阈值`），并配"把灯全摘掉必须塌"的对照。

5. **拟合 / 对齐类扫描的判据必须含"形状"，不能是逐键绝对误差平均**。
   反例（2026-10-09 房间光照）：以游戏内截图为目标扫档位，用 9 个亮度统计量的平均绝对误差选档，
   结果**把整幅糊成白**的那档拿到最小距离 0.086（mean 0.549 早已越过参照 0.473，靠其它键补偿得分）。
   ⇒ 换成**分位数距离**（p05/p25/p50/p75/p95，Wasserstein-1 的代理）**+ 饱和度误差**，
   再加一条**过曝闸**（亮部面积超过参照 1.6 倍直接判红）。
   同族教训：只量亮度的度量对"颜色被镀白"是瞎的——亮度分布逐位对上时，sat 仍只有参照的 44%。
9. **给统计量起一个它撑不起的名字，比没有统计量更坏**（2026-10-09 同日第四轮）。
   我把"亮且偏蓝像素占比"命名为 `skyf`（天空/海面占比），据此推出"某分区机位没拍到窗"。
   真相是那张参照图里**根本没有窗**，14.5% 全是冷白瓷砖墙——一个名字就把猜测包装成了测量。
   ⇒ **给统计量命名之前，先拿一张"已知不含该物体"的样本量一遍**；一张反例样本的判死成本，
   远低于事后纠错。命名之后要补一句"它到底在量什么"（本案：冷亮面占比，与窗无关）。
10. **自动生成器要自证它的前提还成立**。机位是算出来的，我为了把窗弄进画面把视线劈向
   角平分线，结果目标物本身被劈出画面（截图拍到的是另一面墙）——而判据全绿。
   ⇒ 生成完立刻反算前提（"该目标是否仍在半视场内"）并做成判据；
   同时给这类"优化项"设可用区间（两个目标夹角 ≤ 视场 − 2×余量才允许兼顾），
   装不下就退回默认行为，而不是硬优化一个量把另一个量毁掉。
8. **只报红的闸门不改变输出，等于没有闸门**（2026-10-09 同日第三轮）。
   过曝判据一开始只是 `say(over <= 1.6, ...)` 打一行红，而"最近档位"仍从**全体**里按距离挑 ⇒
   一个 living `hi6 74.5% / sat 0.046`（整幅糊白）的档位照样当选，报告同时出现"最近档位=它"和"过曝红"。
   ⇒ 约束型判据必须**先筛掉不合格候选、再在合格集里挑最优**；合格集为空时明说
   "当前网格内没有合格组合"，这句话本身就是结论，不许退回全体里挑最近的当结论。
   同族：**聚合平均会藏掉单幅失败**——三机位平均过一次，单幅的糊白就被别的机位拉回"看着合格"，
   所以面积/占比类判据要按**最差机位**判，并把最差那个的名字打出来。
7. **"我数了 N 个可用信号"这种话必须写成回读不变式，不能只写在注释里**（2026-10-09 同日第二轮）。
   上一条修完透明后我在注释里写下"可用信号只有两个"，其实是三个（漏了"baseColor 贴图自带 alpha"）；
   这句话**以注释形式存在时没有任何后果**，直到新加的对照报出"补摆背景一个像素都不动"才回头查出来。
   而真正把它钉死的是回读里那条「贴图自带 alpha 却是 OPAQUE 必须为 0 个」——它直接点名了漏掉的两种材质。
   ⇒ 认知清单要落成断言：注释会随认知过期，断言会自己把漏项报出来。
6. **单轴扫出的"这条轴没用"是带前提的结论；加了新轴要回头重扫旧轴**。
   反例（同轮）：单独扫"灯强 ×π / 去掉 1/d² 衰减"时 mean 0.184 vs 基线 0.186 ⇒ 记成"调灯无效"；
   后来把泛光打开，同一组参数 0.316 → 0.549。轴之间有交互，端点+中点式单轴扫描看不见。
   同族：**旋钮本身可能是死块**——覆盖 `THREE.ShaderChunk.lightmap_fragment` 之后，
   开与关 4 个档位**逐位相同**（r160 里没有任何 shader include 这个块，lightmap 采样在
   `lights_fragment_maps` 内），看起来就像"这条轴真的没影响"。
   ⇒ **每加一个旋钮就配一条"开关前后必须不同"的对照**，不要等它自己证明有效。
