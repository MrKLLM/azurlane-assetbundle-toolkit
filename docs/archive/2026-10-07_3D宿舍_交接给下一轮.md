## 未打通 —— 下一轮第一件事：跨包 PPtr 解析

房间场景包里 348 个 `MeshFilter` 的网格与材质**全是外链 PPtr**，必须跨包解析才能装配房间。
已撞明的三个坑（都别再重踩）：

1. **一个 bundle 里可能有多个 `SerializedFile`**。这个场景包同时有
   `CAB-….sharedAssets`（32 对象 / **360** externals）和 `CAB-…`（2332 对象 / **357** externals）。
   用 `next(iter(env.file.files.values()))` 会取到 `.sharedAssets` ⇒ `externals[file_id-1]` **整体错位**
   （我第一版就这么把 `WallLeft` 的网格算成了 `fbx_db_pail01_fbx`）。
   ⇒ 必须**按对象自己的 path_id 落在哪个 SerializedFile** 来取它那份 externals。
2. **`ObjectReader.assetsfile` 在这批包上是 `None`** ⇒ 不能靠它反查归属，
   要自己遍历 `env.file.files` 里每个 SerializedFile 的 `.objects` 建 `path_id → 所属文件` 归属表。
3. **`pp.deref()` 是按 CAB 名在同目录下找文件**（报错 `File unity default resources not found in <目录>`）。
   两条可行路：① 先把依赖 bundle `env.load_file(路径)` 装进同一个 `Environment` 再 deref；
   ② 自己按 CAB 索引解析（**索引已建好并缓存**：474 个本地 dorm3d 包全扫一遍 **4.4 秒 / 477 条**，
   落在 `.diag/dorm3d_cab_index.json`，不命中时重扫即可）。
   ⚠️ 注意 `unity default resources` 这类外链**在盘上没有对应文件**，必须优雅跳过、不许当成失败。

**判据（这一步算打通的标准）**：随机抽 20 个 `MeshFilter`，逐个解析出 `(包路径, 网格名, 顶点数)`，
其中**顶点数 > 0 且网格名与该对象的语义相符**（`Wall*` 解析出的不该是 `pail`）≥ 18/20；
并把"解析失败的分别计数"打出来（本包 / 外链命中 / 外链未命中 / 内置资源）。
