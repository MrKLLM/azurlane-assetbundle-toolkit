# 资产台账（`scripts/asset_ledger.py` 读写）

这里的东西回答三个问题：**本机有哪些源包**、**每个产物是由哪几个源包在什么时候生成的**、
**哪些源包已经可以安全删除**。工具用法 `py -3 scripts/asset_ledger.py -h`。

| 文件 | 进 git | 内容 | 为什么 |
|---|---|---|---|
| `sources.json` | ❌（已 gitignore） | 每个源包：路径 / 大小 | **可再生**：`build` 只 stat 全盘，实测 20 秒；3MB 单行 JSON 进 git 每次重建都是一坨大 diff |
| `artifacts.json` | ✅ | 每个产物：大小 + md5 + 生成时刻 + 它由哪几个源包（大小+md5）生成 | 不可再生——记录的是"生成那一刻盘上的源包长什么样" |
| `pruned.json` | ✅ | 被有意删除的源包：路径 / 删除时大小 / 依据哪个产物 | **diff 靠它**：没有它，删掉的包下次会被报成"全部新增"，白下一遍 |

## 「已还原」的判据（两条都要满足，缺一不可）

1. 产物在正式区存在，且大小与台账记录一致；
2. 台账里记录的**每一个**源包，此刻在盘上、大小一致、**md5 一致**。

只满足"产物存在"不算——那可能产物是上一版源包生成的，删掉当前源包就再也对不上了。
源包已经不在盘上时也不判"已还原"（无从核对），此时 `prune` 不会把它列进删除计划。

## 换设备 / 重装系统

```
py -3 scripts/asset_ledger.py export --out 我的台账.json     # 自包含：源包+溯源+归档
#   把 我的台账.json 带到新机（或提交到别的分支/网盘）
py -3 scripts/asset_ledger.py import --file 我的台账.json     # 同路径保留本机较新的记录
```

`schema` 版本对不上会**直接拒绝合并**，不猜格式。导入后 `diff` 立刻认得哪些包是"有意归档"的，
不会把它们当新增重拉；设备上大小变了的照旧算真新版本。

## 删除动作的边界（`prune`）

- 默认 **dry-run**，逐条列出"路径 / 体积 / 依据哪个产物"。
- `--apply` 还必须同时给 `--yes`，否则退出码 2（不可逆动作不接半句话）。
- **永不删**：`files/AssetBundles/dependencies`、`hashes*.csv`、`version`、
  以及 AB 根下那 41 个没有类型归属的散包（消费方不明）；
  `inputs/azdata`、`inputs/gamecfg` 更是不在它的可达范围内（见 `docs/WORKFLOWS.md` WF-15 白名单）。
- 删掉的包 = 将来要重导那张图时必须从云端取回；`pruned.json` 就是"取回清单"。
